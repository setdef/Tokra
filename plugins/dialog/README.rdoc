= tokra-dialog

{rdoc-image:https://justin.searls.co/img/shovelware.svg}[https://justin.searls.co/shovelware/]
{rdoc-image:https://github.com/setdef/Tokra/actions/workflows/ci.yml/badge.svg?branch=trunk}[https://github.com/setdef/Tokra/actions/workflows/ci.yml]

Native file and message dialogs for Tokra desktop applications.

Opens the system's own dialogs through ferro-rfd, a one-to-one Ruby binding
of the rfd crate, and serves the commands of Tauri's dialog plugin, so the
frontend can use <tt>@tauri-apps/plugin-dialog</tt> unchanged. The page's
<tt>window.alert</tt> and <tt>window.confirm</tt> show the system's dialogs
too, as in Tauri.

== Installation

tokra-dialog is pure Ruby. Its dialogs come from ferro-rfd, which compiles
a Rust extension when it installs (its README names the Rust versions; on
Linux it also needs +pkg-config+ and libwayland's development files).
ferro-rfd is not on RubyGems.org yet, so name its release tag in your
Gemfile beside this gem. Keep the glob to ferro-rfd's own folder: a wider
one lets Bundler take other Ferro gems, such as ferro-arboard, from this
tag instead of their own:

  gem "ferro-rfd", git: "https://github.com/setdef/Ferro",
    tag: "ferro-rfd/v0.1.0.pre.2", glob: "gems/rfd/*.gemspec"
  gem "tokra-dialog"

On Linux, the dialogs come from the XDG desktop portal, and message dialogs
from +zenity+, which also stands in when the portal is missing. Desktops
install both; ship them with an app you package.

== Usage

Register the plugin on the app handle, for example in the setup hook. It
manages a Tokra::Plugins::Dialog::Dialog, reachable from any manager as
+dialog+:

  Tokra::Builder.new
    .setup { |app| app.handle.plugin(Tokra::Plugins::Dialog::Plugin.new(app.handle)) }
    .run

In the frontend:

  import { open, save, message, ask, confirm } from '@tauri-apps/plugin-dialog';

  const file = await open({ filters: [{ name: 'Image', extensions: ['png', 'jpeg'] }] });
  const target = await save({ defaultPath: 'report.pdf' });
  if (await ask('Delete it?', { kind: 'warning' })) { /* ... */ }

In Ruby, the builders answer through a block, on another thread, so they
never stop the event loop:

  handle.dialog.file.add_filter("Text", ["txt"]).pick_file { |path| puts path.inspect }
  handle.dialog.message("Saved").kind(Tokra::Plugins::Dialog::MessageDialogKind::Info).show { |_ok| }

The +blocking_+ methods wait for the user instead. Call them only off the
main thread; on the main thread they freeze the app, and on macOS they
never return:

  Thread.new { folder = handle.dialog.file.blocking_pick_folder }

== Differences from Tauri

- Dialogs have no parent window yet: Tokra's windows cannot name their
  native handle. On macOS, file dialogs still slide out of the app's main
  window as sheets, but message dialogs are system alerts of their own. On
  Windows and X11 the window still takes input behind a dialog.
- Picked paths join no fs or asset protocol scope; Tokra has neither yet.
- On Linux, dialogs come from the portal and zenity, not GTK. On Windows,
  custom button labels show the standard ones; the commands still answer
  with your labels.
- A message dialog's default title is the app's product name, or empty.
- <tt>window.__TAURI__.dialog</tt> is not defined; import the package
  through your bundler.

== Features

- Tauri-compatible IPC commands: open, save, message, ask, confirm
- Tauri's argument errors, word for word
- macOS, Windows, and Linux (X11 and Wayland)
