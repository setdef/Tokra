= tokra-log

{rdoc-image:https://justin.searls.co/img/shovelware.svg}[https://justin.searls.co/shovelware/]
{rdoc-image:https://github.com/setdef/Tokra/actions/workflows/ci.yml/badge.svg?branch=trunk}[https://github.com/setdef/Tokra/actions/workflows/ci.yml]

Logging for Tokra desktop applications, ported from Tauri's log plugin.

Your app logs from Ruby and from its pages. tokra-log sends both to the
same places, the terminal, a log file, a Logger of your own, the page's
console, in Tauri's format:

  [2026-11-13][09:41:07][my-app][INFO] window opened
  [2026-11-13][09:41:08][webview:onClick@http://localhost/main.js:12:3][WARN] slow paint

== Usage

Build the plugin with Tokra::Plugins::Log::Builder and register it on the
app handle from the setup hook, before the window opens:

  require "tokra"
  require "tokra-log"

  Tokra::Builder.default
    .setup(&Ractor.shareable_proc { |app|
      log = Tokra::Plugins::Log::Builder.new
        .app_handle(app.handle)
        .level(:info)
        .targets([
          Tokra::Plugins::Log::Target.new(Tokra::Plugins::Log::TargetKind::Stdout.new),
          Tokra::Plugins::Log::Target.new(Tokra::Plugins::Log::TargetKind::Folder.new(path: "logs")),
        ])
        .build
      app.handle.plugin(log)
      log.info("started")
    })
    .run(Tokra.generate_context)

The plugin takes no config. A +log+ entry under +plugins+ in your
<tt>tokra.conf.json</tt> fails the app, as it fails a Tauri app. With
<tt>"withGlobalTauri": true</tt> under +app+, a page finds Tauri's
frontend API on <tt>window.__TAURI__.log</tt>, from the script the gem
ships.

Log from Ruby with +trace+, +debug+, +info+, +warn+, +error+, and
+fatal+. They take Logger's arguments, so the plugin also serves as the
Logger a library asks for: <tt>log.warn("db") { "slow query" }</tt> logs
"slow query" with the target +db+.

Log from the page with <tt>@tauri-apps/plugin-log</tt>. Its +trace+
through +error+ invoke the plugin's <tt>log</tt> command, which logs the
message with the target <tt>webview:<caller></tt>. A Webview target sends
each line back to the page as a <tt>log://log</tt> event, which
+attachConsole+ prints in the page's console:

  import { warn, attachConsole } from "@tauri-apps/plugin-log";

  await attachConsole();
  await warn("slow paint");

== Configuration

Each Builder method returns the builder, so calls chain. With no changes
the plugin writes every level to standard output and to the app's log
directory, in UTC, and starts a log file over at 40000 bytes, as Tauri's
does.

- +targets+, +target+, +clear_targets+:: where lines go: a Target of
  TargetKind::Stdout, Stderr, Folder, LogDir, Webview, or Dispatch (a
  Logger of your own), each with its own +filter+ and +format+
- +level+:: the lowest level logged: +:trace+ (the default), +:debug+,
  +:info+, +:warn+, +:error+, or +:off+
- +filter+:: a block that receives each record's level and target and
  returns whether to log it
- +format+, +clear_format+:: a block that receives the message and the
  record and returns the line, or the message alone
- +timezone_strategy+:: UTC or local time for timestamps and rotated
  file names
- +rotation_strategy+, +max_file_size+:: what happens to a full log file

LogDir and Webview targets need the app handle, given with +app_handle+.

Tauri's +level_for+, +with_colors+, +skip_logger+, and +split+ raise
NotImplementedError: each depends on Rust's module paths, fern's colors,
or Rust's global logger. Their RDoc names the alternative.
