# ADR 008: Tokra Speaks Tauri's IPC Protocol, So Pages Use Tauri's JavaScript Packages

## Context and Problem Statement

A Tokra app's page needs JavaScript bindings for each plugin and for the
core API. Each Tauri plugin has an npm package, such as
`@tauri-apps/plugin-clipboard-manager`, that gives the page TypeScript
functions over Tauri's IPC, and `@tauri-apps/api` does the same for the
core.

Does Tokra write and publish its own `@tokra/plugin-*` packages, or does
it speak Tauri's protocol so that Tauri's packages work unchanged?

## Decision Drivers

- Frontend developers use the packages, documentation, and components
  they already know from Tauri.
- Tokra has no JavaScript of its own to write, publish, or version.

## Considered Options

1. Implement Tauri's IPC protocol, and use Tauri's npm packages directly.
2. Write and publish Tokra's own `@tokra/plugin-*` packages.

## Decision Outcome

Chosen: option 1. Tokra's plugins and core answer the page with Tauri's
command names, payloads, responses, and error messages, and the scripts
the page runs are Tauri's own, vendored from the pinned submodule. Any
Tauri frontend library that uses `invoke()` works with Tokra.
[The plugins design](../design/plugins.md) says what a plugin matches to
be compatible, and [the IPC design](../design/ipc.md) how the protocol
is served.

Confidence: not recorded when the decision was made. The real
`@tauri-apps/api`, loaded through `withGlobalTauri`, now drives a live
invoke round trip in the real-window tests.

### Consequences

- Good, because there is no JavaScript to write, publish, or version,
  and when Tauri improves its packages, Tokra gets the improvement.
- Good, because Tauri's plugin documentation applies to Tokra, and
  Tauri frontend components and libraries work unchanged.
- Bad, because Tokra is coupled to Tauri's protocol: when Tauri changes
  it, Tokra must follow, and Tokra tracks Tauri's releases.
- Bad, because every official plugin whose page package Tokra serves
  has to be ported with Tauri's commands and formats, even where Ruby's
  standard library already does the job for the app's Ruby code.
- Bad, because users may mistake Tokra apps for Tauri apps.

### Confirmation

`test/integration/ipc_transport_test.rb` drives the real
`@tauri-apps/api` over the IPC in a real webview. Each plugin's tests
call its commands through the IPC as the page does, with Tauri's names
and payloads.
