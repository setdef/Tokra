# ADR 008: Tauri JavaScript Protocol Compatibility

## Status
Accepted

## Date
2026-02-01

## Context

Tokra plugins need JavaScript bindings for frontend usage. Each Tauri plugin has a corresponding npm package (e.g., `@tauri-apps/plugin-clipboard-manager`) that provides TypeScript functions for WebView-side code.

We must decide whether to:
1. Write and publish our own `@tokra/plugin-*` npm packages
2. Use Tauri's npm packages directly

## Decision

**Tokra implements Tauri's IPC protocol, enabling direct use of Tauri's npm packages.**

Tokra extracts Tauri's JavaScript format strings at build time via `rake sync:tauri` and uses them unchanged:

```ruby
# lib/tokra/native.rb
def self.emit_js_script(event, payload)
  format(@emit_template, emit_fn: "__TAURI_EMIT__", event:, payload:, ids: "[]")
end
```

This means any Tauri frontend library that uses `invoke()` works with Tokra:

```javascript
// Frontend code using Tauri's npm package
import { readText, writeText } from '@tauri-apps/plugin-clipboard-manager';

const text = await readText();   // Works with Tokra!
await writeText('Hello');        // Works with Tokra!
```

### Plugin Requirements

For a Tokra plugin to be compatible with a Tauri npm package, it must:

1. **Match the IPC command names exactly**
   ```ruby
   # Tauri: invoke('plugin:clipboard-manager|read_text')
   def extend_api(invoke)
     case invoke.command
     when "plugin:clipboard-manager|read_text"
       invoke.resolve(read_text)
       true
     # ...
     end
   end
   ```

2. **Match the payload/response format**
   - Parse `invoke.payload` as Tauri does (JSON object)
   - Return values via `invoke.resolve()` in Tauri's expected format

3. **Use the same plugin name in configuration**
   ```ruby
   def name = "clipboard-manager"  # Matches Tauri's plugin name
   ```

### Verification

To verify compatibility:
1. Read the Tauri plugin's `guest-js/index.ts` for command names
2. Read `src/commands.rs` for payload/response types
3. Implement matching `extend_api` dispatch in Ruby

## Consequences

### Positive

- **Zero JavaScript maintenance** — no npm packages to write, publish, or version
- **Familiar DX** — frontend developers use the same Tauri packages they already know
- **Automatic updates** — when Tauri improves their packages, Tokra gets it free
- **Documentation reuse** — Tauri's plugin docs apply to Tokra
- **Ecosystem compatibility** — Tauri frontend components/libraries work unchanged

### Negative

- **Protocol coupling** — if Tauri changes their IPC protocol, Tokra must update
- **Version alignment** — Tokra may need to track Tauri's release cycle
- **Confusion risk** — users may mistake Tokra apps for Tauri apps

### Risks Mitigated

- **Breaking changes**: Tauri's IPC protocol is stable and versioned; changes are rare
- **Discovery**: Documentation makes the relationship explicit

## Applicability

This decision applies to **all Tokra plugins** that have Tauri npm package equivalents:

| Tokra Plugin | Tauri npm Package |
|--------------|-------------------|
| `tokra-clipboard` | `@tauri-apps/plugin-clipboard-manager` |
| `tokra-dialog` | `@tauri-apps/plugin-dialog` |
| `tokra-notification` | `@tauri-apps/plugin-notification` |
| `tokra-global-shortcut` | `@tauri-apps/plugin-global-shortcut` |
| `tokra-shell` | `@tauri-apps/plugin-shell` |
| `tokra-fs` | `@tauri-apps/plugin-fs` |
| `tokra-http` | `@tauri-apps/plugin-http` |
| `tokra-os` | `@tauri-apps/plugin-os` |
| `tokra-process` | `@tauri-apps/plugin-process` |
| `tokra-updater` | `@tauri-apps/plugin-updater` |

For plugins where Tokra diverges from Tauri's API (if any), a Tokra-specific npm package may be published. This should be documented in that plugin's ADR.

## Documentation Requirement

Each plugin's RDoc MUST include:

```ruby
# == JavaScript (Frontend)
#
# Tokra uses Tauri's IPC protocol. Use the official Tauri plugin:
#
#   npm install @tauri-apps/plugin-<name>
#
# Or via CDN:
#
#   <script src="https://unpkg.com/@tauri-apps/plugin-<name>"></script>
#
# See: https://tauri.app/plugin/<name>/
```
