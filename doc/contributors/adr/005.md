# ADR 005: Thin Binding Steady State

## Status
Accepted

## Date
2026-01-30

## Context
ADR 001 established the "Thin Binding + Ruby Host" architecture, estimating ~500 lines of Rust for the binding layer. After implementing the core WebView/Window/EventLoop infrastructure and migrating event data classes to Ruby `Data.define`, we have achieved a stable foundation.

This ADR documents the **steady state** of the Rust layer and establishes guidelines for future feature development.

## Decision
The Rust binding layer is now architecturally complete at approximately **~500 LOC**. Future feature development should follow established patterns that minimize Rust additions.

### 1. Current Rust Inventory

The Rust layer consists of platform wrappers with no business logic:

| Module | Purpose | Lines |
|--------|---------|-------|
| `lib.rs` | Module init, Magnus FFI | ~30 |
| `event_loop.rs` | Tao event loop wrapper | ~90 |
| `proxy.rs` | Thread-safe EventLoopProxy | ~60 |
| `responders.rs` | Async protocol responder storage | ~15 |
| `user_event.rs` | Internal event enum | ~25 |
| `webview.rs` | Wry WebView wrapper | ~70 |
| `window.rs` | Tao Window wrapper | ~40 |
| **Total** | | **~330 logic lines** |

With tests and documentation, the full crate is ~500 LOC.

### 2. Feature Parity Roadmap

Completing feature parity with Tauri requires additional platform wrappers. Each follows the "Thin Wrapper" pattern:

| Feature | Platform Crate | Rust (Est.) | Ruby (Est.) |
|---------|---------------|-------------|-------------|
| Menus | `muda` | ~80 | ~300 |
| System Tray | `tray-icon` | ~60 | ~200 |
| Global Shortcuts | `tao` | ~40 | ~150 |
| File Dialogs | `rfd` | ~50 | ~100 |
| Notifications | `notify-rust` | ~30 | ~80 |
| Clipboard | `arboard` | ~70* | ~30 |
| Deep Linking | Platform-specific | ~50 | ~100 |
| **Total New Rust** | | **~380** | |

**Projected final Rust LOC: ~710** (current ~330 + new ~380)

\* See **ADR-007**: Plugins requiring shared mutable state across Ractors need the Rust `Mutex<T>` + `frozen_shareable()` pattern, increasing Rust LOC.

### 3. Features Implemented in Pure Ruby

The following Tauri features require **zero additional Rust**:

- **Auto-updater**: Ruby's `Net::HTTP` + version comparison
- **Security Allowlists**: Ruby configuration and runtime checks
- **Plugin System**: Ruby modules and dependency injection
- **State Management**: Ractor-safe Ruby patterns (see ADR-007 for shared mutable state exceptions)
- **CLI/Bundler**: Thor or Rake-based tooling
- **Configuration**: YAML/TOML parsing in Ruby
- **Logging/Telemetry**: Ruby stdlib + optional gems

### 4. The Pattern for New Features

When adding new platform capabilities:

```rust
// Rust (~50-100 lines): Wrap the platform type
#[magnus::wrap(class = "Tokra::Native::Menu")]
struct RbMenu { inner: muda::Menu }

impl RbMenu {
    fn new() -> Self { Self { inner: muda::Menu::new() } }
    fn append(&self, label: String, id: String) {
        self.inner.append(&muda::MenuItem::new(label, true, None));
    }
}
```

```ruby
# Ruby (~200+ lines): Build the user-facing API
class Tokra::Menu
  def initialize(&block)
    @native = Tokra::Native::Menu.new
    @callbacks = {}
    instance_eval(&block) if block
  end

  def item(label, id: SecureRandom.uuid, &action)
    @callbacks[id] = action
    @native.append(label, id)
    self
  end

  def handle_click(id)
    @callbacks[id]&.call
  end
end
```

### 5. Thread Safety Validation

The `RequestAsyncResponder` from Wry is confirmed `Send`, allowing `Proxy#respond` to be called directly from Ruby without routing through the event loop. This was validated by:

1. **Wry source**: `unsafe impl Send for RequestAsyncResponder` with safety documentation
2. **Tauri patterns**: Official examples spawn threads that call `responder.respond()`

This enables the simplified response flow where Ruby calls `proxy.respond()` directly.

## Consequences

### Positive
- **Minimal Rust Maintenance**: The binding layer is stable; most changes happen in Ruby
- **Ruby Developer Experience**: New features are implemented in familiar Ruby patterns
- **Clear Boundaries**: "Rust wraps platform, Ruby owns logic" is easy to follow
- **Ractor Safety**: Ruby `Data.define` events are immutable and automatically shareable

### Negative
- **Performance Overhead**: Instantiating Ruby objects for each event adds microseconds of latency (negligible for desktop apps)
- **Two-Language Debugging**: Platform issues may require tracing through both layers

### Risks Mitigated
- **ADR 001 Drift**: The ~500 LOC target is now achieved and documented
- **Feature Creep in Rust**: This ADR establishes the pattern to resist adding logic to Rust
