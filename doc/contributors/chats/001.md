### `Ractor::Port` (lines 689-833)

This is the **canonical communication primitive** in Ruby 4.0:

```ruby
port = Ractor::Port.new

# Sending (any ractor can send to a port)
port.send(obj)           # copy semantics (default)
port.send(obj, move: true)  # move semantics
port << obj              # alias for send

# Receiving (ONLY the creating ractor can receive)
port.receive             # blocks until message available

# Lifecycle
port.close               # only creator can close
port.closed?             # check if closed
```

**Key constraint**: Only the Ractor that created a Port can call `.receive` on it. Other Ractors can only `.send` to it.

---

### `Ractor.select` (lines 264-342)

Wait on multiple ports OR ractors simultaneously:

```ruby
# Wait for first message from any port OR ractor termination
result_port_or_ractor, obj = Ractor.select(port1, port2, ractor1, ractor2)
```

---

### `Ractor.shareable_proc` / `Ractor.shareable_lambda` (lines 648-687)

Creates **shareable** procs/lambdas that can be passed between Ractors:

```ruby
# Shareable proc - self defaults to nil
callback = Ractor.shareable_proc { |msg| process(msg) }

# Shareable lambda with custom self
handler = Ractor.shareable_lambda(self: some_shareable_obj) { |x| x * 2 }

# Can be used with define_method
class MyClass
  define_method :handler, &Ractor.shareable_proc { do_stuff }
end
```

**Critical constraint**: Cannot access outer variables:
```ruby
a = 42
Ractor.shareable_proc { p a }  # => ArgumentError: accesses outer variables
```

---

### Monitoring (lines 616-646)

New Ruby 4.0 feature for observing Ractor termination:

```ruby
r = Ractor.new { work }
port = Ractor::Port.new
r.monitor(port)

status = port.receive  # => :exited or :aborted
r.unmonitor(port)
```
