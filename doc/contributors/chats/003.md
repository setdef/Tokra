## Investigation Report: `undefining the allocator of T_DATA class` Warning

### Summary

This is a **harmless warning** emitted by Ruby 4.0's garbage collector when a `T_DATA` class (a native extension class wrapping Rust/C data) has its allocator function removed. The warning originates from **line 71 of [handler.rb](cci:7://file:///Users/kerrick/Developer/tokra/lib/tokra/rack/handler.rb:0:0-0:0)** where `event_loop.create_proxy` is called, which triggers lazy initialization of the `Tokra::Native::Proxy` class.

### Root Cause

The warning comes from Ruby's [gc.c](cci:7://file:///Users/kerrick/Developer/ruby/gc.c:0:0-0:0) (line 1072-1079):

```c
static inline void
rb_data_object_check(VALUE klass)
{
    if (klass != rb_cObject && (rb_get_alloc_func(klass) == rb_class_allocate_instance)) {
        rb_undef_alloc_func(klass);
        rb_warn("undefining the allocator of T_DATA class %"PRIsVALUE, klass);
    }
}
```

This check runs whenever a **typed data object** is wrapped (via [rb_data_typed_object_wrap](cci:1://file:///Users/kerrick/Developer/ruby/gc.c:1127:0-1135:1)). Ruby detects that:
1. The class `Tokra::Native::Proxy` was defined with Ruby's default allocator function
2. But it's being used as a `T_DATA` class (wrapping Rust data)
3. Ruby automatically removes the allocator to prevent unsafe `Proxy.allocate` calls from pure Ruby

### Why [Proxy](cci:2://file:///Users/kerrick/Developer/tokra/ext/tokra/src/lib.rs:444:0-446:1) specifically?

Looking at your [lib.rs](cci:7://file:///Users/kerrick/Developer/magnus/src/lib.rs:0:0-0:0), [RbProxy](cci:2://file:///Users/kerrick/Developer/tokra/ext/tokra/src/lib.rs:444:0-446:1) uses a **manual [TypedData](cci:2://file:///Users/kerrick/Developer/magnus/src/typed_data.rs:410:0-523:1) implementation** with [frozen_shareable()](cci:1://file:///Users/kerrick/Developer/magnus/src/typed_data.rs:387:4-394:5):


The other classes (e.g., [RbEventLoop](cci:2://file:///Users/kerrick/Developer/tokra/ext/tokra/src/lib.rs:123:0-128:1), [RbWindow](cci:2://file:///Users/kerrick/Developer/tokra/ext/tokra/src/lib.rs:267:0-269:1), [RbWebView](cci:2://file:///Users/kerrick/Developer/tokra/ext/tokra/src/lib.rs:321:0-323:1)) use the `#[magnus::wrap(...)]` macro, which **automatically calls [undef_default_alloc_func()](cci:1://file:///Users/kerrick/Developer/magnus/src/class.rs:478:4-524:5)** during class definition. ### The Fix

Add [undef_default_alloc_func()](cci:1://file:///Users/kerrick/Developer/magnus/src/class.rs:478:4-524:5) in the [Proxy](cci:2://file:///Users/kerrick/Developer/tokra/ext/tokra/src/lib.rs:444:0-446:1) class definition:

```rust
// In lib.rs, around line 461-468
static CLASS: magnus::value::Lazy<magnus::RClass> = magnus::value::Lazy::new(|ruby| {
    let tokra = ruby.define_module("Tokra").unwrap();
    let native = tokra.define_module("Native").unwrap();
    let class = native.define_class("Proxy", ruby.class_object()).unwrap();
    class.undef_default_alloc_func();  // <-- Add this line
    class
});
```

### Why This Warning Exists

Ruby 4.0 added this warning to catch a potential safety issue: if a `T_DATA` class has Ruby's default allocator, someone could call `Proxy.allocate` from Ruby code, creating an uninitialized object without the underlying Rust data—which would crash when any method is called on it.

Ruby automatically fixes this (by undefining the allocator), but warns you so you can do it explicitly and silence the warning.

### Is It Harmful?

**No.** The warning indicates Ruby is doing the right thing automatically. Your application works correctly. The fix is purely cosmetic to silence the warning.
