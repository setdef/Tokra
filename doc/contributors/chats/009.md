**Regarding dialogs (line 106):**

In Tauri's `plugin-dialog`, dialogs have **two API variants**:

1. **Async (callback-based)** — Safe for main thread:
   - [pick_file(callback)](cci:1://file:///Users/kerrick/Developer/plugins-workspace/plugins/dialog/src/lib.rs:509:4-531:5), [show(callback)](cci:1://file:///Users/kerrick/Developer/plugins-workspace/plugins/dialog/src/lib.rs:318:4-340:5), etc.
   - Uses `rfd::AsyncFileDialog` internally
   - Spawns a background thread to await the result

2. **Blocking** — Must **NOT** run on main thread (will deadlock):
   - [blocking_pick_file()](cci:1://file:///Users/kerrick/Developer/plugins-workspace/plugins/dialog/src/lib.rs:658:4-678:5), [blocking_show()](cci:1://file:///Users/kerrick/Developer/plugins-workspace/plugins/dialog/src/lib.rs:349:4-357:5), etc.
   - Uses `sync_channel` to block until user responds

The original note was misleading. I've updated the document to clarify that Tokra should implement the **async-only** approach (callback-based), which is safe for the main thread. Blocking variants could optionally be added later for use from the Worker Ractor.
