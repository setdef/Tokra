### Planner Response

Here is the Rust code a Tauri developer would use.

They define a command function and direct the [Builder](cci:2://file:///Users/kerrick/Developer/tauri/crates/tauri/src/app.rs:1373:0-1427:1) to use it via `.invoke_handler()`:

```rust
// 1. Define the command (the handler)
#[tauri::command]
fn log_message(msg: String) {
    println!("Received via IPC: {}", msg);
}

fn main() {
    tauri::Builder::default()
        // 2. Pass the handler to the builder
        .invoke_handler(tauri::generate_handler![log_message])
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

In Tokra (Ruby), we are porting this exact pattern to `Rack::Handler::Tokra.run`:

```ruby
# 1. Define the handler (Proc)
log_message = proc { |msg| LOGGER.info("Received via IPC: #{msg}") }

Rack::Handler::Tokra.run(
  app,
  # 2. Pass the handler to the builder
  ipc_handler: log_message
)
```

Does this match the "Tauri-like" architecture you are looking for? If so, I am ready to apply these changes.
