# Plan 066: tokra-process, Tauri's process plugin

Tauri's official process plugin lets a page end its app or start it over:
`exit(code)` and `relaunch()` from `@tauri-apps/plugin-process`. This plan
ports it as `tokra-process`, a pure Ruby gem in `plugins/process`, so the
frontend keeps using that package unchanged (ADR 008).

Sources: `tauri-plugin-process` 2.3.1 at plugins-workspace `d4613ff0`, the
commit plans 021 to 025 ported from: `src/lib.rs`, `src/commands.rs`,
`build.rs`, `Cargo.toml`, `guest-js/index.ts`, `api-iife.js`,
`package.json`, `README.md`, and `permissions/` (`default.toml`,
`autogenerated/reference.md`, `autogenerated/commands/exit.toml`,
`autogenerated/commands/restart.toml`, `schemas/schema.json`). Tauri core
at `vendor/tauri` (`9f0306fbc`): `crates/tauri/src/app.rs:531-538`
(`AppHandle::exit`), `:540-582` (`restart`, `request_restart`),
`crates/tauri/src/process.rs:58-87` (`process::restart`),
`crates/tauri/src/ipc/command.rs:60-145` (how a command reads its
arguments), `crates/tauri/Cargo.toml:207-208` (the symlink feature).

## Context

The whole plugin is two commands. `init()` builds a plugin named
`process` whose invoke handler serves `exit` and `restart`
(`lib.rs:19-23`). `exit` takes an `i32` named `code` and calls
`AppHandle::exit(code)`; `restart` takes nothing and calls
`AppHandle::request_restart()` (`commands.rs:7-15`). Neither returns a
value, so each invoke resolves with `null`. It has no state, no setup, no
init script, no extension trait, and no error type of its own: a bad
`code` rejects with the `#[tauri::command]` macro's argument error.

Tokra already has everything the commands call. Plan 038 ported
`AppHandle#exit`, which asks the event loop to exit, so handlers hear
`RunEvent::ExitRequested` and may prevent it. Plan 039 ported
`AppHandle#request_restart`, `Tokra::Process.restart`, and Tauri's
`process-relaunch-dangerous-allow-symlink-macos` safety default: on macOS
an interpreter reached through a symlink is refused, and the restart then
exits 0 without spawning, as Tauri's does with the feature off. The plugin
inherits that default and adds no switch for it (the Cargo-feature
row, now in [native.md](../design/native.md)). `Tokra::Ipc::CommandItem` reads an argument with
Tauri's messages, and `CommandItem.integer` checks the `i32` range.

## Decisions

1. **The module is `Tokra::Plugins::Process`.** The gem is `tokra-process`,
   and each plugin's module is its plugin's name (`Notification`, `Dialog`,
   `Log`). Inside `module Tokra`, a bare `Process` already names
   `Tokra::Process`, and RuboCop's `Lint/ConstantResolution` refuses one
   in every plugin's `lib/`, so the new module shadows nothing a plugin may
   write. The signature declares it as `module Tokra::Plugins::Process`,
   with the namespace before it, because
   `test/tasks/test_top_level_constants.rb` refuses a bare `Process` in
   any `.rbs` file. Options weighed: `ProcessPlugin` or `Proc` (invented
   names, against tier 2), and editing that test to exempt the file
   (outside this plan's area, and weaker).

2. **`init()` is `Plugin.new(handle)`.** The five ported plugins register
   that way, and another plan is changing how every plugin registers. This
   one follows the five and moves with them.

3. **No `window.__TAURI__.process` yet.** Tauri adds `api-iife.js` to the
   page when the app sets `withGlobalTauri` (`build.rs:9`). Tokra has no
   plugin global scripts, so the README and RDoc say to import the package
   through a bundler, as the notification plugin's do. The plugin
   registration work adds them; this plugin then gives Tauri's
   `api-iife.js`, unchanged, as its script.

4. **Permissions wait for capabilities.** Tokra has no ACL (ADR 010's
   stopgap admits the app's own pages and rejects the rest), so the
   upstream files above have nowhere to go. Every page of the app can call
   both commands, as with `default.toml` granted. The capabilities port
   picks up `default.toml`, `autogenerated/commands/exit.toml`,
   `autogenerated/commands/restart.toml`, `autogenerated/reference.md`,
   and `schemas/schema.json`.

5. **`Commands` mirrors `commands.rs`, and `extend_api` plays the macro.**
   `Commands.exit(app, code)` and `Commands.restart(app)` take what the
   Rust functions take and return `nil`, as they return `()`.
   `Plugin#extend_api` reads the arguments as `generate_handler!` and
   `#[tauri::command]` do, calls the command, and resolves with its
   result; an `InvalidArgs` rejects with its message. Anything else is a
   bug and reaches the router, which rejects with its message too.

6. **Tests run the real app.** Each test builds a real `Tokra::App` over
   `StubNative`, registers the plugin, injects the page's IPC message for
   `plugin:process|exit` or `plugin:process|restart`, and runs the loop.
   They observe the exit through the run events, `StubNative.exit_code`,
   and the page's callbacks, and the restart through `Process.spawn`,
   stubbed as Plan 039's tests stub it, and the `SystemExit` that
   `Tokra::Process.restart` raises. No test ends the test process, and
   none opens a window.

## Verification

- `cd plugins/process && bundle exec rake test`: every test, none of which
  opens a window.
- Each behaviour's test seen failing with its line mutated (the list
  below).
- `bundle exec rubocop plugins/process tasks/package.rake`, then once
  `bundle exec rake steep` and `bundle exec rake reuse:lint`.
- Not run here: the gate, `package:check` (it builds gems), Linux, and
  Windows. The plugin has no platform code; `Tokra::Process.restart`'s
  platform paths are Plan 039's.

## Out of scope

- The global API script and permissions (decisions 3 and 4).
- Packaged apps' restart through a bundle's executable or an AppImage
  (Plan 039, Out of scope).
- A real restart of a real app: Plan 039's `test/integration/restart_test.rb`
  covers `Tokra::Process.restart` end to end; the plugin adds only the
  call.

## Risks

- The registration work will change `Plugin.new(handle)` for all six
  plugins at once; this one is the smallest to move.
- With no ACL, any page the app serves can end it. That is Tauri's
  behaviour with the default permission set, and ADR 010's stopgap keeps
  foreign origins out.

## Mutation checks

Each line below was changed by hand, the plugin's tests run, and the line
restored. Every mutant failed at least one test.

| Mutation | Tests that failed |
|---|---|
| `Commands.exit` calls `app.exit(0)` | exit asks with the code; a handler can prevent it; both ends of the i32 range |
| `Commands.exit` calls `Kernel.exit(code)` | the four exit tests that run the loop (the helper turns the `SystemExit` into a failure) |
| `Commands.restart` calls `app.exit(RESTART_EXIT_CODE)` | both restart tests |
| `Commands.restart` calls `app.restart` | both restart tests |
| `"i32"` becomes `"i64"` | a code that is not an i32 rejects |
| `key: "code"` becomes `"exitCode"` | every exit test |
| the `InvalidArgs` rescue removed | a missing code rejects (the router's rescue would report the page's mistake on standard error) |
| `exit` no longer resolves | exit asks with the code; a handler can prevent it |
| unknown commands claimed (`else return true`) | other commands are not found |
| the name becomes `process-plugin` | all ten |
| `restart` calls `Commands.exit(app, 0)` | both restart tests |
