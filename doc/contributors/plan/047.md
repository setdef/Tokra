# Plan 047: The event system, and every window event

Plan 045 left `Window#on_window_event` and `Listener` and `Emitter` on
`Window` deferred: Tokra emitted only `CloseRequested` and `Destroyed`,
and it had no event targets. Tokra's events were one method,
`AppHandle#emit`, which evaluated Tauri's emit script in every webview
with no listener ids, so no `listen` in the page ever heard it. Its
template still held Rust's doubled braces, so the script did not parse
either. The page had nowhere to register: there was no `event` core
plugin, so `listen`, `once`, `emit`, and `emitTo` from `@tauri-apps/api`
were all rejected with `Command ... not found`.

This plan ports Tauri's event system whole: event names and their rules,
targets, the listener registry with its pending queue, the JS listener
table and scripts, the `event` core plugin, the `Listener` and `Emitter`
traits on `App`, `AppHandle`, `Window`, and `Webview`, and every
`WindowEvent` tao reports, delivered to the run callback, to
`on_window_event` handlers, and to the page as `tauri://` events, in
Tauri's order.

## Decisions

1. **`Tokra::EventTarget` is a module of six `Data` classes**, as
   `WindowEvent` and `RunEvent` are: `Any`, `AnyLabel(label)`, `App`,
   `Window(label)`, `Webview(label)`, `WebviewWindow(label)`, with Tauri's
   constructors as module functions. Rust's `Into<EventTarget>` for any
   string becomes `EventTarget.from`, which `emit_to` calls: a String is
   `AnyLabel`, a target is itself, anything else is a `TypeError`.

2. **The serde form is ported in both directions.** `to_json` writes
   `{"kind":"Window","label":"main"}` as `#[serde(tag = "kind")]` does.
   Reading it back follows serde's internally tagged visitor over
   serde_json's `Value` (serde `private/de.rs:810-886`): an object with a
   string `kind` naming a variant, or a sequence whose first element is
   the tag, and a string `label` for the variants that carry one, failing
   with serde's words (`missing field ...`, `unknown variant ..., expected
   one of ...`, `invalid type: ..., expected internally tagged enum
   EventTarget`, `invalid length ...`). serde_json's `Value` reads an
   identifier only from a string (`value/de.rs:1025-1030`), so a variant
   index is rejected as any other non-string.

3. **Event names are checked where Tauri checks them.** `char::is_alphanumeric`
   is Unicode's `Alphabetic` or `Numeric` (`\p{Alphabetic}`, `\p{N}`).
   A bad name from Ruby raises `Error::IllegalEventName` with Tauri's
   message, the name quoted as Rust's `Debug` quotes it (the existing
   `Ipc::Unexpected.debug`). `listen` and its kin `unwrap` in Rust, a
   panic; Tokra raises the same error, as it translates every panic
   (precedence 1). A bad name from the page fails the command with the
   deserializer's other message, `Event name must include only ...`.

4. **Ruby owns the registry (ADR 005), ported step for step.** One
   `Thread::Mutex` guards the handlers and `try_lock` stands in for
   Rust's, so a listen, unlisten, or emit from inside a handler, or from a
   thread while another emits, goes to the pending queue and runs when
   the emit that held the lock flushes it, as Tauri's does. Handlers run on
   the emitting thread, as Tauri's do. Rust's `HashMap` and `HashSet`
   give no order; Ruby's Hash calls handlers in the order they were added,
   one of the orders Tauri allows. Ids start at 0, shared by Ruby and JS
   listeners, as one `AtomicU32` serves both.

5. **The vendored scripts are Tauri's, with Tauri's names.** `rake
   sync:tauri` now unescapes the emit template's braces and also vendors
   `listen_js_script`, `unlisten_js_script`, and `event/init.js`. The
   listener object and function are `__internal_unstable_listeners_object_id__`
   and `__internal_unstable_listeners_function_id__`, Tauri's fixed names
   (`listener.rs:80-81`); the old comment saying Tauri randomizes them
   described an earlier Tauri.

6. **The `event` core plugin registers first among Tokra's core plugins,**
   after `path`, which Tokra has no plugin for, as `register_core_plugins`
   orders them. Its four commands read their arguments in Tauri's order,
   so the first bad one rejects with `invalid args ...`. `listen`
   evaluates the listener script in the calling webview before it records
   the listener, then answers the id, as `listen_js` does.

7. **`Tokra::Listener` and `Tokra::Emitter` are modules.** `Emitter`'s
   methods are all provided, as the trait's are. `Listener` provides
   `listen_any` and `once_any`; each class defines `listen`, `once`, and
   `unlisten` with its own target (`App`, `Window(label)`,
   `Webview(label)`), as each Rust impl does. A Ruby payload is serialized
   as Tokra serializes an IPC response, a non-finite float becoming
   `null` as serde_json writes it. `emit_filter` takes the filter as a
   block. `emit` evaluates in the webviews before it calls Ruby
   handlers, as `AppManager::emit` does.

8. **A window's event listeners live on the `Window`, called after the
   run callback.** For every event but `CloseRequested`, tao's runtime
   calls the run callback (plugins, then the App#run block) and then the
   window's listeners; `CloseRequested` runs the listeners first
   (`on_close_requested`). The first listener is the manager's: it emits
   the `tauri://` event, then calls the `Builder#on_window_event`
   handlers. `Window#on_window_event` adds more after it. Tauri sends the
   new listener through the event loop because its store lives on the
   loop's thread; Ruby's store is guarded by a mutex, so the listener is
   added at once from any thread, which can only hear more events than
   Tauri's, never fewer. The block receives the event alone, as Tauri's
   closure does. `RunEvent::WindowEvent` is unchanged.

9. **`Resized` carries the size `Window#inner_size` answers, not tao's.**
   tauri-runtime-wry's `parse` replaces tao's size with `inner_size`
   because wry replaces the NSView on macOS. Tokra's `Window#inner_size`
   already asks the webview there, so Ruby asks it when the event arrives,
   on the main thread in the same turn of the loop.

10. **Windows takes focus from WebView2, as Tauri does.** tao's
    `Focused` is dropped on Windows when the window has no child
    webviews, and the webview controller's `GotFocus` and `LostFocus`
    send it instead, through the proxy (`lib.rs:5070-5128`), with
    Tauri's focused-webview bookkeeping for one webview. The binding uses
    the webview2-com and windows versions wry already locks.

11. **On Windows, `ThemeChanged` also themes the webview** with wry's
    `set_theme`, as `handle_event_loop` does (`lib.rs:4155-4166`), after
    the run callback and the window's listeners have heard it.

12. **Drops are window events.** Tokra's one webview is its window's
    content (`WebviewKind::WindowContent`), whose drag and drop handler
    sends `SynthesizedWindowEvent::DragDrop`. So `WindowEvent::DragDrop`
    reaches the run callback and the window's listeners, its `tauri://drag-*`
    events go to every target with the window's label, and
    `Builder#on_webview_event` no longer hears drops, which Tauri never
    sends a webview window's webview. Positions are `f64`, as Tauri's
    `PhysicalPosition::new(x as _, y as _)` makes them.

13. **The `tauri://` payloads are Tauri's.** `resize` is a
    `PhysicalSize`, `move` a `PhysicalPosition`, `close-requested`,
    `destroyed`, `focus`, `blur`, and `drag-leave` are `null`,
    `scale-change` is `{"scaleFactor": ..., "size": ...}`,
    `theme-changed` is `"light"` or `"dark"`, and `drag-enter` and
    `drag-drop` are `{"paths": [...], "position": {...}}`, `drag-over`
    without `paths`. A close request is prevented when the page listens
    for `tauri://close-requested` on this window, since the page's
    `onCloseRequested` destroys the window itself.

## Changes

- `lib/tokra/event.rb`, `event/listeners.rb`, `event/plugin.rb`,
  `event_target.rb`, `listener.rb`, `emitter.rb`; `Error::IllegalEventName`.
- `AppManager` holds the `Listeners` and gains `listen`, `once`,
  `unlisten`, `emit`, `emit_filter`, `emit_to`.
- `App`, `AppHandle`, `Window`, `Webview` include `Listener` and
  `Emitter`; `Window#on_window_event`; `Webview#listen_js`,
  `#unlisten_js`, `#emit_js`. The old `AppHandle#emit` and
  `Native.emit_js_script` go.
- `WindowEvent` gains `DragDrop` and Tauri's fields.
- `App` dispatches the new native events.
- `ext/tokra/src/event_loop.rs` delivers tao's `Resized`, `Moved`,
  `Focused`, `ScaleFactorChanged`, and `ThemeChanged`; `webview.rs` adds
  WebView2's focus handlers and `set_theme` on Windows.
- `tasks/sync.rake` and the vendored scripts.

## Untested without a display or a person

Focus and blur need the window brought to the front, and a theme change
needs the system's appearance changed; the fixtures neither take focus
nor change settings, so those arrive only in stub tests. Drag and drop
needs a real drag. A manual run of `test/integration/fixtures/event/app.rb
--wait` shows each in the page's log when done by hand.

## Out of scope

The core `window` and `webview` plugins (`plugin:window|destroy` and the
rest), which the page's `onCloseRequested` calls after its handler;
`Scopes`; multiwebview windows.

## Risks

Handlers now run inside the emit that triggers them, on the emitting
thread; a handler that blocks holds the registry, as in Tauri. A page
listening for `tauri://close-requested` on its window can no longer be
closed by its close button until the window plugin lands, as a Tauri app
without the window plugin's permission cannot be.

## Status

Every item above is done except those the inventory defers: the fs scope
a drop widens (Tokra has no `Scopes`), `tauri://window-created` and
`tauri://webview-created` (Tokra creates no window after the first), and
the window and webview core plugins.

Mutation checks, each reverted after the named test failed: Any always
passing the filter (`test_listeners.rb`), the page hearing an emit before
Ruby (`test_emitter.rb`), a page listener preventing the close, the run
callback hearing a window event before the listeners, drops going to the
label rather than the window (`test_window_events.rb`), the pending queue's
flush (`test_listeners.rb`), `\p{N}` in event names (`test_event_name.rb`),
`AnyLabel` reaching a `Window` listener (`test_emitter.rb`), the plugin's
argument order and its registration (`test_event_plugin.rb`), and, in the
extension, `Moved`'s x and y swapped (`test/integration/event_test.rb`).

Windows: the new `cfg(windows)` code (`webview_focus.rs`, the webview's
`set_theme`) passed Clippy for `x86_64-pc-windows-gnu` under Tokra's lint
set in a scratch crate with the locked tao, wry, webview2-com, and windows;
it is not run on Windows here, and CI's Windows job is its first run.

Linux: in a `ruby:4.0.9` Debian container with CI's packages the
extension compiles and passes Clippy with no warning, and under
`xvfb-run dbus-run-session` `test:core` ran 1151 tests with 36 skips;
`event_test.rb` passed whole, its resize and move included. The two
failures are the container's own: it has no `.git`, which
`test_top_level_constants.rb` lists files with, and its home is `/root`,
which `test_path_resolver.rb` expects under `/home/`.

After review: a theme change logs only the webview's own `set_theme`
failure; a resize that arrives after the native window closed is dropped,
as Tauri drops one whose window has no inner window; serde's
`invalid length N, expected 0 elements in sequence` for a unit variant
with extra elements; `emit_filter` requires its block; and tests now
cover the Window and WebviewWindow targets of window events, another
thread's calls while an emit holds the registry, and the webview taking
its theme after the listeners, each mutation-checked.
