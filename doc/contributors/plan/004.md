# Thin Binding Migration: Events to Ruby

Migrate event data classes from Rust to Ruby `Data.define` and simplify HTTP response flow to better align with ADR 001's "Thin Binding" architecture.

## Goal

Reduce Rust layer complexity by ~370 lines while maintaining identical functionality, bringing the extension closer to the ~500 LOC target specified in ADR 001.

---

## Phase 1: Thread Safety Research ✅ COMPLETE

### Findings

**`RequestAsyncResponder` is confirmed thread-safe.** Evidence:

1. **Wry Source** ([wry/src/lib.rs:440-447](file:///Users/kerrick/Developer/wry/src/lib.rs#L440-L447)):
   ```rust
   pub struct RequestAsyncResponder {
     pub(crate) responder: Box<dyn FnOnce(Response<Cow<'static, [u8]>>)>,
   }

   // SAFETY: even though the webview bindings do not indicate the responder is Send,
   // it actually is and we need it in order to let the user do the protocol computation
   // on a separate thread or async task.
   unsafe impl Send for RequestAsyncResponder {}
   ```

2. **Tauri Documentation** ([tauri/crates/tauri/src/app.rs:2015-2034](file:///Users/kerrick/Developer/tauri/crates/tauri/src/app.rs#L2015-L2034)):
   ```rust
   .register_asynchronous_uri_scheme_protocol("app-files", |_ctx, request, responder| {
       let path = request.uri().path()[1..].to_string();
       std::thread::spawn(move || {  // <-- Explicitly spawns a thread
           if let Ok(data) = std::fs::read(path) {
               responder.respond(/* ... */);  // <-- Called from spawned thread
           }
       });
   });
   ```

3. **Ruby Concurrency Docs** ([ruby/doc/language/ractor.md](file:///Users/kerrick/Developer/ruby/doc/language/ractor.md)):
   - Confirms `T_DATA` objects (like our Rust-wrapped types) need explicit handling for cross-Ractor use
   - Our `Proxy` is already marked `frozen_shareable` which satisfies this

### Decision

✅ **Proceed with Phase 2a**: Inline response building directly in `Proxy#respond` rather than routing through the event loop.

### Acceptance Criteria

- [x] Document whether `RequestAsyncResponder::respond` is thread-safe → **YES**
- [x] Decision recorded → **Inline in Proxy (Phase 2a)**

## Technical Audit

> [!NOTE]
> Additional considerations discovered during research:

1. **Magnus `funcall` pattern**: The current code uses `callback.funcall::<_, _, Value>("call", (event_obj,))` to pass Rust-wrapped events. For Ruby `Data.define` classes, we'll need to use `ruby.eval()` or get the class constant and call `.new()` on it.

2. **Event loop already handles HttpResponse**: Lines 142-165 in `event_loop.rs` contain the response building logic that will move to `proxy.rs`.

3. **No changes to responders.rs**: The responder storage mechanism remains unchanged; only where `responder.respond()` is called changes.

## Phase 3: Migrate Event Classes to Ruby

### Proposed Changes

#### [NEW] [events.rb](file:///Users/kerrick/Developer/tokra/lib/tokra/native/events.rb)

```ruby
# frozen_string_literal: true

module Tokra
  module Native
    # IPC message from WebView JavaScript
    IpcEvent = Data.define(:message)

    # Wake-up signal from Ractor via Proxy
    WakeUpEvent = Data.define(:payload)

    # Window close requested
    WindowCloseEvent = Data.define

    # HTTP request from tokra:// custom protocol
    HttpRequestEvent = Data.define(:request_id, :method, :uri, :headers, :body)

    # Page load event (started/finished)
    PageLoadEvent = Data.define(:event, :url) do
      def started? = event == "started"
      def finished? = event == "finished"
    end
  end
end
```

```diff
+    let event_obj = ipc_class.funcall::<_, _, Value>("new", (msg,))?;

 }

 UserEvent::HttpRequest { request_id, method, uri, headers, body } => {
-    let event_obj = RbHttpRequestEvent::new(request_id, method, uri, headers, body);
+    let http_class: magnus::RClass = ruby.eval("Tokra::Native::HttpRequestEvent")?;
+    // Convert headers Vec to Ruby array
+    let event_obj = http_class.funcall::<_, _, Value>(

+    )?;

 }
```

> [!IMPORTANT]
> The `headers` conversion requires creating a Ruby `Array` of `[key, value]` pairs. This may need a helper function.
