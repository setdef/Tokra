# Phase 2.0: Webview Wrapper Class Implementation

Implement `Tokra::Webview` and `Tokra::Window` wrapper classes with per-instance `ResourceTable` support, enabling Phase 2.1-2.4 clipboard image operations.

## User Review Required

> [!IMPORTANT]
> The `ResourceTable` implementation itself is **deferred to Phase 2.1**. This phase creates the placeholder and wiring; Phase 2.1 implements the actual table.

---

## Background: Why Wrappers Are Needed

Tokra's current architecture (as of Phase 1) creates native window and webview objects directly in [app.rb:66-70](file:///Users/kerrick/Developer/tokra/lib/tokra/app.rb#L66-70):

```ruby
window = @window_class.new(event_loop)
window.set_title(@config[:title].to_s)
window.set_size(@config[:width].to_f, @config[:height].to_f)
@webview_class.new_with_protocol(window, proxy)
```

The native webview is created but **not stored**—it's fire-and-forget. This worked for Phase 1 text clipboard operations because text doesn't require resource tracking.

**Phase 2 changes everything.** Image clipboard operations in Tauri work through a `ResourceTable`—a per-webview registry that stores images by integer ID. When JavaScript calls `Clipboard.readImage()`, Tauri:

1. Reads raw image bytes from the system clipboard
2. Wraps them in an `Image` resource object  
3. Stores the resource in the calling webview's `ResourceTable`
4. Returns the integer ID to JavaScript

JavaScript never touches raw bytes; it manipulates resource IDs. This pattern comes from Deno's resource system (see [Tauri's resources/mod.rs](file:///Users/kerrick/Developer/tauri/crates/tauri/src/resources/mod.rs#L1-50)).

To support this, Tokra needs:
- **Webview wrappers** that hold both the native webview and a `ResourceTable`
- **Window wrappers** for the resource fallback hierarchy (webview → window → app)
- **Invoke access** to the calling webview's resources

## Proposed Changes

### Core Architecture

Tauri's `Webview` struct (per [webview/mod.rs:1280-1345](file:///Users/kerrick/Developer/tauri/crates/tauri/src/webview/mod.rs#L1280)) demonstrates the pattern:

```rust
pub struct Webview<R: Runtime> {
    pub(crate) window: Arc<Mutex<Window<R>>>,
    pub(crate) webview: DetachedWebview<...>,
    pub(crate) manager: Arc<AppManager<R>>,
    pub(crate) app_handle: AppHandle<R>,
    pub(crate) resources_table: Arc<Mutex<ResourceTable>>,  // ← Key field
}
```

Each Webview owns its own `ResourceTable`. The clipboard's `read_image`/`write_image` commands access this via `webview.resources_table()` (per [resources/plugin.rs:14-22](file:///Users/kerrick/Developer/tauri/crates/tauri/src/resources/plugin.rs#L14)).

The same pattern applies to `Window` ([window/mod.rs:921-931](file:///Users/kerrick/Developer/tauri/crates/tauri/src/window/mod.rs#L921)), which also has its own `resources_table`. This creates a 3-level fallback hierarchy for resource lookup: webview → window → app. Phase 2.0 establishes this structure; full fallback logic comes in Phase 2.1.

### Tokra::Webview

#### [NEW] [webview.rb](file:///Users/kerrick/Developer/tokra/lib/tokra/webview.rb)

The `Webview` class wraps the native webview handle and provides three key capabilities:

1. **Native access** — The `native` accessor exposes the underlying `Native::WebView` for direct operations like `eval(script)`. This mirrors how Tauri's `Webview` wraps a `DetachedWebview`.

2. **ResourceTable ownership** — Each webview instance creates its own `ResourceTable` at construction. This ensures resources registered from one webview are isolated from others—critical for multi-webview applications.

3. **Manager interface** — By including `Manager` and delegating to `app_handle`, the webview participates in Tokra's unified manager hierarchy. Plugins can call `webview.state(SomePlugin)` exactly as they would on an `AppHandle`.

The delegation pattern follows Tauri's `ManagerBase` trait implementation (per [webview/mod.rs:2265-2281](file:///Users/kerrick/Developer/tauri/crates/tauri/src/webview/mod.rs#L2265)). State methods delegate to the app-level `StateManager` because plugins register state once globally, not per-webview.

```ruby
# lib/tokra/webview.rb
module Tokra
  # Webview wrapper holding native webview reference and ResourceTable.
  #
  # Mirrors Tauri's Webview<R> struct. Each webview owns its own
  # resources_table for storing image resources and other managed objects.
  #
  # Plugins access the calling webview through Invoke#webview:
  #
  #   def invoke_handler(invoke)
  #     table = invoke.webview.resources_table
  #     rid = table.add(MyResource.new)
  #     invoke.resolve(rid)
  #   end
  #
  class Webview
    include Manager

    attr_reader :label, :app_handle

    # Creates a new Webview wrapper.
    #
    # +label+ is a unique identifier for this webview (e.g., "main").
    # +native+ is the Native::WebView handle from wry.
    # +window+ is the parent Window wrapper.
    # +app_handle+ provides access to app-level state and config.
    def initialize(label:, native:, window:, app_handle:)
      @label = label
      @native = native
      @window = window
      @app_handle = app_handle
      @resources_table = ResourceTable.new
    end

    # The native webview handle for direct operations.
    attr_reader :native

    # The parent window containing this webview.
    def window
      @window
    end

    # Per-webview resource table for managed resources.
    #
    # Resources added here are scoped to this webview. The table
    # is cleared when the webview is destroyed.
    def resources_table
      @resources_table
    end

    # Evaluate JavaScript in this webview.
    def eval(script)
      @native.eval(script)
    end

    # Manager delegation (all route to app-level state)
    def config = @app_handle.config
    def state(klass) = @app_handle.state(klass)
    def try_state(klass) = @app_handle.try_state(klass)
    def manage(state) = @app_handle.manage(state)
    def webviews = @app_handle.webviews
    def get_webview(l) = @app_handle.get_webview(l)
    def get_window(l) = @app_handle.get_window(l)
    def windows = @app_handle.windows
  end
end
```

### Tokra::Window

#### [NEW] [window.rb](file:///Users/kerrick/Developer/tokra/lib/tokra/window.rb)

The `Window` class mirrors `Webview` in structure but serves a different role. In Tauri's hierarchy, windows can contain multiple webviews, and the window's `ResourceTable` provides fallback for resources not found in any child webview's table.

For Phase 2.0, we implement the wrapper with its own `ResourceTable`. The fallback lookup logic (webview → window → app) will be added in Phase 2.1 when `ResourceTable.get` is implemented.

Window also delegates native operations like `set_title` and `set_size` to the underlying `Native::Window`. This replaces the direct native calls currently in [app.rb:67-68](file:///Users/kerrick/Developer/tokra/lib/tokra/app.rb#L67-68).

```ruby
# lib/tokra/window.rb
module Tokra
  # Window wrapper holding native window reference and ResourceTable.
  #
  # Mirrors Tauri's Window<R> struct. Each window owns its own
  # resources_table, used as fallback if webview table doesn't have resource.
  class Window
    include Manager

    attr_reader :label, :app_handle

    # Creates a new Window wrapper.
    #
    # +label+ is a unique identifier for this window (e.g., "main").
    # +native+ is the Native::Window handle from tao/winit.
    # +app_handle+ provides access to app-level state and config.
    def initialize(label:, native:, app_handle:)
      @label = label
      @native = native
      @app_handle = app_handle
      @resources_table = ResourceTable.new
    end

    # The native window handle for direct operations.
    attr_reader :native

    # Per-window resource table.
    def resources_table
      @resources_table
    end

    # Set the window title (delegates to native).
    def set_title(title)
      @native.set_title(title)
    end

    # Set the window size (delegates to native).
    def set_size(width, height)
      @native.set_size(width, height)
    end

    # Manager delegation
    def config = @app_handle.config
    def state(klass) = @app_handle.state(klass)
    def try_state(klass) = @app_handle.try_state(klass)
    def manage(state) = @app_handle.manage(state)
    def webviews = @app_handle.webviews
    def get_webview(l) = @app_handle.get_webview(l)
    def get_window(l) = @app_handle.get_window(l)
    def windows = @app_handle.windows
  end
end
```

### Manager Interface Update

#### [MODIFY] [manager.rb](file:///Users/kerrick/Developer/tokra/lib/tokra/manager.rb#L88)

The `Manager` module defines the shared interface for `AppHandle`, `Window`, and `Webview`. We add `resources_table` as a required abstract method.

Currently, `Manager` has methods like `config`, `state`, `manage`, `webviews`, etc. (see [manager.rb:28-90](file:///Users/kerrick/Developer/tokra/lib/tokra/manager.rb#L28-90)). Adding `resources_table` here ensures all manager types provide it, enabling polymorphic resource access.

The implementation varies by type:
- `Webview` returns its per-webview table
- `Window` returns its per-window table  
- `AppHandle` returns an app-level fallback table

Insert around line 88 (after the existing abstract methods):

```ruby
# Returns the resources table for this manager.
#
# Each manager type has its own ResourceTable instance.
# Webview and Window tables are created at initialization;
# AppHandle creates its table lazily.
def resources_table
  raise NotImplementedError, "#{self.class} must implement #resources_table"
end
```

### Invoke Webview Accessor

#### [MODIFY] [invoke.rb](file:///Users/kerrick/Developer/tokra/lib/tokra/invoke.rb#L18-35)

The `Invoke` object is passed to plugin command handlers. Currently it provides `command`, `payload`, and `responder`. To support resource operations, handlers need access to the calling webview's `ResourceTable`.

In Tauri, `InvokeMessage` always contains a `Webview<R>` ([ipc/mod.rs:500](file:///Users/kerrick/Developer/tauri/crates/tauri/src/ipc/mod.rs#L500)) — it's not optional. IPC calls always originate from a webview. Tokra should match this exactly: webview is required.

Update the class at lines 18-35:

```ruby
# The webview that made this IPC call.
attr_reader :webview

def initialize(command:, payload:, responder:, webview:)
  @command = command
  @payload = payload
  @responder = responder
  @webview = webview
  @responded = false
end
```

This will require updating existing tests that create `Invoke` objects to pass a webview.

### App#run Updates

#### [MODIFY] [app.rb](file:///Users/kerrick/Developer/tokra/lib/tokra/app.rb#L62-84)

The core change: instead of creating native objects directly and losing the reference, we create wrapper objects that hold the natives and register them with `AppManager`.

Current code (lines 62-70):
```ruby
event_loop = @event_loop_class.new
proxy = event_loop.create_proxy
window = @window_class.new(event_loop)
window.set_title(@config[:title].to_s)
window.set_size(@config[:width].to_f, @config[:height].to_f)
@webview_class.new_with_protocol(window, proxy)
```

New code wraps natives in `Window` and `Webview`, then registers them with `AppManager` for later lookup via `app_handle.get_webview("main")`:

```ruby
def run(&callback)
  @builder.__send__(:setup_hook)&.call(self)

  event_loop = @event_loop_class.new
  proxy = event_loop.create_proxy

  native_window = @window_class.new(event_loop)

  # Create Window wrapper holding native handle
  window = Window.new(label: "main", native: native_window, app_handle: @handle)
  window.set_title(@config[:title].to_s)
  window.set_size(@config[:width].to_f, @config[:height].to_f)
  @handle.instance_variable_get(:@manager).windows["main"] = window

  # Create native webview
  native_webview = @webview_class.new_with_protocol(native_window, proxy)

  # Create Webview wrapper holding native handle
  webview = Webview.new(label: "main", native: native_webview, window: window, app_handle: @handle)
  @handle.instance_variable_get(:@manager).webviews["main"] = webview

  # Emit Ready event
  callback&.call(@handle, RunEvent::Ready.new)
  # ... rest unchanged
end
```

The webview wrapper is stored so IPC dispatch can pass it to `Invoke`. This wiring (dispatching with the correct webview) will be completed when updating the IPC dispatch in the next section.

### AppHandle Updates  

#### [MODIFY] [app_handle.rb](file:///Users/kerrick/Developer/tokra/lib/tokra/app_handle.rb#L60-86)

`AppHandle` needs three additions to satisfy the `Manager` interface:

1. **`resources_table`** — The app-level fallback table, created lazily
2. **`windows`** — Accessor for the windows hash
3. **`get_window`** — Lookup a window by label

These mirror the existing `webviews` and `get_webview` methods. Insert after line 73:

```ruby
# Returns the app-level resources table.
#
# This is the final fallback in the hierarchy: webview → window → app.
# Created lazily on first access.
def resources_table
  @resources_table ||= ResourceTable.new
end

# Returns all managed windows.
def windows
  @manager.windows
end

# Fetches a window by label.
#
# Returns nil if no window with that label exists.
def get_window(label)
  @manager.windows[label]
end
```
