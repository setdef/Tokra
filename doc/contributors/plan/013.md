# Plan 013: Phase 2.4 — Clipboard Image IPC and Plugin Lifecycle Fidelity

Give `Tokra::Plugins::Clipboard::Plugin` the image and HTML halves of
Tauri's clipboard-manager (Ruby methods plus IPC handlers), re-case it onto
the Phase 2.2 `PluginStore` routing, and repair the plugin lifecycle
deviations that currently make a store-registered clipboard plugin
non-functional. This is the final step of [Plan 009](009.md).

## Context

Phase 2.3 (native layer) finished the primitives. But wiring the clipboard
plugin into the Phase 2.2 router exposed lifecycle gaps: nothing ever calls
the gem's invented `on_register` hook, and nothing dispatches run events to
registered plugins — so the plugin's managed state is never stored and its
`RunEvent::Exit` cleanup (which arboard requires before process exit) never
fires. A fidelity pass over the base `Plugin` class against Tauri's
`Plugin` trait (tauri/src/plugin.rs:37-112) also found hook-name drift.
Per the standing directive, unfaithful things do not stay without a
documented reason.

## Fidelity Audit

| Behavior | Tauri | Tokra today | Verdict |
|---|---|---|---|
| Window/webview hooks | `window_created`, `webview_created` | `on_window_created`, `on_webview_created` | **Fix here** (D4) |
| Run event hook | `on_event(&mut self, app, event)` | `on_event(event)` — no app | **Fix here** (D4) |
| Plugins receive run events | `PluginStore::on_event` called per event | Never dispatched | **Fix here** (D3) |
| Plugin initialization | `Plugin::initialize(app, config)` called at registration (`AppHandle::plugin` → `store.initialize` then `register`, app.rs:494-500) | Gem invents `on_register(app)`; nothing calls it | **Fix here** (D2) |
| JsImage resolution | `JsImage::into_img(&resources_table)` in core `image/mod.rs:169-229` | Missing | **Add here, in core** (D1) |
| Clipboard error taxonomy | Single `Error::Clipboard(String)` | `ClipboardOccupiedError`, `ClipboardUnavailableError` — dead code | **Fix here** (D5) |
| Command matching | Bare names (router strips `plugin:NAME|`) | Full strings | **Fix here** (D6) |
| `Builder::plugin` | Exists (app.rs:1701) | Missing; gem RDoc example references it | **Defer**; fix the example (D7) |

## Design Decisions

1. **`Tokra::JsImage` lives in core, co-located with `Image`.** Mirrors
   `image/mod.rs`, where `JsImage` sits beside `Image` (precedent:
   `plugin.rb` holds `Plugin` and `PluginStore`). It wraps the raw payload
   value and exposes `into_img(resources_table)` (Tauri's exact name),
   resolving the four untagged variants by JSON type:
   Integer → `resources_table.get(rid)` (must be an `Image`, else
   `Error::BadResourceId` — the typed-downcast parity established by the
   core image plugin); Array → `Image.from_bytes(value.pack("C*"))`;
   String → `Image.from_path(value)`; Hash → `Image.new` from
   `rgba`/`width`/`height` keys. Anything else raises `ArgumentError`
   (<tt>invalid args: image must be a resource ID, byte array, file path,
   or RGBA hash</tt>), following the core plugins' argument-message style.
   Tokra decodes unconditionally (Phase 2.2 decision), so the
   feature-gated arms need no gate here.

2. **Registration initializes the plugin — via the Ruby constructor.**
   Tauri constructs a plugin without an app, then calls
   `Plugin::initialize(app, config)` at registration. Tokra's base class
   already maps that lifecycle method onto the Ruby constructor
   (`Plugin.new(app, config)`), and the core plugins already construct at
   registration time (`Resources::Plugin.new(@handle)`), which is exactly
   Tauri's timing. The clipboard gem aligns: `initialize(app, config = {})`
   calls `super`, creates the Ractor-shareable native clipboard, and calls
   `app.manage(@native)` — the body of Tauri's setup closure
   (clipboard-manager `lib.rs`: `app.manage(clipboard)`). The invented,
   never-called `on_register` is deleted.

3. **Run events reach plugins.** `PluginStore#on_event(app, event)`
   iterates registered plugins (mirrors `PluginStore::on_event`,
   plugin.rs). `App` emits every `RunEvent` through the store before the
   user callback — a private `emit_run_event(event, callback)` replacing
   the two `callback&.call(@handle, ...)` sites (Exit, WindowEvent). This
   makes the clipboard's Exit cleanup actually run.

4. **Base `Plugin` hooks take Tauri's names.** `on_window_created` →
   `window_created`, `on_webview_created` → `webview_created`, and
   `on_event(event)` → `on_event(app, event)`. Breaking, pre-1.0; grep
   shows no core callers of the renamed hooks yet, and the clipboard gem
   is updated in the same change. CHANGELOG records all three.

5. **One clipboard error class.** Delete `ClipboardOccupiedError` and
   `ClipboardUnavailableError` (dead code, no Tauri counterpart). Add
   `Error::Clipboard` nested under the gem's `Error` (chat 017's nesting
   convention), mirroring `tauri_plugin_clipboard_manager::Error::Clipboard(String)`.
   Every Ruby-facing plugin method (`read_text`, `write_text`,
   `read_image`, `write_image`, `write_html`, `clear`) rescues the native
   layer's `RuntimeError` and re-raises `Error::Clipboard` with the same
   message — the Ruby analog of Tauri's `From<arboard::Error>` conversion.

6. **Bare commands, rescue-to-reject.** `extend_api` matches
   `read_text`/`write_text`/`read_image`/`write_image`/`write_html`/`clear`
   (the Phase 2.2 router strips the `plugin:clipboard-manager|` prefix) and
   rescues `Error::Clipboard`, `Tokra::Error::BadResourceId`,
   `Tokra::Error::Image`, `ArgumentError`, and `SystemCallError` into
   `invoke.reject(e.message)` — the Result-to-InvokeError propagation
   pattern the core plugins use. Payload keys are the wire's camelCase:
   `payload["altText"]` for `write_html` (guest-js sends
   `{ html, altText }`); `write_text` reads `payload["text"]` and ignores
   `label` (desktop parity — Tauri's desktop command ignores it too).

7. **`Builder#plugin` stays deferred.** Registration in this phase is
   `AppHandle#plugin` (a first-class Tauri path, app.rs:485). The gem's
   class RDoc example — which references a `Builder#plugin` that has never
   existed — is corrected to the setup-hook form. A future phase can add
   `Builder#plugin`; it must solve Ractor-shareability of pre-build plugin
   instances, which this phase does not need.

## Changes

### Core

1. **`lib/tokra/image.rb`** — add `JsImage` class (D1) with SPDX snippet
   marker, full Context-Problem-Solution RDoc, and `into_img` citing
   image/mod.rs:169-229.
2. **`lib/tokra/plugin.rb`** — rename hooks, add `app` param to `on_event`
   (D4); add `PluginStore#on_event(app, event)` (D3).
3. **`lib/tokra/app.rb`** — `emit_run_event` helper; route the Exit and
   WindowEvent emissions through it (D3).
4. **`sig/tokra/image.rbs`** — `JsImage` (`def into_img:
   (ResourceTable) -> Image`); **`sig/tokra/plugin.rbs`** — renamed hooks,
   `on_event: (AppHandle, RunEvent::base) -> void` on both `Plugin` and
   `PluginStore`; **`sig/tokra/app.rbs`** — `emit_run_event`.
5. **`CHANGELOG.md`** — Added: `Tokra::JsImage`; plugins receive every
   `RunEvent` via `Plugin#on_event(app, event)`. Changed (breaking):
   hook renames and the `on_event` signature.
6. **Core tests** — `test/test_js_image.rb` (all four variants resolve;
   rid of a non-Image raises `BadResourceId`; unknown rid propagates;
   invalid type raises `ArgumentError`; PNG fixture path decodes);
   `test/test_plugin_store.rb` gains `on_event` fan-out coverage;
   `test/builder/test_event_dispatch.rb` (or a sibling) verifies a
   registered plugin sees `RunEvent::Exit` with the handle.

### Clipboard gem

7. **`lib/tokra/plugins/clipboard.rb`** —
   - `initialize(app, config = {})` per D2; delete `on_register`.
   - `read_image` → `Tokra::Image` via `Image.new(*@native.read_image)`;
     `write_image(image)` taking a `Tokra::Image`;
     `write_html(html, alt_text = nil)`; all six operations wrap native
     errors per D5.
   - `extend_api` per D6; `read_image` handler stores the image in
     `invoke.webview.resources_table` and resolves the rid (commands.rs:53-61);
     `write_image` handler resolves the payload through
     `Tokra::JsImage#into_img` (commands.rs:43-50).
   - `on_event(app, event)` signature (D4).
   - RDoc: JS API section gains the image/HTML commands; the Ruby API
     example becomes the setup-hook registration form (D7); document that
     empty-clipboard reads raise `Error::Clipboard`.
8. **`sig/tokra/plugins/clipboard.rbs`** — error classes per D5; new
   methods; `initialize` → `self.new: (Tokra::AppHandle, ?Hash[Symbol | String, untyped]) -> Plugin`
   — no: config type stays concrete (`Hash[Symbol, Object]` or the gem's
   existing convention); no `untyped`.
9. **`test/test_clipboard.rb`** — existing `Plugin.new` call sites gain a
   stub app (responds to `manage`); dispatch tests move to bare commands;
   new IPC tests: `read_image` resolves an Integer rid and the webview
   table holds a `Tokra::Image`; `write_image` accepts each JsImage
   variant (rid, byte array, PNG fixture path, RGBA hash) and rejects
   unknown rids and invalid types; `write_html` honors `altText`;
   `read_text` on an empty clipboard rejects with arboard's message;
   `on_event(app, RunEvent::Exit)` still cleans up.

## Out of Scope

- `Builder#plugin` (D7) and any Ractor-shareability work for pre-build
  plugin registration.
- `write_text`'s mobile `label` behavior (desktop ignores it, like Tauri).
- The responder gap in `dispatch_ipc` (`responder: nil`) — real JS
  callback wiring is its own phase; these handlers are exercised through
  `extend_api` with test responders, as all plugin tests are today.

## Risks

- **Hook renames are breaking** for any local code overriding
  `on_window_created`/`on_webview_created`/`on_event` — only the clipboard
  gem does, and it changes in the same commit. CHANGELOG records the break.
- **`JsImage` untagged-variant ambiguity**: JSON has no `Uint8Array`, so a
  byte array and an "array of something else" are indistinguishable until
  `pack("C*")`/decode fails; the resulting `Error::Image`/`ArgumentError`
  rejection matches Tauri, whose serde untagged deserialization fails the
  invoke the same way.
- **Run-event fan-out ordering**: plugins hear events before the user
  callback. Tauri does the same (plugins first), so the order is fixed by
  parity, not taste.
