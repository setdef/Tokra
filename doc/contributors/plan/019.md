# Plan 019: Rust Quality Gates and CI

Ferro, the sibling project that takes over Tokra's standalone crate
bindings ([ADR 011](../adr/011.md)), started with two things Tokra lacks: a
gate that reads every cargo step's output, and CI on Linux, macOS, and
Windows. Both came from Tokra's own gate, adapted, so this plan ports them
back. Sources: Ferro commits `2304555` (Rust quality; its plan 001,
decisions 18 and 19) and `b713e7b` (CI; plan 001, "Follow-up: CI"). The two
parts are separable and land as separate commits.

## Part 1: Rust quality

### Problem

The gate trusts each cargo step's exit status. Most steps exit zero with
warnings: `cargo build` and `cargo test` print rustc warnings and succeed,
and rb_sys's Makefile hides the compile behind make. Even `clippy -D
warnings` lets some through: an unknown lint in a `[lints]` table reaches
rustc as a command-line flag, and `unknown_lints` ignores `-D warnings`.
Ferro learned this when a misplaced lints header turned `unsafe_code` into
`clippy::unsafe_code`, printed `warning[E0602]`, and disabled the unsafe
code lint while the gate passed.

Tokra's crates deny `unsafe_code` and allow it per block, but nothing
requires the block to say why it is sound, and nothing stops a value from
being leaked into a `'static`.

### Design

1. **`tasks/cargo_output.rb` (`CargoOutput`)**, ported from Ferro: runs a
   command, echoes its output, and fails if it exits non-zero or prints a
   line that starts `warning:` or `warning[CODE]:`. Indented lines (`=
   warning:` notes) and Ruby's `file:line: warning:` do not count.
   Tooling tests in `test/tasks/test_cargo_output.rb` drive it with small
   Ruby scripts in place of cargo.
2. **Every cargo step the gate runs goes through it.** `compile:strict`,
   the gate's first step, compiles tokra and each plugin with a native
   crate in a child rake, so the extension builds are read; Cargo replays a
   crate's warnings on a cached build, so later no-op compiles cannot hide
   one. `test:rust`, `rust:clippy`, `rust:fmt`, `rust:check`, and a new
   `package:fetch` (`cargo fetch --locked`) use it too. Every cargo command
   that resolves passes `--locked`.
3. **`clippy::undocumented_unsafe_blocks = "deny"`** in each crate's
   `[lints.clippy]`. Each remaining `unsafe` gets a `SAFETY` comment citing
   the source, at its locked version, that justifies it. Two hand-written
   `unsafe impl TypedData` blocks (`RbProxy`, `RbClipboard`) existed only to
   set `frozen_shareable`, which magnus's `wrap` macro supports
   (magnus-macros `typed_data.rs:65-66`, `216-217`); they become `wrap`
   attributes. `unsafe impl Send for RbWindow` is redundant: tao's `Window`
   is `Send + Sync` on every desktop platform (`platform_impl/macos/mod.rs:68-69`,
   `linux/window.rs:1058-1059`; on Windows every field is), so it goes.
4. **`clippy.toml` `disallowed-methods`** for `Box::leak` and `Vec::leak`,
   moved into each crate so it ships with the gem and applies to that crate
   alone; the empty root file goes. Neither crate leaks today.
5. **`[profile.release]` with `strip = false` and `debug = false`** in
   each native gem's workspace root, the only place Cargo reads profiles,
   so a panic backtrace from an installed gem names Tokra's functions from
   the symbol table. Ferro also keeps debug info (`debug = true`), but on
   Linux that grows tokra.so from 2 MB (stripped) to 94 MB; line tables
   alone make it 29 MB, and symbols alone 6 MB (measured on aarch64 Linux),
   so Tokra keeps the symbols only. Not stripping also keeps rust-objcopy,
   whose stripping macOS 27 rejected before Rust 1.99 (commit `b6897c7`),
   out of the release build. `package:check` and `package:install` confirm
   the packaged gems still load.
6. **`cargo fmt --all --check`**, and a `rust:clippy:fix` task for
   Clippy's automatic fixes.
7. **Lints tables audit.** Each crate's `[lints.clippy]` and
   `[lints.rust]` sit under their own headers, after `[dependencies]`, with
   `unsafe_code` under `[lints.rust]`.

### Mutation checks

Each must fail the gate, then be reverted: an unused variable (compile),
a removed `SAFETY` comment (Clippy), a `Box::leak` (Clippy), and a lints
header moved so `unsafe_code` lands under `[lints.clippy]` (the `E0602`
warning).

### Finding: the main-thread `Send` impls

`unsafe impl Send` remains on `RbEventLoop` and `RbWebView`, whose tao and
wry values must stay on the main thread. magnus requires `Send` for any
wrapped type (`typed_data.rs:411-413`) because Ruby can hand an object to
any Ruby thread. The impls are sound only while every call and the drop
happen on the main thread. Tokra keeps its own calls there, tao creates the
loop only on the main thread, and the extension is not Ractor-safe, so
other Ractors cannot call it. But app code on another Ruby `Thread` can call
these objects' methods, and a garbage collection that runs on another
thread can free them. The `SAFETY` comments now say exactly this. Closing
the gap, by checking the calling thread and refusing a foreign one, or by
dispatching to the main thread as Tauri does, is a design decision left to
a follow-up.

## Part 2: CI

### Design

`.github/workflows/ci.yml` runs the gate, `bundle exec rake`, on
`ubuntu-latest`, `macos-latest`, and `windows-latest`, once per supported
Ruby (today 4.0; adding a release is one matrix line). It runs on pushes to
`trunk` and on pull requests, cancels superseded runs, reads only the
repository, checks out without persisted credentials, pins every action to
a full commit SHA, and reads the Rust and Python pins from `mise.toml`.

- **Linux** installs the libraries the locked `-sys` crates link:
  `libwebkit2gtk-4.1-dev` (wry's README), `libgtk-3-dev` (tao's README),
  `libsoup-3.0-dev`, and `libjavascriptcoregtk-4.1-dev`, with `pkg-config`
  and `libclang-dev` for bindgen. libX11 needs no headers: the locked `x11`
  crate is used for its types only, and `x11-dl` loads it at run time. The gate runs under
  `xvfb-run` and `dbus-run-session`, so `RealApp`'s real-window tests and
  the in-process `Native` tests run against a real X server. The clipboard
  plugin speaks X11 through arboard's pure-Rust client, and on X11 text
  outlives the last clipboard only once a clipboard manager takes it over
  (arboard `src/platform/linux/x11.rs`), so `xfce4-clipman` runs beside
  Xvfb, as in Ferro.
- **macOS** runs the gate as is. `RealApp` skips unless `launchctl
  managername` reports `Aqua`; a step prints it, so the first run shows
  whether GitHub's runners have a GUI session.
- **Windows** builds with Rust's GNU toolchain, because RubyInstaller's
  Ruby is a MinGW build and rb-sys refuses the MSVC target for it, and
  points bindgen at the MSYS2 headers setup-ruby installs, as Ferro does.
  `RealApp` skips Windows by design (Plan 018). Git checks out symlinks as
  symlinks.

### Validation

actionlint and shellcheck pass on the workflow. A Docker run of the Linux
job's steps, in the `ruby:4.0` image (Debian 13, aarch64, Ruby 4.0.9, so
not the runner's Ubuntu on x86_64), found what the macOS-only gate had
hidden:

- tao's Linux backend registers a GtkApplication on the session bus for
  each event loop (`platform_impl/linux/event_loop.rs:227-230`), so the
  second `Native::EventLoop.new` in one process panics, and the panic ended
  the whole test run. The in-process native tests now share one loop
  (`test/support/native_event_loop.rb`); an app has one anyway.
- Every request body over `tokra://` and `ipc://` arrived empty: wry hands
  WebKitGTK's body to the handler only with its `linux-body` feature
  (`src/webkitgtk/web_context.rs:175-205`), which tauri-runtime-wry
  enables (`Cargo.toml:15-20`) and Tokra did not. It is on now. Every
  real-window fixture reports over a POST, so all of them hung.
- On WebKitGTK, wry reports the webview's top-level URI for every
  `postMessage`, not the sending frame's (`src/webkitgtk/mod.rs:635-645`),
  so the local-origin stopgap (ADR 010 §6) cannot reject a foreign frame
  over `postMessage` on Linux. Tauri parses the same URI
  (`ipc/protocol.rs:302`) and decides locality from it
  (`webview/mod.rs:1726`), so this matches Tauri. `ipc://` still rejects
  the foreign frame. The test asserts what Linux does, so a wry change that
  reports the frame shows up, and ADR 010 §6 and `App#route_invoke`'s RDoc
  now say so.
- setup-ruby's `bundler-cache` installs the bundle in `vendor/bundle`,
  which RuboCop's `Exclude` (it replaces the default) and `.gitignore` did
  not cover.
- As in Ferro, the packaging tests resolve fixture crates with `cargo
  metadata --offline`, which needs every platform's crates in Cargo's
  cache, so `test:core` depends on `package:fetch`; and their fixture
  ignored only `*.bundle`, so on Linux the fake `.so` counted as untracked.
- The in-process native tests skipped whenever `CI` was set without
  `DISPLAY`. GitHub's macOS and Windows runners set `CI` and never
  `DISPLAY`, so they would have skipped there for no reason. Only Linux needs a display
  server for an event loop, so the rule is now Linux's alone.

With those fixed the Linux gate passes under Xvfb with the real-window
tests running: 473 core runs with 4 skips (the macOS- and Windows-only path
tests), 56 clipboard runs, 83 log runs.
WebKitGTK under Xvfb needed nothing beyond the packages above; it prints
AT-SPI warnings about a missing accessibility bus, which are harmless.

### Unverifiable until the first push

macOS's GUI session and Windows. On the GNU target, wry links
`WebView2Loader.dll` dynamically (webview2-com-sys `src/lib.rs:15-22`), and
Tauri copies that DLL beside the executable for GNU builds (tauri-build
`src/lib.rs:660-682`). Tokra ships no such copy, so the extension may fail
to load under RubyInstaller; if the first Windows run shows that, shipping
or locating the loader is a follow-up, not a CI change.
