# Plan 065: tokra-log does what Tauri's log plugin does

An agent that built an example app on every plugin found that tokra-log
falls short of Tauri's: the page's `@tauri-apps/plugin-log` functions
reach nothing, the page's lines carry no timestamp, a `progname` with a
Webview target raises `NoMethodError`, and the timestamps come from
Ruby's Logger rather than the time crate. Reading the plugin against its
source found those four and more. tokra-log grew as a wrapper around
Ruby's Logger with Tauri's names, so its lines, its files, its rotation,
its defaults, and its filters all followed Logger. This plan ports the
plugin itself.

Sources: plugins-workspace `d4613ff0` (the commit every Tokra plugin
ports), `plugins/log/src/lib.rs`, `src/commands.rs`, `guest-js/index.ts`,
`permissions/default.toml`; and the versions its `Cargo.lock` pins, read
from Cargo's registry: fern 0.7.1 (`src/log_impl.rs`), log 0.4.27 (read
as 0.4.29, whose `Level` and `LevelFilter` text is the same), serde_repr
0.1.20 (read as 0.1.19, the same error text), and time 0.3.41, whose
local-offset code matches 0.3.55's, the release ferro-time 0.1.0 binds.
Line numbers below are `d4613ff0`'s; the agent's report cited a later
upstream (`lib.rs:640-655`, `405-417`), which moved the same code.

## How Tauri's plugin works

The plugin builds one fern `Dispatch` and installs it as the process's
`log` logger (`lib.rs:567-719`). A record passes the top dispatch's
level and filters, is formatted once by the top dispatch's format, and
goes, formatted, to each target's own dispatch, which applies the
target's filters and, if it has one, the target's format to the already
formatted line (fern `log_impl.rs:446-550`). Each target writes the line
it receives: standard output and error with a newline, a folder or the
log directory through `RotatingFile`, the webview as a `log://log`
event. The page's `log` command builds a record whose target is
`webview` or `webview:<location>` and hands it to the same logger
(`commands.rs:11-41`).

## Decisions

1. **One dispatch, ported.** The plugin keeps a list of outputs, one per
   target, and logs a record as fern does: the builder's level and
   filters, then the builder's format, then each target's filters,
   format, and output. Ruby's Logger is gone from the inside; Tauri's
   behavior lives in the dispatch, and a Logger can no longer leak its
   own format, rotation, or attributes into it. That is what made the
   Webview target crash (claim 3) and drop the timestamp (claim 2).

2. **A format is a block that returns the line.** fern's format takes a
   `FormatCallback` and calls `out.finish(format_args!(...))` because
   `format_args!` borrows; the callback exists for Rust's lifetimes, so
   by the first rule of the precedence it is translated: Tokra's format
   receives `(message, record)` and returns the line. A record is a
   `Record` value with fern's fields (`args`, `level`, `target`, `file`,
   `line`, `key_values`) and `metadata`, a `Metadata` of level and
   target. Levels are the symbols `:error`, `:warn`, `:info`, `:debug`,
   and `:trace`, as `log::Level` names them, and `LEVEL` text is log's
   (`ERROR`, `WARN`, ...).

3. **Timestamps through ferro-time.** `TimezoneStrategy#get_now` returns
   a `Ferro::Time::OffsetDateTime` (UTC, or local falling back to UTC on
   `IndeterminateOffset`), and the formats are time's format
   descriptions, parsed once with `FormatDescription.parse_borrowed(1, ...)`,
   the run-time equivalent of `format_description!`. tokra-log depends
   on `ferro-time = 0.1.0`, the release tokra-notification pins.

4. **The quirks stay.** `timezone_strategy` replaces the format, with the
   level before the target, the reverse of the default; it replaces a
   format set before it, and a later `format` replaces it.
   `max_file_size` above `u64::MAX` is clamped. `RotatingFile` names its
   file with Rust's `with_extension("log")`, which replaces an extension
   the name already has, but looks for archives by `<file_name>_`.

5. **Folder and LogDir write through a port of `RotatingFile`.** Each
   record is written whole and the file is flushed, as fern's writer
   output does, so the size check sees the line and its newline.
   Rotation follows `lib.rs:186-262`, names archives with
   `LOG_DATE_FORMAT` in the builder's timezone strategy, and moves a
   clashing archive to `.bak`. A `KeepSome(0)` is not pinned: Rust
   underflows `keep_count - 1`.

6. **Webview emits from the logging thread.** Tauri spawns the emit on
   its async runtime so a log call never waits on a webview. Tokra has
   no async runtime, and `AppHandle#emit` only evaluates a script in
   each page and calls the Ruby handlers, so the output emits before the
   log call returns. The payload is the formatted line and its
   `LogLevel`. One consequence differs: a Ruby `log://log` handler that
   logs to the same plugin recurses, where Tauri's would queue.

7. **The `log` command logs through the plugin.** Tauri's command logs to
   `log::logger()`, the global logger the plugin installed. Ruby has no
   global logger, so the command hands its record to the plugin that
   served it, which is the same logger in every case the plugin's
   `build` covers. Arguments read as Tauri's types: `level` as
   serde_repr's `LogLevel` (`invalid value: 7, expected one of: 1, 2,
   3, 4, 5`), `message` a `String`, `location` and `file`
   `Option<&str>`, `line` `Option<u32>`, `keyValues`
   `Option<HashMap<String, String>>`. A bad argument rejects with
   Tauri's `invalid args` message; the command resolves `null`.

8. **The Ruby-side API is the log macros, and Logger's shape.** Rust code
   logs with `log::info!`; Ruby code calls the plugin: `trace`, `debug`,
   `info`, `warn`, `error`, `fatal`, and `add` with Logger's arguments,
   so the plugin can stand in for a Logger a library takes. Logger's
   `FATAL` and `UNKNOWN` log at `:error`, log's highest level. A
   record's target is the call's `progname`, or else the app's name, as
   a Rust record's target is its module path, which in an app starts
   with the app's crate. `Builder#progname`, `#datetime_format`,
   `Target#rotation_strategy`, `Target#timezone_strategy`, `Plugin#<<`,
   `Plugin#with_level`, `TracingLogger`, `WebviewLogger`, and the IO and
   Pathname target kinds go: each was Logger's API, not Tauri's, and the
   gem has not been released. `TargetKind::Dispatch` takes any Ruby
   Logger, Tauri's escape hatch for arbitrary targets.

9. **`level_for` and `with_colors` stay declined.** `level_for` filters by
   Rust module path, which Ruby records lack; `with_colors` needs fern's
   colors. Both raise `NotImplementedError` with the reason and the
   alternative. `level_for` moves from `Plugin` to `Builder`, where Tauri
   has it.

10. **`skip_logger` and `split` are declined.** Both exist so a Rust app
    can install its own global logger or compose the plugin's into one.
    Ruby has no global logger to install, and a skipped logger would
    make the plugin's `log` command drop every record silently. Both
    raise `NotImplementedError`; `TargetKind::Dispatch` sends the
    plugin's records to the app's own Logger.

11. **Construction is untouched but for the app handle.** The plugin is
    still built from a `Builder` and registered by the caller; another
    agent is changing registration. When `Builder#app_handle` is given,
    LogDir reads the handle's path resolver and the app's name from it,
    as Tauri's `acquire_logger` reads `app_handle.path()` and
    `package_info().name`; `path_resolver` and `app_name` still override.
    A LogDir target with neither raises `ArgumentError` when the plugin
    builds.

## Changes

1. `ferro-time` dependency; `TimezoneStrategy#get_now`.
2. The dispatch: `Record`, `Metadata`, `LogLevel`, formats, levels,
   filters, target kinds, outputs, `RotatingFile`, defaults.
3. The `log` command in `extend_api`.
4. README, RDoc, RBS, and the CHANGELOG's tokra-log entry.

## Verification

Each change is test-first in `plugins/log/test/`, through a real
`AppHandle` from Tokra's `StubNative` where the handle matters, a real
listener for `log://log`, and real files in a temporary directory. Each
new behavior was reverted by hand to see its test fail. Not verified
here: the page's own `@tauri-apps/plugin-log` against a real webview
(no window may open on the maintainer's Mac); Linux and Windows.

## Out of scope

Capabilities (`allow-log`), the path resolver's Linux and Windows log
directory, and the plugin's registration.
