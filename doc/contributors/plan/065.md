# Plan 065: tokra-log does what Tauri's log plugin does

An agent that built an example app on every plugin found that tokra-log
falls short of Tauri's: the page's `@tauri-apps/plugin-log` functions
reach nothing, the page's lines carry no timestamp, a `progname` with a
Webview target raises `NoMethodError`, and the timestamps come from
Ruby's Logger rather than the time crate. Reading the plugin against its
source found those four and more. tokra-log grew as a wrapper around
Ruby's Logger with Tauri's names, so its lines, its files, its rotation,
its defaults, and its filters all followed Logger. This plan ports the
plugin itself.

Sources: plugins-workspace `d4613ff0` (the commit every Tokra plugin
ports), `plugins/log/src/lib.rs`, `src/commands.rs`, `guest-js/index.ts`,
`permissions/default.toml`; and the versions its `Cargo.lock` pins, read
from Cargo's registry: fern 0.7.1 (`src/log_impl.rs`), log 0.4.27 (read
as 0.4.29, whose `Level` and `LevelFilter` text is the same), serde_repr
0.1.20 (read as 0.1.19, the same error text), and time 0.3.41, whose
local-offset code matches 0.3.55's, the release ferro-time 0.1.0 binds.
Line numbers below are `d4613ff0`'s; the agent's report cited a later
upstream (`lib.rs:640-655`, `405-417`), which moved the same code.

## How Tauri's plugin works

The plugin builds one fern `Dispatch` and installs it as the process's
`log` logger (`lib.rs:567-719`). A record passes the top dispatch's
level and filters, is formatted once by the top dispatch's format, and
goes, formatted, to each target's own dispatch, which applies the
target's filters and, if it has one, the target's format to the already
formatted line (fern `log_impl.rs:446-550`). Each target writes the line
it receives: standard output and error with a newline, a folder or the
log directory through `RotatingFile`, the webview as a `log://log`
event. The page's `log` command builds a record whose target is
`webview` or `webview:<location>` and hands it to the same logger
(`commands.rs:11-41`).

## Decisions

1. **One dispatch, ported.** The plugin keeps a list of outputs, one per
   target, and logs a record as fern does: the builder's level and
   filters, then the builder's format, then each target's filters,
   format, and output. Ruby's Logger is gone from the inside; Tauri's
   behavior lives in the dispatch, and a Logger can no longer leak its
   own format, rotation, or attributes into it. That is what made the
   Webview target crash (claim 3) and drop the timestamp (claim 2).

2. **A format is a block that returns the line.** fern's format takes a
   `FormatCallback` and calls `out.finish(format_args!(...))` because
   `format_args!` borrows; the callback exists for Rust's lifetimes, so
   by the first rule of the precedence it is translated: Tokra's format
   receives `(message, record)` and returns the line. A record is a
   `Record` value with fern's fields (`args`, `level`, `target`, `file`,
   `line`, `key_values`) and `metadata`, a `Metadata` of level and
   target. Levels are the symbols `:error`, `:warn`, `:info`, `:debug`,
   and `:trace`, as `log::Level` names them, and `LEVEL` text is log's
   (`ERROR`, `WARN`, ...).

3. **Timestamps through ferro-time.** `TimezoneStrategy#get_now` returns
   a `Ferro::Time::OffsetDateTime` (UTC, or local falling back to UTC on
   `IndeterminateOffset`), and the formats are time's format
   descriptions, parsed once with `FormatDescription.parse_borrowed(1, ...)`,
   the run-time equivalent of `format_description!`. tokra-log depends
   on `ferro-time = 0.1.0`, the release tokra-notification pins.

4. **The quirks stay.** `timezone_strategy` replaces the format, with the
   level before the target, the reverse of the default; it replaces a
   format set before it, and a later `format` replaces it.
   `max_file_size` above `u64::MAX` is clamped. `RotatingFile` names its
   file with Rust's `with_extension("log")`, which replaces an extension
   the name already has, but looks for archives by `<file_name>_`.

5. **Folder and LogDir write through a port of `RotatingFile`.** Each
   record is written whole and the file is flushed, as fern's writer
   output does, so the size check sees the line and its newline.
   Rotation follows `lib.rs:186-262`, names archives with
   `LOG_DATE_FORMAT` in the builder's timezone strategy, and moves a
   clashing archive to `.bak`. A `KeepSome(0)` is not pinned: Rust
   underflows `keep_count - 1`.

6. **Webview emits from the logging thread.** Tauri spawns the emit on
   its async runtime so a log call never waits on a webview. Tokra has
   no async runtime, and `AppHandle#emit` only evaluates a script in
   each page and calls the Ruby handlers, so the output emits before the
   log call returns. The payload is the formatted line and its
   `LogLevel`. One consequence differs: a Ruby `log://log` handler that
   logs to the same plugin recurses, where Tauri's would queue.

7. **The `log` command logs to the process's logger.** Tauri's command
   logs to `log::logger()`, the global logger the plugin's setup
   attached (decision 10), and so does Tokra's: `Commands.log` hands its
   record to `Log.logger`. With none attached, as after `skip_logger`,
   the record goes to a logger that drops it, the log crate's
   `NopLogger`. Arguments read as Tauri's types: `level` as serde_repr's
   `LogLevel` (`invalid value: 7, expected one of: 1, 2, 3, 4, 5`),
   `message` a `String`, `location` and `file` `Option<&str>`, `line`
   `Option<u32>`, `keyValues` `Option<HashMap<String, String>>`. A bad
   argument rejects with Tauri's `invalid args` message; the command
   resolves `null`.

8. **The Ruby-side API is the log macros, and Logger's shape.** Rust code
   logs with `log::info!`; Ruby code calls the process's logger,
   `Log.logger` (decision 10): `trace`, `debug`, `info`, `warn`, `error`,
   `fatal`, and `add` with Logger's arguments, so the logger can stand
   in for a Logger a library takes. Logger's
   `FATAL` and `UNKNOWN` log at `:error`, log's highest level. A
   record's target is the call's `progname`, or else the app's name, as
   a Rust record's target is its module path, which in an app starts
   with the app's crate. `Builder#progname`, `#datetime_format`,
   `Target#rotation_strategy`, `Target#timezone_strategy`, `Plugin#<<`,
   `Plugin#with_level`, `TracingLogger`, `WebviewLogger`, and the IO and
   Pathname target kinds go: each was Logger's API, not Tauri's, and the
   gem has not been released. `TargetKind::Dispatch` takes any Ruby
   Logger, Tauri's escape hatch for arbitrary targets.

9. **`level_for` and `with_colors` stay declined.** `level_for` filters by
   Rust module path, which Ruby records lack; `with_colors` needs fern's
   colors. Both raise `NotImplementedError` with the reason and the
   alternative. `level_for` moves from `Plugin` to `Builder`, where Tauri
   has it.

10. **One logger per process, as Tauri's.** Tauri's setup attaches the
    logger with `attach_logger`, the log crate's `set_boxed_logger` and
    `set_max_level`, and a second attach in one process fails with
    `SetLoggerError` ("attempted to set a logger after the logging
    system was already initialized"), which fails the second app's
    plugin. Ruby can hold one process-wide logger, so this is not a
    construct to translate away, and fidelity decides:
    `Log.attach_logger(max_level, log)` sets it once and raises
    `Log::SetLoggerError` after, `Log.logger` answers it, or a logger
    that drops every record before any attach, and `Log.max_level` the
    level recorded, `:off` before. They sit in `Tokra::Plugins::Log`
    beside the log crate's `Record`, `Metadata`, and `LogLevel`, which
    this plan already puts there, since the plugin crate re-exports log;
    a nested `Log::Log` would split one crate's names across two places.
    The object `acquire_logger` makes, Tauri's anonymous
    `Box<dyn log::Log>`, is `Log::Logger`; `Log::Dispatch`, after fern's
    type, would sit beside `TargetKind::Dispatch` and confuse. Managing
    the logger as app state instead, which would let two apps in one
    process each log, was weighed and refused: Tauri does not, and it
    changes behavior. With a global logger, `skip_logger` and `split`
    port as Tauri has them: `skip_logger` builds a plugin that attaches
    nothing, and `split(app_handle)` returns `[plugin, max_level,
    logger]` unattached, or raises `Error::LoggerNotInitialized` ("Internal
    logger disabled and cannot be acquired or attached") after
    `skip_logger`. `max_level` is fern's: the builder's level, or `Off`
    with no targets (fern `builders.rs:589-595`). The logger lives on the
    main Ractor, where the plugins run. The orchestrating session made
    this decision on 2026-11-20 from AGENTS.md's precedence, and the
    maintainer may overrule it. Inside `module Log` a bare `Logger` now
    names this class, the trap AGENTS.md records for `Process`, so
    RuboCop's `Lint/ConstantResolution` covers `Logger` too, and the
    plugin's code writes `::Logger` or `Log::Logger`.

    The tests cope with one logger per process as Tauri's documentation
    tells a test to: Tauri's log plugin has no tests of its own, and its
    `skip_logger` rustdoc says to call it when registering the plugin
    more than once, as tests do. The test helper attaches one forwarding
    `Log::Logger` subclass when the suite loads and points it at each
    test's own logger, made with `split`; every app a test registers the
    plugin on calls `skip_logger`, or expects the second attach to fail;
    and the README's app, whose setup attaches, runs in a process of its
    own. Nothing in `lib/` resets the logger.

11. **`build` returns a `TauriPlugin` whose setup acquires the logger.**
    Plan 064 left this here. `Log::Builder#build` takes no app, as
    Tauri's does, and returns a `Tokra::Plugin::TauriPlugin` named `log`
    with the `log` command and a setup that makes the `Logger` with the
    app handle and attaches it (`lib.rs:666-708`). The handle gives what
    Tauri's `acquire_logger` reads from it: `app_log_dir` from its path
    resolver for LogDir, `package_info.name` for file names and the
    target of a Ruby record, and the emitter for Webview. So
    `Builder#app_handle`, `#path_resolver`, and `#app_name` go, and with
    them the `ArgumentError` for a LogDir or Webview target without a
    handle. The setup reads the builder's settings as they were at
    `build`, as Tauri's `build` consumes the builder. A target that cannot
    be opened, or a second attach, raises from the setup, which the app
    reports as `Error::PluginInitialization`. The plugin's config type is
    `()`, so a non-null `plugins.log` fails the app, as plan 064 had
    `Log::Plugin#initialize_plugin` check by hand; a plugin from `split`
    has no setup and, as in Tauri, never reads its config.

12. **A logger closes its files on `drop`.** Rust closes a
    `RotatingFile`'s file when the logger holding it drops, which happens
    the moment nothing holds it; Ruby closes a `File` only when the
    collector finds it, and Windows refuses to delete or rename a file
    that is open, so the first landing of this plan failed CI's Windows
    job wherever a test removed a directory holding a log file. What
    Tauri closes, and when: the attached logger never, since
    `set_boxed_logger` leaks it, so its files close when the process
    ends; a logger `set_boxed_logger` refuses, at once, since the box
    drops; the outputs a failing `acquire_logger` built before the
    failure, at once; a logger from `split`, when the app lets it go; and
    the old file on rotation, before the rename, which the port already
    did. `Log::Logger#drop`, `RotatingFile#drop`, and a `drop` on each
    output port Rust's `Drop`, as `Tokra::Plugin#drop` does (plan 064,
    decision 6), and `Log.attach_logger` and the setup call it at the two
    points Tauri drops. A finalizer was weighed and refused, since it runs
    when the collector chooses, as `File`'s own does; closing on
    `RunEvent::Exit` was refused, since Tauri never closes the attached
    logger and the process's end closes it anyway. The tests drop each
    logger and file they make before their temporary directory goes, as
    Rust drops what leaves its scope. A Dispatch output leaves the app's
    own Logger open: Ruby's app keeps that object, where Rust's moved it
    into the plugin.

## Changes

1. `ferro-time` dependency; `TimezoneStrategy#get_now`.
2. The dispatch: `Record`, `Metadata`, `LogLevel`, formats, levels,
   filters, target kinds, outputs, `RotatingFile`, defaults.
3. The `log` command.
4. README, RDoc, RBS, and the CHANGELOG's tokra-log entry.
5. Registration (decisions 10 and 11): `Builder#build` and `#split` make
   a `TauriPlugin`, `#skip_logger`, `Log.attach_logger`, `Log.logger`,
   `Log.max_level`, `Log::Logger`, `Log::Commands`, `Log::Error`,
   `Log::SetLoggerError`, `Log::Logger#drop` (decision 12);
   `Builder#app_handle`, `#path_resolver`,
   `#app_name`, and `Log::Plugin` go. The package smoke builds the plugin
   and checks the packaged `api-iife.js`.
6. `examples/plugin_tour` registers tokra-log on the builder with Stdout
   and Webview targets, and its page logs with `window.__TAURI__.log`'s
   `info` and hears the lines with `attachLogger`.

## Verification

Each change is test-first in `plugins/log/test/`, through a real
`AppHandle` from Tokra's `StubNative` where the handle matters, a real
listener for `log://log`, and real files in a temporary directory, and
for registration a real `Tokra::App` with its window and loop replaced.
Each new behavior was reverted by hand, or by a script that applied
each mutation, ran the tests named for it, and restored the file, to
see its test fail. The suite and the tour ran on Linux under Xvfb; a
probe plugin, kept outside the repository, had the tour's page log one
line with `window.__TAURI__.log.info`, which came back through the
Webview target to `attachLogger` and reached the terminal. macOS and
Windows are CI's.

## Out of scope

Capabilities (`allow-log`). The `tracing` feature, which also emits
each page record as an event of Rust's tracing crate
(`commands.rs:37-38, 44-74`), has no Ruby counterpart to emit to.
