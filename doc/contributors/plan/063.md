# Plan 063: The path API

A Tauri app asks `app.path()` where its config, data, cache, and log
files belong, and its page asks the same through `@tauri-apps/api/path`.
Tokra's resolver answers one question, `app_log_dir`, and answers it
wrongly off macOS, and the page's `path` module rejects every call,
because no `path` core plugin exists. The store, window-state, and fs
plugins, and the log plugin's file targets, all start from these
directories.

The road-to-1.0 inventory names this C-42 and, for the page, J-10 (the
brief that started this plan said J-09, which is the `app` module). Its
claims were checked against the source below; where they were wrong,
this plan says so.

## Decisions

1. **The directories come from the dirs crate, through a collaborator
   shaped like it.** Tauri fidelity says the answers must be the dirs
   crate's. dirs 6.0.0 on macOS joins fixed names to the home directory;
   on Linux it reads `XDG_*` variables and `user-dirs.dirs`; on Windows
   it calls `SHGetKnownFolderPath` for each known folder. Three routes
   were weighed. (a) A Ferro gem, `ferro-dirs`, binding dirs 6.0.0 1:1,
   as the former ADR 011 (now ADR 020) had Ferro bind stateless standalone crates (its crate table, now in [native.md](../design/native.md),
   names dirs among them) and AGENTS.md says standalone crate bindings
   are moving to Ferro. (b) Fourteen more functions in Tokra's own
   `ext/tokra/src/path.rs`, which already binds `home_dir` and
   `data_local_dir`: it grows the extension that the former ADR 011 (now ADR 020) keeps for the
   windowing stack, and this work may not compile. (c) A Ruby port of
   dirs: macOS and Linux are environment and file logic Ruby can
   express, but Windows' known folders are not environment variables
   (Downloads has none, and a redirected Documents differs from
   `%USERPROFILE%\Documents`), so Ruby cannot give dirs' answers there
   without a native call, and Tokra would own a second copy of dirs to
   keep in step. So the faithful route is (a), which this work does not
   write. `PathResolver` takes a `dirs:` collaborator whose methods are
   the dirs crate's functions, each answering a String or `nil`, which
   is what a Ferro gem makes of `Option<PathBuf>` (the translation table, now in [native.md](../design/native.md)). Its
   default is `Tokra::Native`, which has `home_dir` and `data_local_dir`;
   a method that needs a function the collaborator lacks raises
   NotImplementedError naming the function, and the page's call rejects
   with that message. When `ferro-dirs` exists, the default becomes its
   module and nothing else changes. This is reported to the orchestrator
   as a decision.
2. **Rust's path rules, in Ruby, for both families.** Every command and
   every join here is `std::path`: `PathBuf::push`, `Components`,
   `parent`, `file_name`, `extension`, and on Windows the prefixes
   (`C:`, `\\server\share`, `\\?\`) and both separators. Ruby's `File`
   and `Pathname` differ (Ruby keeps `.` components and trailing
   separators, and on Windows writes `/`). `Path::Std` (`:nodoc:`) ports
   the 1.99.0 parser line by line, with one value for Unix and one for
   Windows, chosen by the app's `Utils::Platform::Target`, so the tests
   pin both on any host. dunce's `simplified` is ported beside it; it
   changes nothing off Windows.
3. **Ruby's methods return Pathname; the wire carries strings.**
   `PathBuf` is Rust's path type and Pathname Ruby's, and the existing
   `app_log_dir` already returned one, which the log plugin joins. The
   string inside each Pathname is the one Rust builds, separators and
   all.
4. **`PathResolver`, with `Resolver` kept.** Tauri's type is
   `tauri::path::PathResolver`, so Tokra's is `Tokra::Path::PathResolver`.
   `Tokra::Path::Resolver` stays as an alias, since the log plugin's RBS
   names it and the log plugin is another agent's area; it goes when the
   log plugin moves.
5. **The path plugin manages the resolver, and `Manager#path` reads
   it.** Tauri's `path` plugin's setup manages `PathResolver(app)`
   (`plugin.rs:236-249`), and `Manager::path` is that state
   (`lib.rs:771-774`), so every handle answers `path`. `AppHandle#path`,
   which built a private resolver of its own, goes. The plugin's Ruby
   constructor does what Tauri's setup does, at registration.
6. **The errors live with the path API.** `NoParent`, `NoExtension`,
   `NoBasename`, `CurrentDir`, and `UnknownPath` are `Tokra::Error`
   subclasses with Tauri's messages, defined in `lib/tokra/path/error.rb`
   because `lib/tokra/error.rb` is outside this work's area. Moving them
   there is a one-step refactor for whoever owns that file.
7. **`resource_dir` is deferred.** Tauri's derives from `current_exe`
   (tauri-utils `platform.rs:264-336`), which in Tokra is the Ruby
   interpreter. ADR 015 as it stood then, in the section now
   [packaging.md](../design/packaging.md) "What ships", says a packaged
   app's resource folder is `tokra-packaged/resources/`, "when it is
   ported"; no packaged context exists yet, and what development answers
   (the config folder is one candidate) is undecided. `#resource_dir`
   raises NotImplementedError saying so, and `BaseDirectory::Resource`
   rejects on the page. `resolve_path`'s `_root_` and `_up_` mapping is
   ported, so it is ready when the directory is. Reported as a decision.
8. **`temp_dir` is `std::env::temp_dir`.** On Unix, Rust answers
   `TMPDIR` when set, even empty, else on Apple platforms
   `confstr(_CS_DARWIN_USER_TEMP_DIR)`, else `/tmp`. Ruby's
   `Etc.systmpdir` makes the same `confstr` call on Darwin and answers
   `/tmp` elsewhere (ruby `ext/etc/etc.c:738-775`), so the Unix answer is
   exact. On Windows Rust calls `GetTempPath2W`; Ruby follows its
   documented order for a process that is not SYSTEM: `TMP`, `TEMP`,
   `USERPROFILE`, then the Windows directory, ending in a backslash.
   UNVERIFIED on Windows: a SYSTEM process (Rust answers
   `C:\Windows\SystemTemp`) and a relative variable (Windows makes it
   absolute) differ.
9. **The init script is Tauri's, rendered in Ruby.** `rake sync:tauri`
   vendors Tauri's scripts, but `tasks/sync.rake` is outside this work's
   area, so `Path::Plugin#initialization_script` holds `init.js` with its
   two values filled in as JSON, and a test renders the vendored
   `init.js` the same way and compares. Moving it into `sync:tauri` is a
   small follow-up.
10. **`u16` is read where it is needed.** serde reads `directory` as a
    `u16` before serde_repr matches it. `Ipc::CommandItem::INTEGERS` has
    no `u16`, and that file is outside this work's area, so
    `BaseDirectory.deserialize` checks the range itself with serde's
    words. Adding `"u16"` there is a one-line follow-up.
11. **Commands are functions of a platform.** Each command's body is a
    class method of `Path::Plugin` taking the `Std` value, as Tauri's are
    free functions, so the tests pin Unix and Windows answers on any
    host, and the invoke tests drive the plugin on the host's platform.
12. **`app_log_dir` off macOS was wrong.** Tokra answered
    `<local data>/logs/<identifier>`; Tauri's is
    `<local data>/<identifier>/logs` (`desktop.rs:285-288`). Fixed, with
    a CHANGELOG line. Tauri's `BaseDirectory::AppLog` rustdoc says
    `Config/{identifier}/logs` (`mod.rs:144-147`); the code says local
    data, and the code wins.
13. **`SafePathBuf.new` raises ArgumentError.** Rust returns
    `Err(&'static str)`, an error with no type; Ruby's error for a bad
    argument is ArgumentError, with Tauri's message.

- Windows behavior is ported from source and tested by its rules, not
  run on Windows here.
- Until `ferro-dirs` exists, most directories raise NotImplementedError,
  so store and window-state stay blocked.

## Results

`resource_dir` (decision 7) and the dirs functions Tokra's extension
does not bind (decision 1). What changed from the text above, and why:

- **The real-window test was not run.** `test/integration/path_plugin_test.rb`
  and its fixture are written; this work may not open windows.
- **No "Fixed" line for `app_log_dir`.** The resolver came after the last

  library, with no Ruby API to document.
