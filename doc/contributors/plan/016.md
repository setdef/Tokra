# Plan 016: Fix Forward the Audit of the Clipboard and `ipc://` Phases

An independent audit of commits 30b49bf, 39b764d, 0b9967c, and c03ac65 found
them faithful in shape but wrong in places that matter: an installed gem that
cannot load its own scripts, binary responses that cannot be sent, invokes that
never settle, a lifecycle event that never fires, and a native panic reachable
from the frontend. This plan records each finding as verified against the
pinned Tauri source (`vendor/tauri`, commit `9f0306fb`), the locked wry, tao,
arboard, and magnus sources, and Tauri's clipboard-manager plugin
(plugins-workspace `d4613ff0`), then states the fix.

No new gates are added here (mutation testing, install-from-gem CI, skills are
the next step). Every fix lands with a regression test written first that fails
without the fix.

## Bugs

### 1. The gem ships without its scripts, and neither native gem compiles once installed

**Verified.** `lib/tokra/js/` is gitignored, so `git ls-files` omits it, and the
gemspec adds back only `lib/tokra/js/*.erb`. `App#initialization_scripts` also
reads `process-ipc-message-fn.js` and, under `with_global_tauri`,
`bundle.global.js` through `Native.load_js_template`, so an installed gem raises
`LoadError` on the first `App#run`. The glob was also relative to the working
directory, not the gemspec, so loading the gemspec from elsewhere (Bundler
`path:` gems, the plugin Rakefiles) shipped nothing.

Checking the plugin gemspecs for the same class of problem (a file the
installed gem needs that the package lacks) found a worse one in both native
gems. Each crate manifest says `[lints] workspace = true`, and the tokra gem
ships the repository-root `Cargo.toml`, whose workspace names
`plugins/clipboard/ext/tokra_clipboard` as a member. In an installed tokra gem
that member is absent, so Cargo refuses the workspace; in an installed
tokra-clipboard gem there is no workspace root at all ("failed to find a
workspace root"). Both were reproduced by running `cargo metadata` against the
packaged manifest layout. tokra-log is pure Ruby and ships everything it loads.

**Fix.** Glob every file in `lib/tokra/js/` relative to `__dir__`. Move the
lint tables into each crate manifest (the workspace keeps only `members`), and
leave the root `Cargo.toml` out of the tokra gem. Building the gem also showed
it shipped all of `plugins/` (two other gems, including the clipboard crate
manifest) and the `vendor/tauri` gitlink; both are now excluded. Trimming the
rest of the development files from the package is left to the packaging gate. A test builds the gem with
`gem build` into a temporary directory and asserts that every script the app
loads (recorded by running a real `App` with `with_global_tauri`, plus
`emit.js.erb`) is in the package, that no packaged `Cargo.toml` inherits from a
workspace, and that the root workspace manifest is not shipped.

### 2. Binary response bodies cannot be served

**Verified.** `Proxy#respond` took the body as a Rust `String`. magnus converts
a Ruby string to `String` only when it is valid UTF-8 or 7-bit ASCII-8BIT
(`RString::to_string`, `test_as_str`), so a PNG or font raises `EncodingError`
while converting arguments, before the method body runs and before the
responder leaves the map. The request then hangs forever (see 3). Request
bodies had the mirror bug: `String::from_utf8_lossy` replaced every invalid
byte, corrupting binary uploads.

**The "File.read fixed the CSS" superstition.** Chat 004 concluded that
`File.binread` broke a stylesheet and `File.read` fixed it. That cannot be the
cause: the stylesheet is pure ASCII, and magnus accepts a 7-bit ASCII-8BIT
string exactly as it accepts a UTF-8 one, so both reads put identical bytes on
the wire. The fix was observed alongside other edits in the same session
(removing a debugging interception and reworking body collection), and the
encoding change took the credit. For any non-ASCII asset `File.read` is
actively wrong: it tags binary bytes as UTF-8, which is exactly the string
magnus rejects.

**Fix.** `Proxy#respond` takes the body as bytes (`RString#to_bytes`, so the
Ruby encoding is irrelevant); `Rack::Handler::Tokra` reads `to_path` bodies
with `File.binread`; request bodies cross into Ruby as ASCII-8BIT strings
holding the exact bytes, and the `ipc://` JSON path reinterprets them as UTF-8
before parsing. A test serves `test/fixtures/2x2.png` through the Rack path and
asserts the body is byte-identical and binary; `test/native/test_proxy.rb` calls
the real native `Proxy#respond` with the PNG and asserts it fails only for the
missing request id, not the encoding.

### 3. Invokes that never settle

**Verified.** The native event loop discarded every Ruby exception
(`let _ = callback.funcall(...)` in `event_loop.rs`), and `App` rescued only
`IpcProtocolError`. A handler that raised, or a resolved value that
`JSON.generate` cannot encode (invalid UTF-8, `NaN`), left the `ipc://` fetch
or the `postMessage` promise pending forever with nothing logged.

Tauri never loses a response: a value that fails to serialize becomes a
rejection carrying the serializer's message (`InvokeResponse::from`,
`ipc/mod.rs:265-276`), a rejection value that fails becomes its error string
(`InvokeError::from`, `ipc/mod.rs:240-247`), and `responder_eval` falls back to
formatting the error into the error callback (`ipc/protocol.rs:323-335`).

**Fix.** `Ipc::Invoke` serializes before calling the responder; a
`JSON::GeneratorError` turns the response into a rejection with the error's
message, as Tauri does. Responders now receive the JSON text, not a Ruby value.
`route_invoke` rescues `StandardError` from handlers, logs it to stderr, and
rejects the invoke with the exception message if it has not responded yet.
The `ipc://` command decoder no longer raises on a malformed path (Tauri
decodes it lossily, `ipc/protocol.rs:443-445`), so every parse failure is a
500. The native loop no longer discards exceptions: it prints the
exception's full message to stderr, and a `SystemExit` (from `AppHandle#exit`)
ends the loop with its status through `ControlFlow::ExitWithCode`.

### 4. `AppHandle#manage` is missing

**Verified.** `AppHandle` inherited `Manager#manage`, which raises
`NotImplementedError`, while `sig/tokra/app_handle.rbs` declared it, hiding the
gap from Steep. The clipboard plugin calls `app.manage(...)` at registration,
so it could only run against a test double.

**Fix.** `AppHandle#manage(state)` stores state in the app's `StateManager` and
returns `true` when stored, `false` when that class is already managed
(`Manager::manage`, `lib.rs:694-699`; `StateManager::set`, `state.rs:118-133`).
The clipboard test registers the plugin on a real handle built with
`Tokra::Builder.default.build(native: StubNative)`.

### 5. `RunEvent::Exit` never reaches plugins in a real run

**Verified.** tao's `EventLoop::run` returns `!` and calls `process::exit`, so
the `emit_run_event(RunEvent::Exit)` after `event_loop.run` ran only under the
stub loop. In Tauri, `RunEvent::Exit` comes from the runtime's handling of
`Event::LoopDestroyed` (`tauri-runtime-wry/src/lib.rs:4046-4047`, mapped in
`app.rs:1304-1305` and `2400`).

**Fix.** The native loop forwards `Event::LoopDestroyed` as
`Native::LoopDestroyedEvent`, and `App` emits `RunEvent::Exit` from it. The
stub loop delivers the injected event and then `LoopDestroyedEvent`, mirroring
the real order. The CHANGELOG now names the variants Tokra emits: `Ready`,
`WindowEvent` (close requested), and `Exit`.

### 6. An empty clipboard image panics the VM

**Verified.** arboard's macOS backend unwraps `CGImageCreate`, which returns
null for a zero width or height (`platform/osx.rs:73-87`). The byte-count check
let `width = 0` with empty bytes through, and the resulting panic surfaces as
Ruby's uncatchable `fatal`, reachable from `plugin:clipboard-manager|write_image`.

**Fix.** Reject `width == 0 || height == 0 || bytes.is_empty()` and any byte
count other than `width * height * 4` with arboard's `ConversionFailure`
message, inside the clipboard guard so a failed or cleaned-up clipboard reports
its own error first.

### 7. Clipboard payload errors hang the invoke

**Verified.** A missing `text` or `html`, or a negative width, raised
`TypeError` or `RangeError` in the native conversion, outside the plugin's
rescue list, so the invoke never settled. `JsImage` packed bytes with
`pack("C*")`, which wraps 256 to 0 and truncates 1.5 to 1.

Tauri deserializes command arguments before the command runs and rejects with
`invalid args `{key}` for command `{command}`: {serde message}`
(`error.rs:59-60`), where a missing key reads
`command {command} missing required key {key}` (`ipc/command.rs:97-102`) and a
wrong type reads serde_json's `invalid type: ..., expected ...`. `JsImage` is an
untagged enum of `PathBuf`, `Vec<u8>`, `u32`, and `{rgba: Vec<u8>, width: u32,
height: u32}` (`image/mod.rs:166-190`); anything else fails with serde's
`data did not match any variant of untagged enum JsImage`.

**Fix.** The clipboard plugin validates each argument and rejects with Tauri's
wording (`text` and `html` must be strings; `altText` may be absent or null).
`JsImage` accepts only what the untagged enum accepts (u8 byte arrays, u32
resource IDs and dimensions) and raises `ArgumentError` with serde's untagged
message otherwise; the plugin wraps that in the `invalid args` prefix.

### 8. The clipboard plugin hides a broken native extension

**Verified.** `rescue LoadError` around the native `require` turned a real
dlopen failure into a `NameError` at first use. **Fix.** Require it
unconditionally so the real message surfaces.

### 9. Exit cleanup must clean the managed clipboard

**Verified.** Tauri's `on_event` calls `_app.clipboard().cleanup()`, the managed
state (clipboard-manager `lib.rs:62-66`). Tokra cleaned the plugin's own
`@native`; a second plugin instance (whose `manage` returns `false`) would clean
a clipboard nothing uses and leave the managed one alive. **Fix.** Clean
`app.clipboard`, and read and write through it.

## Security

### 10. Reject invokes from origins that are not the app (stopgap)

**Verified.** Tauri decides local versus remote with `is_local_url`
(`webview/mod.rs:1680-1720`): the URL's scheme and domain must match the app's
protocol URL, which is `tauri://localhost` on macOS and Linux and
`http://tauri.localhost` on Windows (`manager/mod.rs:331-338`). Remote origins
then get only what capabilities grant, and a denied command rejects with
`Command {cmd} not allowed by ACL` in release builds (`webview/mod.rs:1826-1829`).
Tokra has no capabilities, so any page that loads in the webview (wry injects
the initialization scripts, key included, into every top-level document) could
invoke every command.

For Tokra the local origin is `tokra://localhost` on macOS and Linux. On
Windows, wry rewrites the navigation URL to `http://tokra.localhost/` (Tokra
does not enable `use_https`) and reverts only the request URI given to the
protocol handler (`webview2/mod.rs:514-521`, `1088-1092`), so the page origin
and the `Origin` header stay `http://tokra.localhost`.

**Fix (maintainer-approved).** Until capabilities land (TODO 001 #9), both
transports reject an invoke whose origin is not local, with Tauri's release
message. This is stricter than Tauri, which lets remote origins call app
commands when no app ACL manifest exists; the stopgap goes away when
capabilities do. `ipc://` also ports `Origin header is not a valid URL`
(`ipc/protocol.rs:491-499`) as a 500.

`postMessage` gets the same check. Tauri has origin data there: wry passes the
sending frame's URL as the request URI (`wry_web_view_delegate.rs:50-61`,
`webview2/mod.rs:890-905`, `webkitgtk/mod.rs:636-646`), and Tauri builds
`InvokeRequest.url` from it (`ipc/protocol.rs:302`). Tokra now forwards that URL
as `Native::IpcEvent#url`. Documented in ADR 010 and the `App` RDoc.

## Parity

### 11. The 10 KiB threshold counts characters, not bytes

**Verified.** `json.len()` is a byte length (`format_callback.rs:64,68`).
**Fix.** `bytesize`, with tests at exactly 10,240 and 10,241 bytes and a
multibyte payload whose character count is under the threshold but whose byte
count is over it.

### 12. Plugin initialization scripts are never injected

**Verified.** Tauri collects `Plugin::initialization_script` from every plugin,
wraps each as `(function () { SCRIPT })();` (`plugin.rs:918-933`), and appends
them after `init.js` and before the global API scripts (`manager/webview.rs:
124-128, 189-215`). **Fix.** `PluginStore#initialization_script` and `App`
inject them in that order. A test asserts the full list order.

Plugin global API scripts are **deferred**: Tauri builds that list at compile
time from each plugin crate's `global_api_script_path` (`tauri-codegen
context.rs:430`, `tauri-plugin build/mod.rs:64`), not from the `Plugin` trait,
and no Tokra plugin vendors a guest-js IIFE yet. The vendored core
`bundle.global.js` (Tauri's own entry in that list) is already appended last.

### 13. `plugin:a|b|c` routes command `b|c`

**Verified.** Tauri takes only the second `|` token (`webview/mod.rs:1793-1799`).
**Fix.** `split("|")[1]`.

### 14. Callback IDs are not strict u32

**Verified.** `Integer(v, 10)` accepts `" 12 "`, `"-5"`, `"1_0"`, and values
above `u32::MAX`; Rust's `u32::from_str` accepts only an optional `+` and ASCII
digits within range (`ipc/protocol.rs:501-520`, `CallbackFn(pub u32)` in
`ipc/mod.rs:586`). **Fix.** Match that grammar and range.

### 15. Content-type parameters and non-object payloads

**Verified.** Tauri parses the header as a `Mime` and compares with `==`, which
includes parameters (mime 0.3 `PartialEq`), so `application/json;
charset=utf-8` is `content type ... is not implemented`, and an unparseable
value is `unknown content type`. Tokra stripped parameters. **Fix.** Match
Tauri.

A non-object JSON payload stays a `serde_json::Value` in Tauri; Tokra keeps
mapping it to `{}`. **Documented deviation:** Ruby handlers index
`Invoke#payload` by string key, and `String#[]` on a non-Hash would silently
return a substring. Tauri's own key lookup on a non-object yields
`missing required key`, which is what `{}` produces, so commands behave the
same.

### 16. The `http://ipc.localhost/` branch is unreachable

**Verified.** wry's WebView2 handler reverts the workaround URI to
`ipc://localhost/...` before calling the protocol handler
(`webview2/mod.rs:1088-1092`). **Fix.** Remove the branch; correct ADR 010 and
Plan 015.

### 17. Undocumented deviations

**Documented in ADR 009 and 010:** `postMessage` responses always evaluate
`runCallback` (Tauri uses Channels for object and array results on non-macOS,
`ipc/protocol.rs:371-388`); a malformed `postMessage` is tolerated as
fire-and-forget or logged to stderr instead of Tauri's `console.error` eval
(`ipc/protocol.rs:422-430`); the event function and listener object names are
fixed instead of random (`listeners.rs`).

## Documentation

- RBS: comments removed from every touched signature file. The rule "no
  `initialize`, use `self.new`" cannot be applied to plain classes: Steep then
  checks each `def initialize` against `Object#initialize` and fails
  ("The method parameter is incompatible with the declaration `() -> void`").
  Those `initialize` signatures stay; only `Data` classes use `self.new`.

- CHANGELOG: drop the "Fixed" line for the per-page-load warning (introduced
  and fixed since the last tag); add `WebView.new_with_protocol`'s arity change,
  `Proxy#drop_response`, `AppHandle#manage`, the origin stopgap, and byte-exact
  bodies; state exactly which `RunEvent`s plugins receive.
- The clipboard gem has never been tagged or released, so its earlier API
  (`on_register`, argument-less `Plugin.new`, the occupied/unavailable error
  classes, `read_text` returning an empty string) never reached anyone. Its
  current contract is recorded where a user will meet it: the gem's README and
  an Added entry, rather than "breaking" lines against an unreleased draft.
- `App#invoke_key` RDoc: Tauri's key is public with a security warning
  (`app.rs:1040-1047`), not crate-private.
- ADR 002 and 008 link forward to 009 and 010. ADR 006 and TODO 001 use the
  renamed hooks; ADR 006 links point at pinned upstream commits.
- SPDX snippet on the clipboard Ruby plugin; corrected years on the Rust one;
  no `&mut self` in plugin RDoc; `window_created` and `webview_created` noted as
  not yet called; the clipboard main-thread deviation documented (Tauri runs
  its commands `async`, off the main thread; Tokra runs them on the main thread
  today, so the Linux deadlock warning applies to IPC reads too).

## Review follow-ups

An independent review of the first pass found these, fixed test-first:

- **Invokes could still hang.** `Invoke#respond` marked the invoke responded
  before serializing and rescued only JSON and encoding errors, so a value
  whose `to_json` raised escaped, and `route_invoke`'s fallback `reject` was a
  no-op. Serialization now rescues every `StandardError`, and the invoke counts
  as responded only once its JSON exists.
- **Non-finite floats resolve as `null`.** serde_json writes `NaN` and
  infinities as `null` (`ser.rs:157-174` at 1.0.145, the version Tauri's
  lockfile pins; `Value::from(f64)` is `Null`, `value/from.rs:59-61`), so Tauri
  resolves them. Tokra now does too, on both transports. Invalid UTF-8 is the
  only Ruby-only rejection: a Rust `String` cannot hold it.
- **`write_text` validates `label`.** Tauri desktop ignores the label but
  still deserializes it as `Option<String>`, so a non-string rejects with
  `invalid type: ..., expected a string` (serde's `String` visitor wording).
- **`JsImage` accepts the sequence form.** serde's derived struct visitor also
  reads `[rgba, width, height]` (exactly three elements, field order) for the
  `Rgba` variant, after `Bytes` fails. Accepting it is a few lines and
  faithful, so Tokra does, with the same u8 and u32 checks.
- **Rack bodies join as bytes**, so a UTF-8 chunk next to a binary chunk
  cannot raise `Encoding::CompatibilityError`.
- **Request bodies are tested byte-exact in Rust** through the factored
  `http_request_event` (`webview.rs`).

### Untested without a display

These native paths run only inside tao's event loop, which needs the main
thread and a window server and never returns (it calls `process::exit`), so no
headless test can drive them. A manual run should confirm each:

- `deliver` and `report_callback_error` (`event_loop.rs`): a Ruby exception
  raised while dispatching an event prints its full message to stderr and the
  loop keeps running.
- `SystemExit` maps to `ControlFlow::ExitWithCode(status)`: `AppHandle#exit(3)`
  ends the process with status 3.
- `Event::LoopDestroyed` reaches Ruby as `Native::LoopDestroyedEvent`, so
  plugins receive `RunEvent::Exit` on window close and on Ctrl-C.

The Ruby side of each (Exit emission order, handler rejection, logging) is
covered through `StubNative`.

- The tokra gem still ships development files such as `.gitmodules`.
