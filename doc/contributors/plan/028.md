# Plan 028: Raw window handles, and dialogs with a parent

Tauri's windows answer raw-window-handle's `HasWindowHandle` and
`HasDisplayHandle`, and the dialog plugin parents every dialog to the
calling window through them. Tokra's windows named no handle, so plan 023
shipped dialogs with none. ADR 013 settles where the windowing stack lives
and how a Ruby object answers for its handles; this plan implements it.

## Fidelity audit

| Behavior | Tauri | Tokra before | Verdict |
|---|---|---|---|
| `Window: HasWindowHandle` | dispatcher getter on the main thread (`window/mod.rs:943-949`, runtime-wry `lib.rs:2012-2018`) | none | port: `Window#window_handle` through `RuntimeContext#getter` |
| Getter failure | `HandleError::Unavailable` (`lib.rs:2016`) | none | port |
| Closed window | message matches no window, channel drops, `Unavailable` (`lib.rs:3244-3253`, `4293-4299`) | windows close only when the loop ends | port as the loop-ended case; decision 3 |
| `Window`, `App`, `AppHandle: HasDisplayHandle` | runtime handle reads the event loop's target on the calling thread (`lib.rs:2656-2660`) | none | port; read from the first window on the main thread, ADR 013 decision 3 |
| `WebviewWindow` impls | window's handle, app's display (`webview_window.rs:1410-1426`) | no `WebviewWindow` | nothing to port onto |
| Handle values | `RawWindowHandle` and `RawDisplayHandle` variants holding raw-window-handle structs | none | `Tokra::RawWindowHandle` `Data` classes for the eight structs tao answers with; decision 1 |
| `HandleError` | `NotSupported`, `Unavailable`, with Display text (`lib.rs:346-388`) | none | port: subclasses of `HandleError < StandardError`, messages verbatim |
| X11 display handle | new `XOpenDisplay` per call, never closed; null is UB in tao 0.34.5 | none | deviation: first answer kept for the process; ADR 013 decision 4 |
| Dialog `set_parent`/`parent` | kept only when both handles are `Ok`, else unchanged (`lib.rs:287-302`, `460-478`) | ferro-rfd values only; `nil` for none | port: also takes a `Tokra::Window`; `HandleError` means no parent |
| Command parents | open: Windows and macOS; save, message, ask, confirm: desktop (`commands.rs:129-132`, `229-232`, `281-284`) | none (plan 023, decision 3) | port; macOS and Wayland parentless, ADR 013 decision 6 |

## Decisions

1. **The values are `Data`, the variant is the struct.** One class per
   raw-window-handle struct that tao 0.34.5 answers with, with the crate's
   field names; pointers are addresses and IDs are numbers, all Integers.
   No Xcb (tao never answers it) and no mobile or web kinds. The native
   layer (`ext/tokra/src/raw_handle.rs`) returns a tagged Array, as
   ferro-rfd's native layer takes one, and `RawWindowHandle.window_handle`
   and `.display_handle` build the values or raise the named error.
2. **Threads follow ADR 012.** `Native::Window#raw_window_handle` and
   `#raw_display_handle` answer only the window's thread, like every other
   native method. `Window#window_handle` and `AppHandle#display_handle` go
   through `RuntimeContext#getter`, and `Error::Runtime` from it becomes
   `HandleError::Unavailable`.
3. **A closed window is a window whose loop ended.** Tokra has no window
   close of its own: a close request ends the loop. After the loop, a
   call from another thread raises `Unavailable`; a main-thread call in an
   exit hook still answers, since the window still exists.
4. **`AppHandle#display_handle` asks the first window.** Before `App#run`
   builds it, `Unavailable`. Recorded in the RDoc as a deviation.
5. **One X11 display.** A `OnceLock` holds the first Xlib answer's address
   and screen. Each display handle is then the same live connection.
6. **tokra-dialog copies what ferro-rfd binds.** (Superseded by plan 035:
   ferro-rfd 0.1.0.pre.3 reads handles by kind, so Tokra's values pass as
   they are, and binds AppKit by window number; only Wayland is still no
   parent.) `Desktop::WindowHandle.of`
   reads a parent's two handles, copies Win32, Windows, and Xlib values
   into ferro-rfd's classes, drops AppKit and Wayland (no parent), and
   passes ferro-rfd's own values through, so the builders still take a
   hand-made parent. Either handle raising `HandleError` or answering
   `nil` leaves the parent as it was.
7. **The commands pass `invoke.webview.window`,** read on the worker
   thread as Tauri reads it in its async command, so the handle getters
   wait for the main thread like the dialog's start does.

## Verification

- Unit (StubNative native window, real app, handle, and RuntimeContext):
  each tagged Array becomes its value or error with the crate's message;
  the getter from another thread; `Unavailable` after the loop and when
  the loop ends mid-getter; `display_handle` before any window, from the
  first window, through `Window` and `App`.
- Real windows (`window_handle_test.rb`), macOS, Linux under Xvfb, and
  Windows (the fixture loads no page): the kinds are the platform's; the
  fields that name the window are nonzero; a thread gets what the main
  thread gets; the handle leads to the window (AppKit's
  `-[NSView window]` title, Win32's `GetWindowTextW`, xdotool for the XID);
  on X11 every display handle is the same connection, whose display name
  Xlib reads through the pointer; after the loop, `Unavailable` with the
  crate's text.
- Native refusal: both getters raise `ThreadError` off the window's thread.
- Dialog (real ferro-rfd, read back through rfd's Debug): no parent from a
  window without handles; an earlier parent survives a failing one; X11
  and Win32 parents reach rfd on their platforms; AppKit and Wayland are
  no parent, alone or paired; the copies keep every field; a loop that
  ends during the parent read still settles the command.
- Linux real window: the fixture's bus has dbus-monitor on it and no
  portal, so rfd's FileChooser calls fail over to the fake zenity and are
  recorded: `SaveFile` names `x11:<the window's XID in hex>`, `OpenFile`
  names none.
- Manual mutation checks, in Results.
- `bundle exec rake` from a clean build.

## Untested here

- Windows: only CI runs it. `window_handle_test.rb` is the first real-window
  test there, since it is the first fixture without a page; a failure
  there may be `App#run` on Windows rather than the handles.
- Wayland: CI runs X11 only. The Wayland values are mapped and unit-tested;
  nothing follows them.
- A dialog that a parent keeps in front of its window on Windows is
  visible only to a person.

## Results

Every decision above is done. Deferred, with reasons: `WebviewWindow`
(Tokra has none) and AppKit and Wayland dialog parents (Ferro follow-ups,
ADR 013 Consequences).

- macOS 27 (Ruby 4.0.9): the real window answered `AppKitWindowHandle`
  and `AppKitDisplayHandle` on the main thread and from a thread, the
  `NSView` led to the window with the fixture's title, and a thread after
  the loop got `Unavailable` with the crate's text.
- Linux, in a Debian trixie container under Xvfb (arm64, Ruby 4.0.9, Rust
  1.99.1): every new and touched test passes with no skips that apply
  there: `XlibWindowHandle` whose XID xdotool names with the fixture's
  title, one display connection whose name Xlib reads as `$DISPLAY`, and
  the dialog window's `SaveFile` call naming `x11:<XID>` while `OpenFile`
  names none. Clippy passes there.
- Manual mutation checks, each reverted after:
  `Window#window_handle` without the getter fails
  `test_window_handle_from_another_thread_waits_for_the_main_thread` and 3
  real-window checks; dropping the `Error::Runtime` mapping fails the two
  loop-ending unit tests; tagging AppKit's window handle `Wayland` in
  `raw_handle.rs` fails `test_the_handles_are_this_platforms_kinds`;
  removing the X11 cache fails `test_an_x11_display_handle_is_one_live_connection`
  and one more real-window check (Linux); removing `WindowHandle.of`'s
  `HandleError` rescue errors 2 parent tests; dropping either AppKit and
  Wayland line in `WindowHandle.of` fails
  `test_each_handle_ferro_rfd_cannot_take_is_no_parent_whatever_its_pair`
  (it survived until that test was added: the other handle's line hid
  it); dropping `hinstance` from the Win32 copy fails
  `test_a_tokra_handle_becomes_ferro_rfds_value`; replacing the parent on
  failure fails `test_a_window_whose_handles_fail_keeps_the_earlier_parent`;
  parenting `open` on Linux, and not parenting `save`, each fail
  `test_on_x11_save_names_the_window_to_the_portal_and_open_does_not`
  (Linux); `OPEN_HAS_PARENT = false` fails
  `test_open_has_a_parent_on_windows_and_macos_only` (a review found it
  survived on macOS, where the AppKit parent drops anyway).
- `bundle exec rake` from a clean build on macOS: 590 core runs (5
  skips), 33 Rust tests, and every plugin suite (dialog 71 runs, 14 skips)
  pass; RuboCop, Steep, RBS validation and parity, RDoc (100%), REUSE,
  Clippy, fmt, and the packaging check pass, with no warnings.
- UNVERIFIED until CI runs: all of Windows, including
  `window_handle_test.rb`, the first real-window test there.
