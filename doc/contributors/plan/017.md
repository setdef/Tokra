# Plan 017: Turn Recurring Failure Modes into Gates and Skills

The audit behind [Plan 016](016.md) found the same kinds of mistake again
and again, each one past rules that already said not to make it. Tests
passed with the covered code deleted, or exercised only a stub. Installed
gems could not load their own scripts, and their crates could not compile
outside the repository. An RBS signature hid a method that existed only as
an inherited `NotImplementedError` (`AppHandle#manage`). Endless method
definitions broke RDoc. "Done" was claimed with plan items skipped, and
Tauri-derived code went unattributed.

Prose rules did not stop these. This plan turns the mechanical ones into
gates that fail `bundle exec rake`, and the judgment-heavy ones into agent
skills that carry the project's checklists into every session.

## 1. Packaging gate

### Problem

The working tree hides packaging bugs. A file `spec.files` forgets still
loads from the repository; a crate leaning on the repository's Cargo
workspace still compiles there. `test/test_gem_package.rb` (Plan 016)
asserted parts of this by inspecting a built gem, but nothing loaded or
compiled the package itself.

### Design

`tasks/package_check.rb` (`PackageCheck`) and `tasks/package.rake` check
tokra, tokra-clipboard, and tokra-log, in dependency order, in a temporary
directory outside the repository.

`rake package:check` (fast, in the default gate, about 12 seconds with
the extensions already compiled):

1. Builds each gem with `gem build`, then unpacks it.
2. Fails if the package holds a file outside the gem's packaged paths (a
   development file), or lacks a working-tree file under those paths. The
   working tree counts untracked files that git does not ignore, because
   `spec.files` comes from `git ls-files`, so a file someone forgot to add
   loads in development and vanishes from the gem.
3. Resolves each packaged crate with
   `cargo metadata --locked --offline --manifest-path` from the unpacked
   gem, and checks that the workspace root Cargo found is the gem's own.
   This catches a crate that inherits from a workspace the gem lacks (the
   `lints.workspace` bug) and a missing or stale lockfile, without the
   network.
4. Checks that the locked `rb-sys` crate satisfies the gemspec's `rb_sys`
   requirement. The crate and the gem ship fixes separately (the macOS 27
   install-name fix was in the gem's `mkmf.rb`; Ruby 4.1 support was in the
   crate's bindings), so a lockfile could otherwise pin a crate older than
   the gem the install uses. Both lockfiles now pin `rb-sys` 0.9.130,
   matching the bundled gem.
5. Copies the repository's compiled extension into the unpacked gem, then,
   in a fresh Ruby with no Bundler, no `RUBYLIB`, and an empty `GEM_HOME`,
   requires every packaged Ruby file and runs the gem's smoke script. Each
   run sees only its own gem's `lib` and those of the gems it declares, so
   an undeclared dependency between our gems fails to load.
   tokra's script builds an `App` with `with_global_tauri` and renders every
   initialization script, which reads each vendored template through
   `Native.load_js_template`, and calls into the native extension.
   tokra-clipboard's checks the native clipboard class and its methods;
   tokra-log's builds a logger configuration. Each run fails if any loaded
   feature came from the repository, if it activated a gem other than a
   default gem or a declared runtime dependency (transitively), or if it
   activated one of our gems from anywhere but the packages under test.
   `GEM_PATH` keeps Ruby's own gem directory, for `rb_sys` and bundled gems
   such as `logger`, which is why that last check exists. Files a gem reads
   without `require` (templates, assets) are covered only as far as its
   smoke script exercises them.

`rake package:install` (full, not in the default gate): builds each gem
and installs it with `gem install --local` into an empty `GEM_HOME`, so
RubyGems compiles every native extension from the packaged sources with
`cargo --locked`, then runs the same smoke scripts against the installed
gems, requiring that each gem under test was activated from its install
directory.

The tradeoff: a full install compiles tokra's crate and its wry and tao
dependency tree from scratch; `package:install` takes one to two minutes
for the three gems, which is too long for every commit. The fast mode
catches every packaging bug found so far: missing Ruby or JavaScript files
(step 2 and the smoke script), workspace inheritance and lockfile problems
(steps 3 and 4), and broken or undeclared requires (step 5). What only
the full mode catches is a crate that resolves but does not compile from
the packaged sources, which step 2 makes unlikely by proving the package
holds every source file the working tree does. Run the full mode before a
release and whenever a change touches a gemspec, a Cargo manifest, or an
`extconf.rb`.

`test/tasks/test_package_check.rb` drives `PackageCheck` on throwaway gems
in their own git repository, with the real gem, git, and cargo commands. A
complete package passes and runs its smoke script; a generated file the
gemspec adds passes; a declared gem may be activated and a declared sibling
gem loaded; a compiled extension is copied in; a crate that resolves alone
passes. Each of these fails: an untracked file, a development file, a
generated file the gemspec forgets, a require of a file the package lacks,
a failing smoke script, a smoke script that loads from the repository, an
undeclared gem, an undeclared sibling gem, a missing compiled extension, a
crate inheriting a workspace table that does not exist, and a locked
`rb-sys` outside the gem requirement. It replaces
`test/test_gem_package.rb`, whose assertions the gate now makes against the
real package.

Verified by hand: removing the `lib/tokra/js` glob from `tokra.gemspec`, an
untracked file in `lib/tokra/`, and `[lints] workspace = true` in the
clipboard crate each fail `package:check`.

### (a) Installed gems build against pinned dependencies

Plan 016 deferred this: an installed gem had no `Cargo.lock`, and magnus
was a git dependency on `branch = "main"`, so each install resolved
whatever was newest. Cargo reads a lockfile only at the workspace root, so
the lockfile a gem ships has to sit at the root of the workspace the gem
builds in. Three layouts were possible:

- Keep one repository workspace and generate a per-crate lockfile at gem
  build time. This is a generated, untracked file the gemspec adds by hand,
  the exact pattern that lost `lib/tokra/js` in Plan 016.
- Commit a second lockfile beside each crate and gate that it agrees with
  the workspace's. Two sources of truth that a check has to keep in sync.
- Make each gem with a native crate its own workspace, with its own
  committed `Cargo.lock`. The gem ships the same manifest and lockfile its
  tests ran against. This is the layout Bundler's Rust gem template uses.

The third is the only one with a single source of truth, so the root
`Cargo.toml` is now tokra's workspace (members `ext/tokra`, excluding
`plugins`), `plugins/clipboard/Cargo.toml` is tokra-clipboard's, and both
lockfiles are committed (`Cargo.lock` is no longer gitignored). Splitting
the lockfile changed no version. The cost is that the cargo tasks
(`rust:clippy`, `rust:fmt`, `rust:check`, `test:rust`) now run once per
workspace, through `CARGO_WORKSPACES` in `tasks/rust.rake`, and
`rust:no_allows` now scans the plugin crates too.

magnus stays a git dependency (only its unreleased 0.9 supports Ruby 4.0,
Plan 001) but is pinned with `rev` to the commit already locked,
`2370a352`, so the manifest alone names the code. Both `extconf.rb` files
pass `--locked` to Cargo through rb_sys's `extra_cargo_args`, so a build
whose lockfile does not match its manifest fails instead of resolving newer
versions. Tauri itself commits its lockfile; an installed native gem is an
application build, not a library, so it gets the same treatment.

The READMEs (`README.md`, `plugins/clipboard/README.rdoc`) now state what
an install needs: Rust 1.88 or newer for tokra and 1.85 for
tokra-clipboard (the highest `rust-version` among each lockfile's crates;
the version 4 lockfile itself needs Cargo 1.78), 1.99 on macOS 27, and that
setting `RB_SYS_EXTRA_CARGO_ARGS` replaces `--locked` (rb_sys assigns it
with `?=`).

### (b) Development files no longer ship

The tokra gem shipped every tracked file except a short deny list: plans,
chat transcripts, tasks, tool configuration, `.gitmodules`, and the empty
`exe/semantic-highlight` scaffold, which installed a useless executable.
Each gemspec now lists the paths it ships and asks `git ls-files` for only
those: tokra ships `lib sig ext/tokra Cargo.toml Cargo.lock README.rdoc
CHANGELOG.md LICENSE LICENSES` plus the vendored scripts; tokra-clipboard
ships `lib sig ext Cargo.toml Cargo.lock README.rdoc`; tokra-log ships
`lib sig README.rdoc`. A new top-level path now has to be added on purpose,
and `package:check` names any file outside the list. tokra's package went
from several hundred files to 99.

## 2. RBS and implementation parity

### Problem

Steep trusts `sig/`. A declared method with no implementation type-checks
at every call site and fails at run time; a public method with no
signature is invisible to Steep. Plugin signatures were not checked at all.

### Design

`tasks/rbs_parity.rb` (`RbsParity`) loads every file in the lib
directories, reads the signatures through `RBS::EnvironmentLoader` and
`RBS::Environment` (core and stdlib skipped, since only our declarations
matter), and compares them with Ruby reflection and Prism. `rake
rbs:parity` runs it over `sig`, `lib`, and every plugin's `sig` and `lib`,
after compiling the native extensions, as part of `lint:rbs`.

- **Declared means owned.** A method declared for class C must be defined
  with C as its owner (`instance_method(name).owner`). A method that only
  an ancestor provides is reported as "only inherited from Ancestor": a
  redeclaration an ancestor satisfies either duplicates the ancestor's
  signature or hides a stub. Deleting `AppHandle#manage` today fails the
  gate with that message.
- **No inherited stubs.** A declaration is not the only way to hide a stub:
  `include Manager` in `sig/tokra/window.rbs` gave Window every Manager
  method in Steep's eyes while Ruby gave it only Manager's
  `NotImplementedError` bodies. So every lib class is checked whether or
  not its signature mentions the method: a public method it inherits from
  a lib module or class, without overriding it, whose whole body (parsed
  with Prism) is `raise NotImplementedError`, is reported. Restoring the
  old Manager makes `App#manage`, `Window#manage`, and `Webview#manage`
  fail the gate.
- **Arguments match.** Each overload's positional and keyword arguments,
  read from the RBS function, must be ones the implementation accepts,
  read from `UnboundMethod#parameters`: no fewer required arguments, no
  unknown keywords, no rest arguments the method lacks. `self.new` on an
  ordinary class is checked against `initialize`, or against `new` when
  the class defines it (magnus classes, a custom `self.new`). On a `Data`
  class it is checked against the members: all of them positionally or all
  by keyword, unless the class overrides `initialize`.
- **Generated methods count as owned.** `Data.define` and `Struct.new`
  generate readers and `new` on an anonymous superclass, or on the class
  itself; those count. Their reflection helpers (`[]`, `members`,
  `inspect`) need no signature, since RBS's core `Data` and `Struct`
  signatures describe them. Declaring `initialize` on a `Data` class is
  reported even beside `self.new`, as AGENTS.md says ("declare `self.new`
  instead of `initialize`"); plain classes declare `initialize`.
- **Visibility matches.** Public and private must agree. RBS has no
  `protected`, so a protected method declared public passes. Ruby makes
  `initialize` and `respond_to_missing?` private on its own, and the lint
  knows it.
- **Interfaces count.** `include _Plugin` declares the interface's methods
  on the class.
- **Every public method has a signature.** A module is ours when
  `const_source_location` puts its constant in a lib directory, when a
  native extension defined it under `Tokra::Native` or
  `TokraClipboard::Native`, or when a lib file adds a method to it (a
  reopened class). Each of its public instance and singleton methods needs
  a signature. Private methods may go unsigned.

Exceptions use the existing `Lint` pattern: `allow "Tokra::Foo#bar", lint:
:rbs_parity, reason: ...` in `rbs_exceptions.rb`. `Lint#allow` now keys
named lints by name instead of `path:line`. There are none.

`test/tasks/test_rbs_parity.rb` covers each rule on a fixture library: a
redeclared inherited method, a class inheriting a stub with no
declaration, a missing method, class, and alias, an unsigned instance,
singleton, and alias method, visibility, `protected`, `module_function`
(`self?.`), an included interface, overloads with too many arguments, a
missing required argument, and an unknown keyword, `initialize` arity
behind a plain class, Data members, Data readers, `initialize` on a Data
class, `new` on a module and on a class without `initialize`, a reopened
class, a native namespace, and an allowed key. Reverting each rule fails
at least one test.

### What the first run found, and the fixes

- **Window, Webview, and App were Managers in name only.** `Manager`'s
  methods all raised `NotImplementedError`, so `Window#manage` and
  `Webview#state` raised, and so did nine methods on `App`, which also
  returned the window settings Hash from `config`. In Tauri the `Manager`
  trait's methods are provided: each reaches the shared `AppManager`, and
  an implementor (`App`, `AppHandle`, `Window`, `Webview`) defines only
  `resources_table` (lib.rs `Manager`; app.rs:683-701,
  window/mod.rs:987, webview/mod.rs:2256). `Manager` now does the same in
  Ruby: `config`, `manage`, `state`, `try_state`, `get_window`,
  `get_webview`, `windows`, and `webviews` go through `app_handle`, and
  only `app_handle` and `resources_table` stay abstract. `App` defines
  both (the app-level table, as Tauri's does), its `config` is now the
  app's `Config`, and `sig/tokra/app.rbs` includes `Manager`.
  `test/test_manager_delegation.rb` checks each Manager method on a real
  `App`, `Window`, and `Webview` from a run under `StubNative`.
  `Native::Window` and `Native::WebView` no longer include `Manager`: they
  hold no app handle, and the wrappers are the Managers.
- **`RunEvent::ExitRequested.new`** was declared with an optional `code`;
  the Data member is required, as Tauri's field is.
- **`Builder`'s internal readers** were public in `lib/` though `sig/`
  declared them private and every caller already used `__send__`. They are
  now private. Builder has not been released, so the CHANGELOG has no
  entry.
- **`FormatCallback.escape`** is `private_class_method`; its signature is
  now `private def self.escape`.
- **Native classes** declared `initialize`, but magnus defines `new`; they
  now declare `self.new`. `Native::Window#id`, `WakeUpEvent#payload`, and the
  `self.new` of every event `Data` class gained signatures, and the event
  classes say `< Data`.
- **`Image`** declared `initialize`; it now declares `self.new`, positional
  and keyword.
- **`Rack::Body`** was declared as a class that does not exist; it is now
  the interface `Rack::_Body`. The empty `Tokra::Rack` module declaration
  is gone.
- **tokra-log had no signatures.** `plugins/log/sig/tokra/plugins/log.rbs`
  now declares every method, and the gem ships it. `FilteringLogger#method_missing`
  was public; it is private, which Ruby's dispatch does not care about.

Plugin signatures are not checked by Steep (the Steepfile targets core
only). Until they are, `rake rbs:validate` (in `lint:rbs`) runs
`rbs validate` over core and plugin signatures, so a type name a plugin
signature gets wrong fails the gate, and `steep:no_untyped` now scans
plugin signatures too. Steep targets for the plugins are a follow-up.

## 3. No endless methods in RDoc'd files

RDoc mis-parses `def foo = bar`: the methods after it lose their comments
and visibility (`documentation_style.md`, section 5). The bundled RuboCop
(1.84) has `Style/EndlessMethod` with `EnforcedStyle: disallow`, so
`.rubocop.yml` enables it for every path RDoc reads: `lib`, `plugins/*/lib`,
`ext`, and `examples`. No new tool was needed. The cop autocorrects, so
the gate's `lint:fix` step rewrites an endless method before the `lint`
step checks; the rewrite then shows in the diff for review, and RuboCop
run on its own (or in CI without `lint:fix`) fails on it. Autocorrect
rewrote the 24 endless methods in the log plugin; the thirteen
`configured_*` readers kept their `:nodoc:` on the `def` line.
`.rubocop.yml` now also lints the `.agents` scripts.

## 4. Agent skills

### Location

The Agent Skills specification defines what a skill directory holds, not
where it lives. Its client guide names `<project>/.agents/skills/` as the
cross-client convention and `<project>/.<client>/skills/` as each client's
native place. Claude Code reads only `.claude/skills/`, and documents that
an entry there may be a symlink to a skill directory elsewhere. So the real
files live in `.agents/skills/<name>/`, where any compliant agent looks,
and `.claude/skills/<name>` is a relative symlink to `../../.agents/skills/<name>`.
Symlinking each skill rather than the whole `skills` directory follows the
form Claude Code documents. `test/skills/test_skills.rb` checks each
skill's frontmatter against the specification (name format and length,
name matching its directory, description length, body under 500 lines),
that every relative link resolves to a file inside the same skill, so
each skill stands alone, and that each symlink resolves.
`SKILL.md` files carry their SPDX tags in a comment after the frontmatter,
since the frontmatter has to come first.

### Skills

- **port-tauri-feature**: finding the authority (`vendor/tauri`, locked
  crates through `cargo metadata`, plugins-workspace in an ignored scratch
  directory), the plan shape, test-first work against real collaborators
  with a manual mutation check, attribution, deviations, and the finish.
  `references/parity-checklist.md` holds the checklist and
  `references/lessons.md` the mistakes from Plans 012 to 016 and ADRs 009
  and 010, each with the habit that prevents it.
- The audit-parity skill carries its own copy of the parity checklist
  rather than linking into another skill, so either skill works alone.
- **audit-parity**: scoping a diff, verifying it against the source, the
  failure modes this project has hit, a manual mutation check, the gates,
  and the report format the recent audits used: a verdict and a findings
  table (BUG, PARITY, TEST-GAP, DOC, NIT) with the change's `file:line`, the
  Tauri citation, and a fix, plus UNVERIFIED for anything not checked.
- **commit-session**: the definition of done, the clean-build gate, the
  transcript export, staging, and the commit message, never pushing.
  `scripts/export_transcript.rb` generalizes the exporter used for chats 019
  and 020: it finds the current Claude Code session from
  `CLAUDE_CODE_SESSION_ID` (or the newest transcript for the directory) or
  takes a path, and writes the next numbered chat with `--next`. It opens
  the output with `File.write(..., mode: "wx")`, so it never overwrites,
  and it never runs git: the copyright holder comes from `--copyright` or
  from `GIT_AUTHOR_NAME` and `GIT_AUTHOR_EMAIL`, and it stops with exit 2
  when neither is set. User input is the string content or text blocks of
  a user entry, minus Claude Code's harness messages (known tags such as
  `system-reminder` and `command-name`) and compaction summaries. It
  reproduces chats 019 and 020 byte for byte from their transcripts.
  `test/skills/test_export_transcript.rb` covers the format, array-form
  input, harness and summary filtering, the title, the holder from the
  environment with no `git` on `PATH`, a missing holder, `--next`,
  `--output` refusing to overwrite, session discovery, and a missing
  transcript.

Each skill points at AGENTS.md for facts only AGENTS.md states instead of
repeating them.

## Mutation testing: deferred

Automated mutation testing is deferred for Ruby and Rust alike. The
maintainer has ruled out the existing Ruby tool, and a Ruby mutation
library is planned as a separate project, so no mutation dependency is
added here.

When one exists, it plugs in as a `mutation:changed` task beside
`package:check`: it takes the Ruby and Rust files changed since `trunk`
(`git diff --name-only trunk...HEAD -- lib plugins/*/lib ext plugins/*/ext`),
mutates only the methods those diffs touch, runs the tests that load each
file, and fails on any surviving mutant not listed with a justification in
an exceptions file through the same `Lint` pattern. Scoping to changed code
keeps it fast enough for every commit.

Until then, both the port-tauri-feature and audit-parity skills ask for a
manual check: for each new or changed behavior, name the test that fails
if the line is deleted or a key constant or branch changes, and spot-check
a sample by reverting the line, running the test, and restoring it.

## Out of scope, and follow-ups

- Steep targets for the plugin signatures.
- A lint for comments in `.rbs` files (AGENTS.md forbids them; a few
  remain in `sig/`).
- The `rbs:parity` stub rule recognizes only a body that is exactly
  <tt>raise NotImplementedError</tt> (optionally with a message). It misses
  <tt>fail</tt>, <tt>NotImplementedError.new(...)</tt>, a
  <tt>::NotImplementedError</tt> path, a raise after other statements, and
  protected or singleton stubs. Every stub in the repository today uses the
  recognized form; widen the rule before adding stubs of another shape.
- The `rbs:parity` failure message should name the
  `allow "Klass#meth", lint: :rbs_parity` escape hatch.
- The two copies of the parity checklist (port-tauri-feature and
  audit-parity) are identical, but no test keeps them in sync.
- The transcript exporter recognizes harness messages only by their opening
  tag; a known tag block inside user text is exported as written.

## Verification

`rm -rf tmp plugins/clipboard/tmp`, delete the compiled bundles, then
`bundle exec rake`: zero errors and zero warnings. The default task now
ends with `package:check`; `lint:rbs` runs `rbs:validate` and
`rbs:parity`; RuboCop enforces `Style/EndlessMethod`. `rake package:install`
was run once by hand and passed in about a minute.
