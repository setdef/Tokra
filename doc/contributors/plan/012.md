# Plan 012: Phase 2.3 — Faithful Native Clipboard Layer, Plus Image Methods

Add `read_image`, `write_image`, and `write_html` to the clipboard gem's
native extension (`TokraClipboard::Native::Clipboard`), and repair the
existing methods where they deviate from Tauri's
`tauri-plugin-clipboard-manager/src/desktop.rs`. This executes the fourth
step of [Plan 009](009.md), revised after a fidelity audit; the Ruby-side
IPC handlers that consume these methods are Phase 2.4 (a separate plan).

## Context

Phase 2.2 (commit 37707c5) finished the resource infrastructure the image
commands need. Before adding image methods, the existing native layer was
audited line-by-line against `desktop.rs`. Plan 009 (authored earlier,
against less source context) baked one of the deviations into its Phase 2.3
spec ("read_image returns nil when clipboard has no image"); this plan
supersedes that instruction. AGENTS.md's precedence governs: Ruby the
language, then Tauri port fidelity, then Ruby the culture — "established
local convention" is not a tier.

## Fidelity Audit

| Behavior | Tauri (`desktop.rs`, `error.rs`) | Tokra today | Verdict |
|---|---|---|---|
| Empty clipboard on read | `get_text()?` / `get_image()?` propagate; frontend promise rejects with arboard's message | `read_text` returns nil | **Fix here** (D1) |
| Construction failure | Stored as `Result`; each call returns `Error::Clipboard(e.to_string())`; app still boots | `Clipboard.new` raises immediately | **Fix here** (D2) |
| Use after cleanup | `.as_mut().unwrap()` — panics | Raises RuntimeError "Clipboard has been cleaned up" | **Keep** — justified adaptation (D3) |
| `write_html` | Present: `set_html(html, alt_text)` | Missing | **Add here** (D6) |
| Error taxonomy | One variant: `Error::Clipboard(String)` — all arboard errors collapse to their message | `ClipboardOccupiedError`, `ClipboardUnavailableError` defined (and never raised) | **Defer to 2.4** — delete; see Out of Scope |
| `write_text` label param | `commands.rs` only; mobile-only, desktop ignores it | Absent | Correct as-is (desktop parity) |
| Main-thread deadlock warning (Linux) | Doc comment on `read_text`/`read_image` | Absent | **Port here** (D8) |

## Design Decisions

1. **All arboard errors propagate — no nil-on-empty.** `read_text` and
   `read_image` raise `RuntimeError` carrying arboard's exact Display
   message (empty clipboard: <tt>"The clipboard contents were not available
   in the requested format or the clipboard is empty."</tt>). Tauri's
   `Error::Clipboard` formats as `"{0}"`, so using arboard's message
   verbatim gives message parity for free. This is a breaking change to the
   gem's Phase 1 behavior; pre-1.0, zero users.

2. **Construction failure is stored, not raised.** Restructure the wrapper
   to `inner: Result<Mutex<Option<arboard::Clipboard>>, String>` — the
   `String` is the construction error's message, pre-formatted (guaranteed
   `Send + Sync`, so `frozen_shareable` is unaffected). `Clipboard.new`
   never raises; every method's match arm surfaces the stored message as a
   `RuntimeError` at call time, exactly as Tauri surfaces
   `Error::Clipboard(e.to_string())`. Consequence: a Tokra app on a
   clipboard-less system boots and errors per-call instead of crashing at
   plugin construction.

3. **Use-after-cleanup keeps the guard.** Tauri unwraps and panics;
   aborting the Ruby VM is not an acceptable translation of a Rust panic
   (tier 1: Ruby the language). Keep raising `RuntimeError` with
   "Clipboard has been cleaned up", and document the deviation in the
   rustdoc where the guard lives.

4. **Shapes: `[rgba, width, height]`.** `read_image` returns a 3-element
   array (binary String, Integer, Integer); `write_image` takes
   `(rgba, width, height)` positionally. Matches
   `Tokra::Native.image_from_bytes` and `Tokra::Image.new`'s field order,
   so Phase 2.4 can splat: `Image.new(*native.read_image)`.

5. **Byte-length validation, reluctantly.** The original decision was none
   (Tauri passes bytes straight to arboard). Implementation falsified it:
   arboard 3.6.1's macOS backend panics on a mismatch (unwrap on `None`,
   `platform/osx.rs:88`; fixed on arboard main) instead of returning
   `ConversionFailure`, and the panic aborts the Ruby VM — a Tauri app
   crashes identically here. Per the same tier-1 rule as D3, the native
   layer catches the mismatch and raises arboard's own `ConversionFailure`
   message, which is what the non-macOS backends report. Revisit when
   arboard releases the fix.

6. **Add `write_html(html, alt_text)`.** Completes the `desktop.rs` method
   surface in the phase that owns the native layer. arboard's `set_html` is
   not feature-gated. `alt_text` maps to `Option<String>` (magnus converts
   Ruby `nil` to `None`); callers pass `nil` explicitly at the native
   boundary — a Ruby-side default lands with the Phase 2.4 wrapper. This is
   a scope addition relative to Plan 009, per the fidelity directive.

7. **magnus gains the `bytes` feature** for safe binary access
   (`RString::to_bytes`) under the workspace's `unsafe_code = "deny"` lint,
   matching the core extension. No arboard change: `image-data` is in
   arboard 3.6's default feature set (verified in arboard's Cargo.toml).

8. **Port Tauri's behavioral caveats.** `desktop.rs` warns that `read_text`
   and `read_image` must not run on the main thread on Linux (the underlying
   libraries can deadlock when reading data this app copied). Carry that
   warning into the rustdoc now and the Ruby RDoc in Phase 2.4 — the
   documentation style guide classifies it as a behavioral contract.

## Changes

### 1. `plugins/clipboard/ext/tokra_clipboard/Cargo.toml`

```toml
magnus = { git = "https://github.com/matsadler/magnus", branch = "main", features = ["bytes"] }
```

### 2. `plugins/clipboard/ext/tokra_clipboard/src/lib.rs`

All inside the existing SPDX snippet block (everything adapts `desktop.rs`).

Restructure the wrapper and constructor (D2):

```rust
pub struct RbClipboard {
    inner: Result<Mutex<Option<arboard::Clipboard>>, String>,
}

fn new() -> Self {
    Self {
        inner: arboard::Clipboard::new()
            .map(|c| Mutex::new(Some(c)))
            .map_err(|e| e.to_string()),
    }
}
```

Each method matches on `&self.inner` first (construction error → raise its
stored message), then on the `Option` (cleaned up → raise the guard message),
then performs the operation, raising arboard's message on any error — no
`ContentNotAvailable` special case anywhere. A private helper can hold the
two guard arms so the five operations stay declarative.

Reworked and new operations:

```rust
fn read_text(&self) -> Result<String, Error>                              // drops Option
fn read_image(&self) -> Result<(RString, u32, u32), Error>                // get_image → (str_from_slice(&bytes), w, h)
fn write_image(&self, rgba: RString, width: u32, height: u32) -> Result<(), Error>
    // set_image(ImageData { width, height, bytes: Cow::Borrowed(&rgba.to_bytes()) })
fn write_html(&self, html: String, alt_text: Option<String>) -> Result<(), Error>
```

Registration additions in `init`:

```rust
clipboard_class.define_method("read_image", method!(RbClipboard::read_image, 0))?;
clipboard_class.define_method("write_image", method!(RbClipboard::write_image, 3))?;
clipboard_class.define_method("write_html", method!(RbClipboard::write_html, 2))?;
```

Rustdoc: cite `desktop.rs` line ranges per method; port the Linux
main-thread deadlock warning onto `read_text` and `read_image` (D8);
document the panic-vs-raise deviation on the cleanup guard (D3).

### 3. `plugins/clipboard/sig/tokra/plugins/clipboard.rbs`

`TokraClipboard::Native::Clipboard` becomes:

```rbs
def self.new: () -> Clipboard
def read_text: () -> String
def write_text: (String) -> void
def read_image: () -> [String, Integer, Integer]
def write_image: (String rgba, Integer width, Integer height) -> void
def write_html: (String html, String? alt_text) -> void
def clear: () -> void
def cleanup: () -> void
```

Plugin ripple: `Plugin#read_text` becomes `() -> String`.

### 4. `plugins/clipboard/lib/tokra/plugins/clipboard.rb` (ripples only)

- `Plugin#read_text` RDoc: drop "or +nil+ if empty"; state that an empty
  clipboard raises with arboard's message.
- Class-level JS API comment: drop "(returns string or null)".
- No code changes — the method delegates; full IPC rescue-to-reject and
  error-class mapping are Phase 2.4. No broken intermediate exists: the
  plugin is not yet registered with the Phase 2.2 `PluginStore` (it still
  matches full command strings), so nothing routes IPC to it until 2.4.

### 5. `plugins/clipboard/test/test_clipboard.rb`

Changed:
- `test_clear_empties_clipboard` — `assert_nil` becomes `assert_raises`
  matching arboard's empty-clipboard message.

New:
- `test_write_and_read_image_roundtrip` — write the 2x2 red/green/blue/white
  RGBA fixture bytes (same 16 bytes as core's `test/fixtures/2x2_rgba.bin`),
  read back, assert width 2, height 2, byte-exact RGBA.
- `test_read_image_raises_when_no_image` — `clear`, then `read_image` raises

  `test_write_image_rejects_after_cleanup`,

## Verification

1. `cd plugins/clipboard && bundle exec rake` — compiles and tests (its
   default task is `[:compile, :test]`).
2. `bundle exec rake` at the repo root — full gate, zero errors and zero
   warnings, including plugin test aggregation.
3. Manual smoke: round-trip the fixture in `bundle exec ruby -e`, print hex
   digests of written vs. read bytes; write_html then paste into a text
   field to observe the alt text.

No root CHANGELOG entry: the root CHANGELOG covers the `tokra` gem, and the
clipboard gem's Phase 1 set that precedent (its text operations are absent
from the Unreleased section). The behavioral break (`read_text` raising) is
recorded here and in the gem's RDoc.

## Out of Scope (Phase 2.4)

- Ruby `read_image`/`write_image`/`write_html` methods and IPC handlers on
  `Tokra::Plugins::Clipboard::Plugin`, with rescue-to-reject matching the
  core plugins, and JsImage resolution (rid vs. inline bytes) against
  `invoke.webview.resources_table`.
- Re-casing `extend_api` to bare command names and registering via
  `AppHandle#plugin`.
- Error hierarchy rework, sharpened by this audit: **delete**
  `ClipboardOccupiedError` and `ClipboardUnavailableError`. They are dead
  code (nothing raises them) with no Tauri counterpart — Tauri collapses
  every arboard error into `Error::Clipboard(String)`. The faithful shape
  is a single nested `Error::Clipboard` (chat 017's nesting convention)
  carrying the message.

## Risks

- **Pasteboard round-trip fidelity.** macOS re-encodes images through the
  system pasteboard, which can alter semi-transparent pixels (alpha
  premultiplication). The fixture is fully opaque primaries, which survive
  bit-exact. If exact equality still proves flaky, stop and surface it
  rather than weakening the assertion.
- **`write_html` alt-text flavor varies by platform.** If `read_text` after
  `write_html` doesn't return the alt text on some platform, adjust the test
  to assert per-platform reality and document the caveat — don't drop to a
  doesn't-crash test.
- **Clipboard tests mutate the developer's real clipboard.** Existing
  precedent from the text tests; noted, not mitigated.
- **magnus git dependency.** `to_bytes`/`str_from_slice` are the same APIs
  the core extension already uses; no new exposure beyond the existing pin.
