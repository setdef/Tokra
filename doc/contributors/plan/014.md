# Plan 014: IPC Response Wiring — invoke() Round-Trips to JavaScript

> [!NOTE]
> **Execution amendment.** Implementing this plan surfaced that `App` was
> reachable only by tests: every real app used `Rack::Handler::Tokra.run`,
> a second event loop with no Tauri analog, so IPC responses placed in
> `App` were unreachable. Per ADR 004 (Builder is porcelain over the
> Rack::Handler plumbing), the fix was to complete `Builder#app`/`#title`/
> `#size` and collapse `Rack::Handler::Tokra.run` onto the App path, rather
> than teach the fork the protocol. That unification was folded into this
> phase; the example round-trip (D7) is fulfilled through it. The final
> architecture is recorded in [ADR 009](../adr/009.md).

Close the responder gap: `App#dispatch_ipc` builds every `Invoke` with
`responder: nil`, so `resolve`/`reject` never reach the WebView and every
frontend `await invoke(...)` hangs forever. After this phase, a page using
`@tauri-apps/api` gets working promises: resolutions and rejections
delivered through Tauri's own callback protocol, guarded by Tauri's invoke
key.

Revision note: a maintainer-style review of the first draft falsified two
of its decisions (mismatch handling, key generation) and its injection
topology; this version pins every load-bearing fact to Tauri source.

## Context

All citations against `vendor/tauri` (pinned submodule).

1. **Wire message** (postMessage mode, `ipc/protocol.rs:234-242`): the
   frontend sends one JSON object —
   <tt>{cmd, callback, error, payload, options, \_\_TAURI_INVOKE_KEY\_\_}</tt> —
   where `callback`/`error` are u32 callback IDs and `payload` holds the
   command arguments. **Tokra currently treats the whole message as the
   payload**; that deviation must go (D3).
2. **Response delivery**: on macOS (and as universal fallback), Tauri
   evaluates <tt>window.\_\_TAURI_INTERNALS\_\_.runCallback(id, json)</tt>
   in the webview (`ipc/format_callback.rs:100-106`,
   `ipc/protocol.rs:323-335`). JSON objects/arrays over 10,240 bytes are
   wrapped in <tt>JSON.parse('...')</tt> with backslash-then-single-quote
   escaping (`serialize_js_with`, `format_callback.rs:45-79`).
3. **Invoke key**: generated once per app as 16 random bytes,
   z85-encoded (`lib.rs:1252-1256`), templated into the injected scripts,
   held by the app manager (`app.rs:1427`, `manager/mod.rs:775`). On
   mismatch, `Webview::on_message` prints
   <tt>\_\_TAURI_INVOKE_KEY\_\_ expected {expected} but received {received}</tt>
   to stderr and **silently drops the message** — no rejection reaches
   the frontend (`webview/mod.rs:1725-1745`).
4. **Injection topology** (`manager/webview.rs:160-192`) — four
   main-frame scripts, in order:
   1. A bootstrap that defines <tt>window.isTauri</tt> and creates the
      bare <tt>window.\_\_TAURI_INTERNALS\_\_</tt> object
      (inline Rust string, `manager/webview.rs:160-175`).
   2. `ipc-protocol.js` — the Builder's `invoke_initialization_script`
      (`app.rs:1430-1438`), templated with the raw
      `process-ipc-message-fn.js`, `os_name`,
      `fetch_channel_data_command`, and `invoke_key`. Defines
      <tt>\_\_TAURI_INTERNALS\_\_.postMessage</tt>.
   3. A metadata script defining
      <tt>\_\_TAURI_INTERNALS\_\_.metadata</tt> with the current
      window/webview labels (`manager/webview.rs:177-188`).
   4. `init.js` (`manager/webview.rs:343-398`), which wraps, in order:
      `freeze_prototype.js` (config-gated, off), `pattern.js`
      (pattern = brownfield), `ipc.js` (defines
      <tt>\_\_TAURI_INTERNALS\_\_.ipc</tt>, routing brownfield to
      `postMessage`), `core.js` (templated with `os_name`,
      `protocol_scheme`; defines `invoke`, `transformCallback`,
      `runCallback`, `convertFileSrc`), and the event-initialization
      script Tokra already extracts.
5. **Automatic transport degradation**: `ipc-protocol.js` first tries
   <tt>fetch('ipc://localhost/...')</tt>; when the custom protocol is
   unavailable — as in Tokra — it warns in the console once per page
   load, latches `customProtocolIpcFailed`, and permanently falls back to
   `window.ipc.postMessage`. Tauri's own scripts therefore work verbatim
   against Tokra's postMessage-only backend.

## Design Decisions

1. **Vendor Tauri's scripts via `sync:tauri`, verbatim.** Extend the
   extraction task to copy `init.js`, `pattern.js`, `ipc.js`,
   `ipc-protocol.js`, `process-ipc-message-fn.js`, and `core.js` into
   `lib/tokra/js/`. Because these scripts contain literal `%` risks and
   JS template literals, rendering uses ERB (marker conversion
   <tt>\_\_TEMPLATE_x\_\_</tt> → <tt><%= x %></tt>,
   <tt>\_\_RAW_x\_\_</tt> → <tt><%= x %></tt>), not `format`. Template
   values render as JS literals: strings JSON-encoded, raw scripts
   spliced. Values: `os_name` ("macos"/"linux"/"windows" from
   `RUBY_PLATFORM`), `protocol_scheme` "http", `pattern` "brownfield",
   `invoke_key` from the app, `fetch_channel_data_command` the constant
   <tt>plugin:\_\_TAURI_CHANNEL\_\_|fetch</tt> (`ipc/channel.rs`),
   `isolation_origin` empty string. The two inline Rust scripts
   (bootstrap, metadata) port as Ruby heredocs citing
   `manager/webview.rs:160-188`, with labels "main".

2. **`Tokra::Ipc` namespace, and `Invoke` migrates into it.** Tauri has
   `pub mod ipc` with no root re-export; `tauri::ipc::Invoke` is
   canonical, so `Tokra::Invoke` is misplaced by this project's own
   rules. This phase moves it: `lib/tokra/ipc/invoke.rb` defining
   `Tokra::Ipc::Invoke`, plus `Tokra::Ipc::FormatCallback` in
   `lib/tokra/ipc/format_callback.rb` porting `format_callback.rs`
   (`format`, `format_raw`, the 10 KiB `JSON.parse` heuristic, the
   escaping order). All references (core, sigs, tests, clipboard gem)
   update in the same commit; CHANGELOG records the break. The old
   `lib/tokra/invoke.rb` is deleted — **the `git ls-files`-based rake
   tasks will need the deletion staged; pause and ask** per AGENTS.md.

3. **`dispatch_ipc` speaks the real protocol.** Parse `callback`,
   `error`, and `payload` from the message; `Invoke#payload` becomes the
   message's `payload` member (breaking: it was the whole message). The
   responder evaluates `FormatCallback.format` against the calling
   webview: success → callback ID, failure → error ID. Messages without
   integer callback IDs get a nil responder (fire-and-forget), preserving
   today's hand-rolled-message tolerance.

4. **Invoke key: generate, inject, verify, drop.** `Tokra.generate_invoke_key`
   (module function mirroring `tauri::generate_invoke_key`,
   `lib.rs:1252-1256`) returns z85(16 random bytes); a small
   `Tokra::Z85.encode` ports the ZeroMQ spec (~15 lines, tested against
   the RFC "HelloWorld" vector). The key lives on `AppManager` (new
   member, mirroring `manager/mod.rs`), is exposed via `App#invoke_key`
   (public where Tauri's is crate-private — Ruby has no crate privacy;
   documented as internal), rendered into the scripts, and verified in
   `dispatch_ipc`: on mismatch, warn to stderr with Tauri's exact message
   and drop the message without responding (Context 3).

5. **Assembly lives in the Ruby host, not Native.** Script rendering and
   ordering happen in `App`'s build/webview-creation path, mirroring
   Tauri's split (Builder renders `ipc-protocol.js`; the webview manager
   assembles `init.js`). `Native` stays dumb pipes:
   `Native::WebView.new_with_protocol(window, proxy, scripts)` gains an
   `Array[String]` parameter feeding wry's
   `with_initialization_script` per entry (breaking internal signature;
   `StubNative` records the scripts). Pre-existing smell, out of scope:
   `Native.emit_js_script` already does rendering in Native; migrate it
   when the events phase touches it.

6. **Existing raw-message tests migrate loudly.** Every test injecting
   `{"cmd":...}` messages gains the key via `app.invoke_key` (drop
   semantics would otherwise fail them silently — no dispatch, no
   error). One new test asserts the drop: mismatched key → no plugin
   dispatch, no eval, stderr message matching Tauri's text.

7. **Accepted deviation, documented:** on macOS, real Tauri serves
   `ipc://` as the primary transport; Tokra's fallback costs one failed
   fetch and one console warning per page load until the `ipc://`
   protocol lands (a named follow-up phase, not an "optimization").
   `verify_ping_pong` switches to
   <tt>window.\_\_TAURI_INTERNALS\_\_.invoke(...)</tt> and renders the
   resolved value — the first true round-trip through a real webview.

8. **The synchronous responder is interim, by design.** ADR 001's target
   architecture routes commands Main Ractor → Worker Ractor → proxy →
   main-thread eval; today's dispatch (and this phase) runs handlers
   synchronously on the Main Ractor, so the responder evals directly.
   That is the diagram's final step without its middle. The responder
   stays an opaque callable on `Invoke` so the Worker-Ractor phase can
   swap its implementation for a proxy round-trip without touching
   handlers — and nothing in this phase may hand the webview-capturing
   responder to another Ractor. The ported Linux warnings ("do not read
   the clipboard on the main thread") are the standing motivation for
   that phase.

9. **ADR 009 documents the transport decision.** This phase outgrows
   ADR 008's letter ("extracts Tauri's JavaScript format strings"):
   whole vendored scripts, injected initialization scripts, an invoke
   key, and postMessage-first transport are a new architectural layer.
   Ship `doc/contributors/adr/009.md` recording it — script vendoring
   strategy, key semantics (drop-and-log), the accepted `ipc://`
   deviation and its follow-up, and the interim synchronous responder —
   cross-referenced from ADR 008, following the precedent of commit
   c29c4c5 (ADRs cross-referenced when 007/008 landed).

## Changes

1. **`tasks/sync.rake`** — copy the six scripts with SPDX snippet
   headers; abort when a source file is missing; regenerate
   `lib/tokra/js/`.
2. **`ext/tokra/src/webview.rs`** — initialization-scripts parameter on
   the protocol constructor (D5).
3. **`lib/tokra/ipc/invoke.rb`**, **`lib/tokra/ipc/format_callback.rb`**,
   **`lib/tokra/z85.rb`** + sigs (D2, D4); delete `lib/tokra/invoke.rb`
   (staged by user).
4. **`lib/tokra/app.rb`** — key on `AppManager`; script assembly +
   injection at webview creation; `dispatch_ipc` per D3/D4/D6.
5. **Tests** — Z85 RFC vector; FormatCallback exact-output tests
   (literal path, `JSON.parse` path, quote/backslash escaping);
   StubNative round-trips (resolution evals `runCallback(callback, rid)`
   for `plugin:image|new`; rejection evals
   `runCallback(error, "The resource id ... is invalid.")`); key
   mismatch drop; migrated raw-message tests.
6. **`CHANGELOG.md`** — Added: invoke responses reach the frontend;
   injected `__TAURI_INTERNALS__` scripts; `Tokra.generate_invoke_key`.
   Changed (breaking): `Tokra::Invoke` → `Tokra::Ipc::Invoke`;
   `Invoke#payload` is the message's `payload` member;
   `Native::WebView.new_with_protocol` signature.
7. **`examples/verify_ping_pong`** — D7.
8. **`doc/contributors/adr/009.md`** — D9, with a cross-reference added
   to ADR 008.

## Verification

1. `bundle exec rake` at root — zero errors, zero warnings.
2. FormatCallback and Z85 outputs byte-compared against expected strings
   (Z85: RFC 32/Z85 "HelloWorld" vector).
3. StubNative integration round-trips per Changes 5.
4. Manual: run `examples/verify_ping_pong`, click an `invoke`-based
   ping, observe the resolved pong rendered in-page and the one-time
   custom-protocol console warning (expected, documented).

## Out of Scope

- The `ipc://` custom-protocol transport — Tauri's primary on desktop;
  named follow-up (see D7 for the accepted interim cost).
- Channels (`ipc/channel.rs`) and the
  <tt>plugin:\_\_TAURI_CHANNEL\_\_|fetch</tt> command — templated as a
  constant so scripts render; unimplemented until the events phase.
- Isolation pattern, CSP, `freeze_prototype` (config-gated off),
  `withGlobalTauri` (`bundle.global.js`) — candidates for the phase that
  proves `@tauri-apps/api` end-to-end.
- `Invoke` headers/`options` member beyond `customProtocolIpcBlocked`
  passthrough.

## Risks

- **Script drift** with the submodule pin; mitigated by `sync:tauri`
  aborting on pattern mismatch.
- **File deletion mid-session** (`lib/tokra/invoke.rb`) breaks
  `git ls-files`-based rake tasks until staged; the implementation stops
  and asks for staging at that point rather than working around it.
- **`process-ipc-message-fn.js` ArrayBuffer side-channel** is unused by
  Tokra's JSON path; harmless until channels land.
- **Breaking `Invoke` rename + payload shape**: all in-repo consumers
  update in the same commit; zero external users.
