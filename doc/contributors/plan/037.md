# Plan 037: raw bytes and the fetch path through Channel

Plan 025 ported Tauri's `ipc::Channel` but evaluated every message, and
sent JSON only. Plan 033 gave the IPC raw bodies both ways and named what
was left: a raw `Channel` message, and Tauri's channel-data fetch command,
which carries large messages. This plan ports both, and with them the
`postMessage` invoke results Tauri sends over a Channel off macOS, which
ADR 009 and ADR 010 list as deviations only because Tokra's Channel could
not carry them.

Sources: Tauri core at `vendor/tauri` (`9f0306fbc`):
`crates/tauri/src/ipc/channel.rs` (all of it, cited by line below),
`ipc/protocol.rs:197-241` (`RequestOptions`), `:327-420` (the
`postMessage` responder and `can_use_channel_for_response`),
`ipc/mod.rs:106-205` (`InvokeResponseBody`, `IpcResponse`, `Response`),
`ipc/format_callback.rs:83-106`, `app.rs:1460-1475` and `:2260-2261`
(the managed queue and the channel plugin), `webview/mod.rs:1790-1806`
(the ACL exemption), `scripts/ipc-protocol.js:16-28`, and
`packages/api/src/core.ts` (`class Channel`), whose built form Tokra
already vendors unchanged.

## How Tauri sends a Channel message

`Channel::send` turns its value into an `InvokeResponseBody`: JSON text for
any `Serialize` value, and the body of a `Response`, which may be raw
bytes (`ipc/mod.rs:181-198`, `channel.rs:291-297`). A channel from the
page then picks one of three paths by size (`channel.rs:153-182`):

- JSON shorter than 8192 bytes evaluates
  `runCallback(ID, { message: JSON, index: N })`.
- Raw bytes shorter than 1024 evaluate
  `runCallback(ID, { message: new Uint8Array([..]).buffer, index: N })`.
- Anything else is stored in the app's `ChannelDataIpcQueue` under an id
  from a process-wide `u32` counter, and the page is told to fetch it:
  `__TAURI_INTERNALS__.invoke('plugin:__TAURI_CHANNEL__|fetch', null,
  { headers: { 'Tauri-Channel-Id': 'DATA_ID' } })`, whose answer it hands
  to `runCallback` with the same `{ message, index }` shape.

The `fetch` command (`channel.rs:318-337`) reads the header, parses it as
a `u32`, removes the data from the queue, and answers with
`Response::new(data)`: raw bytes come back as `application/octet-stream`,
an `ArrayBuffer` in the page, and JSON as `application/json`. A missing or
unreadable header rejects with `missing channel id header`, an id the
queue does not hold with `data not found`. The page's `Channel` orders
messages by index and holds the end message until every earlier one has
arrived, so a fetched message that lands after the end is still
delivered.

Nothing removes queued data but the fetch. Data whose fetch never runs,
because the page reloaded or the script failed, stays in the queue for the
life of the app; dropping a channel does not touch it.

`Channel::from_callback_fn` (`channel.rs:244-284`) is the same three paths
without the index, for invoke results: `postMessage` off macOS sends a
JSON object or array result, and a raw result, over it unless the command
is the fetch command itself or the client reports
`customProtocolIpcBlocked` (`ipc/protocol.rs:337-407`).

## Fidelity audit

| Behavior | Tauri | Tokra before | Verdict |
|---|---|---|---|
| `send` of a `Response` with raw bytes | raw body (`ipc/mod.rs:194-198`) | JSON only | port |
| `send` of any other value | `serde_json::to_string` (`ipc/mod.rs:181-187`) | same | already matched |
| Small JSON inline | `< 8192` bytes (`channel.rs:37`, `155-162`) | always inline | port the threshold |
| Small raw inline | `< 1024` bytes as `new Uint8Array(ARRAY).buffer` (`channel.rs:39`, `163-166`) | none | port |
| Larger messages | queued under a counter id, fetch script evaluated (`channel.rs:167-181`) | evaluated inline | port |
| Data id counter | process-wide `AtomicU32`, wrapping (`channel.rs:42`, `169`) | none | port |
| Queue | app state, `Arc<Mutex<HashMap<u32, InvokeResponseBody>>>`, managed at build (`channel.rs:44-46`, `app.rs:2260`) | none | port |
| `fetch` command | `plugin:__TAURI_CHANNEL__|fetch`, header `Tauri-Channel-Id`, `missing channel id header`, `data not found` (`channel.rs:31-33`, `318-346`) | not routed | port |
| `fetch` and the ACL | exempt (`webview/mod.rs:1802-1806`) | origin stopgap rejects foreign origins | exempt it from the stopgap |
| End message | `{ end: true, index: N }` after the last message, page holds it until earlier ones land (`channel.rs:186-193`, `core.ts`) | same, inline only | already matched |
| Send after drop | impossible in Rust (`channel.rs:80-86`) | no-op (Plan 025 review) | already matched |
| Unfetched data after drop or reload | stays queued | n/a | port as is |
| `postMessage` object, array, or raw result off macOS | over `from_callback_fn` unless fetch or `customProtocolIpcBlocked` (`ipc/protocol.rs:337-407`) | always evaluated (ADR 009 §5, ADR 010 §7) | port |
| `customProtocolIpcBlocked` | `bool`, default `false` (`ipc/protocol.rs:223-231`) | ignored | read it; a non-bool is still ignored (ADR 009) |

## Decisions

1. **A Channel carries an InvokeResponseBody, as Plan 033 spells one.**
   `Channel#send(Ipc::Response.new(bytes))` sends the response's body;
   any other value is serialized as before. The message handler, the
   block of `Channel.new` included, receives the body String: binary for
   raw bytes, UTF-8 JSON text otherwise (Plan 033 decision 1). Sending a
   binary String without a Response serializes it, as `Invoke#resolve`
   does, so there is one way to say "bytes".
2. **Thresholds and names are Tauri's.** `MAX_JSON_DIRECT_EXECUTE_THRESHOLD`
   (8192), `MAX_RAW_DIRECT_EXECUTE_THRESHOLD` (1024), and
   `CHANNEL_ID_HEADER_NAME` are private constants of `Channel`, as they are
   private in `channel.rs`; `FETCH_CHANNEL_DATA_COMMAND` moves from `App`
   to `Channel`, where Tauri defines it. Sizes are byte lengths, as Rust's
   `len()` is.
3. **`Tokra::Ipc::ChannelDataIpcQueue`** holds the queue: `insert` and
   `remove` under one mutex, the two `HashMap` calls Tauri makes. `App`
   manages one at build, as `App::build` does, so every handle's
   `state(ChannelDataIpcQueue)` finds it. Data ids come from a
   process-wide counter that wraps at 2^32, as `fetch_add` on an
   `AtomicU32` does.
4. **`Tokra::Ipc::Channel::Plugin`** is Tauri's `channel::plugin()`: the
   core plugin `__TAURI_CHANNEL__`, registered at build beside the
   resources and image plugins, answering `fetch`. It reads the
   `tauri-channel-id` header (Tokra stores header names lowercased, Plan
   033 decision 3), takes it only if `to_str` would (visible ASCII) and it
   parses as a `u32` (an optional `+`, then digits), and resolves
   `Response.new(data)`.
5. **The fetch command skips the local-origin stopgap**, as Tauri skips
   its ACL check for it. The stopgap stands in for the ACL (ADR 010 §6),
   and Tauri's exemption is part of the ACL's behavior. Data ids are
   sequential and process-wide, so any frame that reaches the IPC can
   fetch queued data meant for another channel, which then never arrives
   where it was sent; Tauri has the same exposure.
6. **`Channel.from_callback_fn`** ports the result path, and the
   `postMessage` responder uses it off macOS for a successful object,
   array, or raw result unless the command is the fetch command or the
   message's `options.customProtocolIpcBlocked` is `true`. Errors still
   evaluate. The real client sets that flag on every `postMessage` it
   sends after `ipc://` failed, so on desktop only a hand-rolled
   `postMessage` takes the Channel path; it now gets an `ArrayBuffer` for
   bytes, as Tauri gives it. This retires the deviation in ADR 009 §5
   and ADR 010 §7.
7. **Ordering stays under the channel's lock.** `send` runs the handler
   inside the lock that `drop` takes, so the index of a fetched message is
   taken, its data stored, and its fetch script queued before the end
   message is. The page reorders by index; Tokra does not wait for the
   fetch.
8. **Unfetched data is not cleaned up**, as in Tauri. A page that reloads
   before its fetch scripts run leaves that data queued until the app
   exits. Cleaning it up would need a hook Tauri does not have, and would
   change what a late fetch answers.

## Verification

- Unit (`test/ipc/test_channel.rb`): each threshold at its edge for both
  kinds, the fetch script verbatim, the queue's contents, data ids that
  increase across channels and wrap, the end message after a fetched
  message, `Channel.new` receiving raw bodies, `from_callback_fn`'s three
  paths, and the `fetch` command's answer and two errors (through
  `App`'s router, over both transports).
- Unit (`test/builder/test_ipc_response.rb`): the `postMessage` result
  path on macOS, on Linux, for the fetch command, and with
  `customProtocolIpcBlocked`.
- Real window (`ipc_transport` fixture): a command sends a large JSON
  message, a small one, a small raw message, and a large raw one through
  the page's Channel, then drops it; the page receives all four in order
  with the right bytes, through two `ipc://` fetches. After the fixture
  makes `ipc://` fail, the same stream arrives over `postMessage`, the
  fetched raw message as a number array, as Tauri's client gets it.
- Mutations, each reverted after: listed in Results.

## Results

Every decision is done. The real-window stream passes on macOS: the
page receives all four messages in order, 9000 characters of JSON and
1 MiB of bytes through two `ipc://` fetches, and after the fallback the
same four over `postMessage`, the fetched bytes as a number array. Linux
and Windows run it in CI. Twelve hand mutations each failed a test:
the JSON threshold at 8193 (two threshold tests), the raw threshold at
1025 (three), `remove` keeping the data (`data not found` and the queue
test), the data counter without its wrap, the fetch command without its
stopgap exemption, ignoring `customProtocolIpcBlocked`, never taking the
Channel path, `send` serializing a Response (five), a header id without
its `+`; and in the real window, fetched JSON answered as bytes, every
fetched message at index 0, and the plugin unregistered.

## Out of scope

- Tauri's channel interceptor (`channel.rs:147-151`), still unported
  (Plan 025).
- `Channel.new`'s id counter does not wrap at 2^32 as Tauri's does; no
  app makes four billion channels.
- Mobile's channel registry (`channel.rs:234-238`).

## Risks

- A page that never fetches leaks memory, exactly as Tauri's does
  (decision 8).
- A producer that keeps sending large messages (JSON of 8 KiB or more,
  bytes of 1 KiB or more) to a Channel whose webview has closed while
  the app runs queues data nobody will fetch. `send` returns +nil+, so
  the producer cannot notice. Tauri leaks the same way.
- Tests that assert a `postMessage` result script now depend on the
  platform; they stub `os_name` so each runs the same everywhere.
