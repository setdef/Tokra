# Plan 032: invoke bodies parse as serde_json parses them

Tauri reads every invoke with serde_json before it routes the command. An
`ipc://` body with `Content-Type: application/json` goes through
`serde_json::from_slice::<serde_json::Value>`, and an error becomes a 500
`text/plain` reply whose body is serde_json's message
(`crates/tauri/src/ipc/protocol.rs:525-538`, `143-151`). A `postMessage`
goes through `serde_json::from_str::<Message>`, and an error is evaluated
in the webview as `console.error("JSON error: ...")`
(`ipc/protocol.rs:287-291`, `422-430`; `error.rs:50-51`). Either way no
command runs.

Tokra parsed both with Ruby's JSON. Ruby's JSON accepts bytes serde_json
rejects: invalid UTF-8 inside a string and a lone trailing surrogate
escape (`"\udc00"`) both become a String with an invalid byte sequence,
which reached a plugin and failed there with Ruby's
`invalid byte sequence in UTF-8`. Review found it through ferro-time and
ferro-url argument readers.

Sources: Tauri at `vendor/tauri` `9f0306fb`; serde_json 1.0.145 (Tauri's
`Cargo.lock:7613-7615`) with the `raw_value` feature Tauri enables
(`crates/tauri/Cargo.toml:45`), and serde_core 1.0.228, both read from
Cargo's registry copy.

## Fidelity audit

| Behavior | serde_json / Tauri | Tokra before | Verdict |
|---|---|---|---|
| Invalid UTF-8 in a string | `invalid unicode code point` (`read.rs:868-870`) | accepted, broken String | fixed |
| Invalid UTF-8 outside a string | `expected value` | rejected, Ruby's words | fixed (message) |
| Lone trailing surrogate `\udc00` | `lone leading surrogate in hex escape` (`read.rs:910-914`) | accepted, broken String | fixed |
| Lone leading surrogate `\ud800` | `unexpected end of hex escape` (`read.rs:921-944`) | rejected, Ruby's words | fixed (message) |
| `/* */` and `//` comments | `expected value` | accepted | fixed |
| `1e400` | `number out of range` (`de.rs:637-675`) | `Infinity` | fixed |
| Integer beyond u64 / below i64 | f64 from the first digits (`de.rs:714-735`) | Integer | fixed |
| `-0` | `-0.0` (`de.rs:509-528`) | `0` | fixed |
| Float rounding | significand times or over a power of ten, without float_roundtrip (`de.rs:637-675`) | correctly rounded | fixed |
| Nesting | 127 levels, then `recursion limit exceeded` (`de.rs:63`, `1370-1385`) | 100 levels | fixed |
| Duplicate keys | last wins | last wins | already matched |
| Object key order | byte order, a BTreeMap without preserve_order (`map.rs:22-26`) | arrival order | fixed |
| NaN, Infinity, trailing commas, raw control characters, BOM | rejected | rejected, Ruby's words | fixed (message) |
| First key `$serde_json::private::RawValue` | its string is parsed as JSON (`value/de.rs:131-135`, `raw.rs:433-466`) | ordinary key | fixed |
| Error text | `<reason> at line L column C`, column in bytes (`error.rs:405-417`, `read.rs:421-430`) | Ruby's messages | fixed |
| `postMessage` failure report | `console.error("JSON error: ...")` in the webview (`ipc/protocol.rs:422-430`) | stderr `failed to parse IPC message: ...` | fixed |
| `postMessage` `cmd` not a string | `invalid type: ..., expected a string at line L column C`, before the key check (`ipc/protocol.rs:233-242`, `287-291`) | passed through | fixed, without the position |

## Decisions

1. **Port serde_json's parser to Ruby** as `Tokra::Ipc::Json`, step for
   step from `de.rs`, `read.rs`, `error.rs`, `value/de.rs`, and `raw.rs`,
   so acceptance, values, and messages all match. It is the one route the
   ADRs leave open. Prefiltering Ruby's JSON cannot recover serde_json's
   messages or its rounding. Ferro skips crates that duplicate the
   standard library or a popular gem and names `serde_json` as one
   (ADR 011 §1). `tokra`'s native crate does not link serde_json (the root
   `Cargo.lock` has none) and stays a thin binding over tao and wry, with
   the logic in Ruby (ADR 001, 005). Ruby integers do not overflow, so
   serde_json's saturating exponent sum and `wrapping_abs` are not
   ported; every exponent past the POW10 table takes the same path either
   way.
2. **Both transports use it.** `parse_ipc_payload` and `dispatch_ipc`
   call `Ipc::Json.parse`. A failure is a 500 with the message over
   `ipc://`. Over `postMessage` the webview evaluates
   `console.error(<message>)`, the message `JSON error: ...` written as
   serde_json writes a string value, which `JSON.generate` matches for a
   String; nothing goes to stderr, as nothing does in Tauri. The ADR 009
   deviation note is amended to say so.
3. **Values are serde_json's.** Handlers see what a Tauri command's
   `serde_json::Value` would hold, including byte-ordered keys. Ruby
   handlers index payloads by key, so the order changes nothing for them;
   it shows only when a command echoes an object back.
4. **A `cmd` that is present but not a string fails as Tauri's does.**
   Tauri's `Message` needs a string `cmd` (`ipc/protocol.rs:233-242`), and
   serde reads the message before `on_message` checks the invoke key, so
   the page gets `JSON error: invalid type: <value>, expected a string`
   (worded by `Ipc::Unexpected`) before the key check. serde adds the line
   and column; a parsed Value no longer knows them, so Tokra leaves them
   out. A missing `cmd` stays the empty command (ADR 009).
5. **`Tokra::Ipc::Json` is internal** (`:nodoc:`). Plugins receive
   parsed payloads and have no need to parse JSON this way.

## Deviations

- `postMessage` messages are parsed as a `Value`, not as Tauri's
  `Message` struct. serde_json skips a struct's unknown fields without
  checking their strings or number ranges (`de.rs:1100-1281`), so Tauri
  accepts a lone surrogate or `1e400` inside an unknown field and Tokra
  rejects it. The shape stays lenient as ADR 009 records: a non-object
  message is logged to stderr, a missing `cmd` is the empty command, and
  a message without integer callback ids is fire-and-forget. The RDoc of
  `App#dispatch_ipc` and ADR 009 record this.
- serde_json's `float_roundtrip`, `arbitrary_precision`, and
  `preserve_order` features change these answers. Tauri does not enable
  them; an app's own Cargo features could. Tokra follows the features
  Tauri asks for.

## Changes

- `lib/tokra/ipc/json.rb`, `sig/tokra/ipc/json.rbs`: the port.
- `lib/tokra/app.rb`: both transports parse with it; `postMessage`
  failures are `console.error`'d in the webview.
- ADR 009: a dated amendment to the `postMessage` deviation.
- Tests: `test/ipc/test_json.rb` (each error, value, and branch);
  `test/builder/test_ipc_protocol.rb` and `test_ipc_response.rb`
  (rejection before dispatch on each transport, serde_json values, the
  non-string `cmd`); the `ipc_transport` real-window fixture (the real
  client's `invoke` with a lone surrogate rejects with serde_json's
  message, and a `postMessage` of one reaches the page's `console.error`
  before the key check, as Tauri orders them).
- CHANGELOG: folded into the Unreleased `ipc://` transport entry, since no
  tagged release had Ruby IPC.

## Verification

An oracle crate in scratch built serde_json 1.0.145 with `raw_value`
and printed, for each input, the value (numbers typed, floats as bits,
keys in map order) or the error's Display. A fuzzer fed both the oracle
and the port valid JSON, random strings with every escape and bad byte,
random numbers up to 30 digits with exponents up to 12 digits, nesting,
the raw-value token, and byte-level mutations of all of these. Five seeds
of 20,101 inputs each (about 6,600 accepted per seed) gave no mismatch
in acceptance, value, or message. Ruby's JSON on the first seed accepted
944 inputs serde_json rejects, rejected 2 it accepts, and gave different
values for 312.

Every expectation in `test/ipc/test_json.rb` was also checked by running
the test file with `Ipc::Json.parse` replaced by the oracle. 29 hand
mutations of the port (limits, positions, surrogate checks, overflow,
exponent overflow sign, decimal overflow exponent, raw value trailing
characters, trailing commas, rounding, whitespace, key order, `E`) each
failed a test. An independent review fuzzed 115,000 more inputs with no
mismatch. Reverting `app.rb` to Ruby's JSON fails the transport tests and the
real-window check.

## Risks

The port is pure Ruby. The review measured typical invokes under 5 KB at
0.01 to 1.4 ms. Token-dense bodies are slow: a 700 KB array of 200,000
small integers takes about 250 ms without YJIT and 85 ms with it, where
Ruby's JSON takes 3 ms, and a `Uint8Array` nested in an invoke's
arguments travels as a JSON number array, so about 1 MB of bytes takes
about a second without YJIT. Long strings stay fast because a regex
finds their end.

The ways out, in order:

1. Raw `application/octet-stream` bodies (Plan 015), so a top-level
   binary argument skips JSON entirely, as it does in Tauri.
2. Hot-path work in Ruby, each step fuzzed against the oracle; this
   gains 1.5 to 3 times, not the 80 times between the port and C.
3. A new ADR amending ADR 011, if native serde_json is ever needed. At
   this boundary serde_json is arguably part of Tauri's own internals
   rather than a duplicate of Ruby's JSON.

## Out of scope

- Raw `application/octet-stream` bodies (Plan 015).
- Tauri's strict `Message` struct over `postMessage` (ADR 009).
