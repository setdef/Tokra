# Plan 026: one argument reader, and a dedicated InvalidArgs

Plans 021, 023, 024, and 025 each taught a plugin to read its command
arguments the way Tauri's serde deserialization does, so the frontend
receives Tauri's words when it sends the wrong thing. Each plugin grew its
own reader, and plan 025 added a core one, `Tokra::Ipc::CommandItem`, with
`Tokra::Ipc::Unexpected` for serde_json's value descriptions. This plan
clears the follow-ups those plans left: dialog's reader reports the wrong
field and describes some values differently from serde_json, and every
plugin rescues any `ArgumentError` as an argument rejection, so a genuine
bug's `ArgumentError` becomes a rejection that looks like the frontend's
fault.

Sources: Tauri core at `vendor/tauri` (`9f0306fbc`):
`crates/tauri/src/error.rs:58-60` (`Error::InvalidArgs`),
`ipc/command.rs:60-145` (`CommandArg`, `CommandItem`'s deserializer and
`deserialize_option`), `ipc/channel.rs:300-316` (Channel's `CommandArg`,
whose bad value is a bare `InvokeError`), `ipc/mod.rs` (`InvokeError`).
Plugins at plugins-workspace `d4613ff0`, the commit plans 021 to 025 ported:
`plugins/dialog/src/commands.rs:28-87`, `plugins/dialog/src/lib.rs:47-61`,
`plugins/dialog/src/models.rs`, `plugins/clipboard-manager/src/commands.rs`.
The locked serde 1.0.228, serde_derive 1.0.228, and serde_json 1.0.140 from
that workspace's `Cargo.lock`.

## Follow-ups this plan takes

- Plan 024, review item 6: a shared InvalidArgs reader in core, which also
  fixes dialog's key order.
- Plan 025: move dialog's reader onto `CommandItem` and `Unexpected`.
- Plan 024, review item 6 (rescue): plugins rescue any `ArgumentError`.

## Decisions

1. **`Tokra::Error::InvalidArgs` is Tauri's `Error::InvalidArgs`.** Tauri
   wraps every serde failure of an argument in
   `crate::Error::InvalidArgs(command, key, serde_json::Error)`, whose
   Display is <tt>invalid args `key` for command `name`: ...</tt>. Tokra's
   errors nest under `Tokra::Error` as Tauri's enum variants do, so the
   class is `Tokra::Error::InvalidArgs.new(command, key, reason)`, with
   readers for the command and the key. `CommandItem` raises it where it
   raised `ArgumentError`. It is not an `ArgumentError`: a plugin rescues
   exactly the argument failures, and an `ArgumentError` from a bug
   reaches the router, which logs it and rejects (`App#route_invoke`).

2. **`Tokra::Ipc::InvokeError` is Tauri's `InvokeError`.** Channel's
   `CommandArg` returns a bare `InvokeError` for a string that is not
   `__CHANNEL__:ID`, not an `InvalidArgs` (`channel.rs:307-313`). Tokra had
   no such class and raised `ArgumentError`. `Channel.from_command` now
   raises `Tokra::Ipc::InvokeError` with the same message; a plugin rescues
   it with `InvalidArgs`. `JavaScriptChannelId.from_str` keeps raising
   `ArgumentError`, as a Ruby parser does, for Rust's `Err(&str)`.

3. **`CommandItem` reads any argument.** Tauri's `CommandItem` is a serde
   `Deserializer` for one key: the key's value, or the missing-key error,
   and for an `Option` a missing key is `None` (`command.rs:97-145`). Its
   blanket `CommandArg` wraps the failure in `InvalidArgs`. `CommandItem`
   gains `deserialize { |value| ... }` and `deserialize_option { |value|
   ... }`, which yield the value and wrap a `CommandItem::Mismatch`, now
   public and serde_json's `Error` in this role, in `InvalidArgs`;
   `Mismatch.invalid_type(value, expected)` builds serde's
   <tt>invalid type</tt> message. `string` and `strings` stay. This is the
   shape every plugin shares, so it moves to core.

4. **Value readers stay in their plugins.** serde_derive's struct visitor
   appears in dialog and notification, but with different field tables and
   only two users; notification's ISO 8601 dates, URL checks, and integer
   ranges, dialog's enums, and clipboard's borrowed strings are each one
   plugin's. Each plugin keeps those and raises `CommandItem::Mismatch`
   through `CommandItem#deserialize`. Duplication over the wrong
   abstraction: a shared struct reader waits for a third user.

5. **Dialog reads as serde_json does.** Four messages change, each to
   what Tauri sends, test-first against an oracle built from the locked
   serde and serde_json (as plan 024's was):
   - An options object is read in its keys' byte order, since serde_json
     without `preserve_order` stores objects in a BTreeMap, so of two bad
     fields the message names the one first in that order.
   - Values are described by `Unexpected`: floats as ryu prints them
     (`1e16`, not Ruby's `1.0e+16`), integers past `u64` as floats, and
     strings with every character Rust's Debug escapes escaped, not only
     ASCII controls.
   - An options array is read as serde_derive reads a struct from a
     sequence, field by field in declaration order, where dialog rejected
     it as the wrong type.
   - An unknown variant of a two-variant enum (`fileAccessMode`) lists the
     two as serde's `OneOf` does, <tt>`copy` or `scoped`</tt>, not
     <tt>one of `copy`, `scoped`</tt> (de/mod.rs:2337-2355). The fuzzed
     oracle found this one.

6. **Clipboard describes values through `Unexpected`.** Its own
   description printed floats as Ruby does and integers past `u64` as
   integers; it now calls `Unexpected`, test-first.

7. **Plugins rescue only argument errors.** Each plugin's `extend_api`
   rescues `Tokra::Error::InvalidArgs` (and global-shortcut
   `Tokra::Ipc::InvokeError`) in place of `ArgumentError`, beside the
   errors its commands return. Clipboard's `write_image` still turns
   `JsImage`'s `ArgumentError` into an `InvalidArgs` for `image`, around
   that one call, since `JsImage` reports serde's untagged-enum mismatch as
   an `ArgumentError` (Follow-ups).

## Steps

Behavior-preserving steps run the existing suites unchanged; behavior
changes start with a failing test.

1. Core: `InvalidArgs`, `InvokeError`, and `CommandItem` raising them
   (test-first: the tests name the classes).
2. Core: `CommandItem#deserialize`, `#deserialize_option`, and
   `Mismatch.invalid_type` (test-first for the new methods; `string` and
   `strings` keep their messages).
3. Notification onto `CommandItem` (refactor), then its rescue narrowed
   (test-first: an `ArgumentError` from a bug reaches the router).
4. Global-shortcut's rescue narrowed (test-first likewise).
5. Clipboard onto `CommandItem` (refactor), onto `Unexpected`
   (test-first), and its rescue narrowed (test-first).
6. Dialog onto `CommandItem` (refactor), onto `Unexpected`, key order,
   and sequences (each test-first), and its rescue narrowed (test-first).
7. Plans 024 and 025 mark their follow-ups (plan 023 has none; plan 024
   recorded its key order); CHANGELOG.

## Verification

- The oracle: a scratch crate with dialog's argument types from
  `commands.rs`, `lib.rs`, and `models.rs`, deserialized with the locked
  serde and serde_json, compared with the plugin's messages on chosen and
  fuzzed inputs.
- Manual mutation checks of each behavior change, listed in Results.
- `bundle exec rake` from a clean build.

## Results

Every decision above is done.

- The oracle: a scratch crate compiled dialog's argument types
  (`OpenDialogOptions`, `SaveDialogOptions`, `DialogFilter`, `PickerMode`,
  `FileAccessMode`, `MessageDialogKind`, `MessageDialogButtons`) with the
  locked serde 1.0.228 and serde_json 1.0.140, and deserialized each input
  from a `&Value`, as `CommandItem` does. The plugin matched it on 17,600
  fuzzed inputs over four seeds (open and save options as objects and
  arrays, buttons, kinds, and strings), after the `OneOf` fix the first run
  found. The new tests embed its answers, and clipboard's new cases are its
  answers for `&str` and `Option<String>`.
- Behavior-preserving steps: notification's reader onto `CommandItem`
  (its 442 assertions unchanged but the error class); dialog's and
  clipboard's onto `CommandItem` before their message changes.
- Manual mutation checks, each reverted after: `CommandItem` raising
  `ArgumentError` fails 4 core tests; `Channel.from_command` raising
  `ArgumentError` for a bad channel string fails
  `test_from_command_rejects_what_tauri_rejects`; `deserialize_option`
  yielding null fails `test_deserialize_option_reads_a_missing_key_or_null_as_nil`;
  `Mismatch.invalid_type` inspecting the value fails
  `test_deserialize_yields_the_value_and_wraps_a_mismatch`; rescuing
  `ArgumentError` again in global-shortcut, notification, clipboard, or
  dialog fails that plugin's
  `test_an_argument_error_from_a_bug_is_not_taken_for_a_bad_argument`;
  dropping `InvokeError` from global-shortcut's rescue errors
  `test_bad_arguments_reject_with_tauris_messages`; clipboard printing
  floats as Ruby does fails 3 `test_invalid_args_*` cases, and not wrapping
  `JsImage`'s mismatch errors 3 image tests; dialog reading keys in sent
  order fails `test_an_object_is_read_in_key_order`; rejecting arrays,
  giving an `Option` without a serde default a default in a sequence, or
  skipping the leftover check each fails `test_options_may_be_a_sequence`;
  writing `one of` for two variants fails
  `test_each_open_option_checks_its_type`; and printing floats as Ruby
  does fails `test_values_are_described_as_serde_json_describes_them`.
- `bundle exec rake` from a clean build: see below.

## Follow-ups

- Done in plan 027: `JsImage#into_img` reported serde's untagged-enum
  mismatch as an `ArgumentError`, so clipboard converted that one call's
  `ArgumentError` into `InvalidArgs`, and the core `image` plugin rescued
  any `ArgumentError`. `JsImage.deserialize` now reads the argument apart
  from `into_img`'s resolution, as Tauri's are, and both rescue narrowly.
- A shared serde_derive struct reader, once a third plugin needs one
  (decision 4).

## Out of scope

- Raw (bytes) invoke payloads and their `CommandItem` message
  (`command.rs:93-96`), which ADR 010 leaves out.
