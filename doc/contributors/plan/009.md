# Plan 009: Clipboard Image Operations (Phase 2)

Port clipboard image functionality with full Tauri JavaScript API parity.

---

## Overview

This plan spans **5 sub-phases**, each suitable for a separate conversation with fresh context. Each phase builds on the previous.

**Dependency Chain:**
```
Phase 2.0: Webview Wrapper ─┐
Phase 2.1: ResourceTable ───┼──► Phase 2.2: Core Plugins ──► Phase 2.3: Rust ──► Phase 2.4: Clipboard
Phase 2.1: ImageResource ───┘
```

## Phase 2.0: Webview Wrapper Class

### Objective

Implement a `Tokra::Webview` wrapper class that holds a native webview reference plus its own `ResourceTable`. Required because clipboard `read_image`/`write_image` use `webview.resources_table()`.

### Research Questions

1. **How does Tauri's Webview struct relate to Window and AppHandle?**
   - Study [webview/mod.rs:1280-1345](file:///Users/kerrick/Developer/tauri/crates/tauri/src/webview/mod.rs#L1280) for the struct definition
   - Note the `window: Arc<Mutex<Window>>` and `app_handle: AppHandle` fields

2. **What Manager methods does Webview implement?**
   - Study the Manager trait implementation for Webview
   - Determine which methods delegate to app_handle vs have own implementation

3. **How does Tokra currently create webviews?**
   - Study [app.rb](file:///Users/kerrick/Developer/tokra/lib/tokra/app.rb) line ~70
   - Find where `@webview_class.new_with_protocol` is called

4. **How does Invoke get the calling webview?**
   - Research how IPC commands access the webview that made the call
   - This affects how clipboard handlers will get `invoke.webview.resources_table`

### Design Decisions

- Should Webview include the Manager module or delegate?
- How to wire Invoke to know its originating Webview?
- Label naming: single webview app vs multi-webview?

### Tests Required

- Manager methods delegate correctly
- Invoke can access its calling webview

## Phase 2.1: ResourceTable and ImageResource

### Objective

Port Tauri's `ResourceTable` for managing resources by integer ID, and create `ImageResource` data class for RGBA images.

### Research Questions

1. **How does Tauri generate random resource IDs?**
   - Study [resources/mod.rs:81-85](file:///Users/kerrick/Developer/tauri/crates/tauri/src/resources/mod.rs#L81)
   - Note: uses `getrandom` for unpredictable IDs (security)

2. **What thread-safety guarantees does ResourceTable need?**
   - In Tauri it's `Arc<Mutex<ResourceTable>>`
   - In Ruby: does it need Mutex protection? Consider IPC dispatch model

3. **How does `close()` differ from `take()`?**
   - Study [resources/mod.rs:172-215](file:///Users/kerrick/Developer/tauri/crates/tauri/src/resources/mod.rs#L172)
   - `close()` calls `resource.close()`, `take()` does not

4. **What is the Resource trait?**
   - Study [resources/mod.rs:27-39](file:///Users/kerrick/Developer/tauri/crates/tauri/src/resources/mod.rs#L27)
   - Optional `name()` and `close()` methods

### Design Decisions

- Ruby equivalent of Resource trait: duck typing or explicit interface?
- Error class: `Tokra::BadResourceId` or use existing error hierarchy?
- ImageResource: `Data.define` or class with accessors?

### Key Sources

| Topic | File | Lines |
|-------|------|-------|
| ResourceTable struct | `tauri/src/resources/mod.rs` | 76-223 |
| Resource trait | `tauri/src/resources/mod.rs` | 27-39 |
| Image struct (Tauri) | `tauri/src/image/mod.rs` | 16-20, 48-59 |
| arboard ImageData | `arboard/src/common.rs` | 127-131 |

- `close` removes resource and calls `close` if defined
