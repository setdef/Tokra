# Plan 067: Every custom URI scheme the builder holds reaches its handler

## Interfaces this changes

- `Tokra::WebviewManager` holds the app's custom protocols, as Tauri's
  `WebviewManager::uri_scheme_protocols` does: `#uri_scheme_protocols`
  (a Hash of scheme to handler) and `#register_uri_scheme_protocol(scheme,
  handler)`, which replaces a handler already held under that scheme
  (`manager/webview.rs:74`, `98-108`). Every handler has the asynchronous
  shape, `handler.call(ctx, request, responder)`; a synchronous one is
  wrapped when it is registered, as Tauri wraps it (`app.rs:1981-2002`).
  A plugin that hands the app a scheme calls this method, as Tauri's
  `TauriPlugin::initialize` does (`plugin.rs:810-815`).
- `Tokra::Builder` keeps one Hash of protocols, not two:
  `register_uri_scheme_protocol` and
  `register_asynchronous_uri_scheme_protocol` write the same Hash, so
  the later registration of a scheme wins whichever kind it is
  (`app.rs:1993`, `2057`). The friendly reader
  `async_uri_scheme_protocols` is gone.
- `Tokra::Native::HttpRequestEvent` gains a last member, `scheme`: the
  scheme the request came in on, the one its handler was registered
  for.
- `Tokra::Native::WebView#open` reads a new required key,
  `uri_scheme_protocols`, an Array of the scheme names to register on the
  webview, as it reads `url` and `initialization_scripts`.
- `Tokra::RuntimeContext#create_window` takes `uri_scheme_protocols:`
  and hands it to `open`.

## Context

`Builder#register_uri_scheme_protocol` and its asynchronous sibling took
a handler for any scheme, but the native layer registered only `tokra`
and `ipc` with each webview (`ext/tokra/src/webview.rs`, the two
`with_asynchronous_custom_protocol` calls in `build`), and
`App#dispatch_http_request` looked up only `"tokra"` among the builder's
handlers. A handler for any other name was stored and never called. Two
agents reported it; reading the code confirmed it on trunk at 7625e0d.

Tauri registers every scheme its manager holds on every webview it
prepares, then its own `tauri` and `ipc` protocols unless a registered
scheme already took the name (`manager/webview.rs:222-280`).

Sources read: Tauri at the pinned submodule, 9f0306fb; wry 0.54.1 and
tao 0.34.5, the versions `Cargo.lock` holds (`cargo metadata --locked`).

## Decisions

1. **Ruby decides the names; Rust registers them.** `WebviewManager#
   registered_scheme_protocols` answers the held schemes in the order
   they were registered, then `tokra` unless held, then `ipc` unless held,
   as `prepare_pending_webview` builds `registered_scheme_protocols`
   (`manager/webview.rs:222-280`). `WebviewWindowBuilder#build` hands the
   list to `RuntimeContext#create_window` beside `url` and
   `initialization_scripts`, and `Native::WebView#open` registers each
   name with the one forwarding closure both protocols shared (the former ADR 010
   §1), skipping on Linux a name the web context already has. The native
   layer learns no scheme name of its own; `new_with_protocol`, which the
   older fixtures use, registers `tokra` and `ipc` as before.

2. **The request says which registration it came through.** Tauri gives
   each scheme its own closure, so its handler never parses the URI to
   learn its scheme. Each Tokra closure captures its scheme name and puts
   it on `UserEvent::HttpRequest`, which reaches Ruby as
   `HttpRequestEvent#scheme`. App routes on that, not on the URI's
   prefix. The URI agrees on every platform today (WebView2's revert,
   above), but a platform that canonicalizes a scheme's case would not
   (UNVERIFIED for WebKit: `setURLSchemeHandler:forURLScheme:` is
   documented to take a lowercase scheme, and a page's URL is lowercased
   by the URL parser), and routing on the registration is what Tauri
   does. Options weighed: parse the URI in Ruby (no native change, but a
   second, weaker source of truth); one closure per scheme in Ruby (the
   native layer would hold Ruby procs, which ADR 012 forbids across
   threads). Cost: one `String` field per request.

3. **App routes as Tauri's registration order does.** A request whose
   scheme the manager holds goes to that handler, `tokra` and `ipc`
   included; otherwise `ipc` goes to the transport and `tokra` to the
   Rack app, when there is one. Before, the synchronous `tokra` handler
   was tried before the asynchronous one; now there is one Hash.

4. **A page from a held scheme is the app's own.** `App#local_url?` gains
   the third arm of `is_local_url`: on macOS and Linux the URL's scheme is
   a held scheme; on Windows its domain's first label is one and its
   scheme is the app's `http` or `https` (`webview/mod.rs:1696-1722`).
   The former ADR 010 §6 calls the check a stopgap until capabilities; this widens
   it exactly as far as Tauri's own locality does.

5. **A NUL in a scheme raises `ArgumentError`** ("scheme contains null
   byte", in the words a NUL label already gets from
   `window_labels::refuse_nul`) from `Native::WebView#open`, before
   anything is built. Tauri panics. Tier 1:
   a Rust panic ends Ruby's VM.

6. **A handler that raises is reported, as before.** The loop reports a
   `StandardError` from any event handler and the request stays pending.
   Tauri's handler cannot raise; a panic inside wry's callback aborts.
   Answering 500 would be an invention, so this plan keeps today's
   behavior and records it.

## Changes

- `ext/tokra/src/webview.rs`: `build` takes the scheme list and registers
  each name; `forward_request_to_ruby` and `http_request_event` take the
  scheme; `open` fetches `uri_scheme_protocols` and refuses a NUL.
- `ext/tokra/src/user_event.rs`, `event_loop.rs`: the `scheme` field and
  its delivery.
- `lib/tokra/native/events.rb`, `sig/tokra/native.rbs`: the member.
- `lib/tokra/builder.rb`, `sig/tokra/builder.rbs`: one Hash; RDoc with
  Tauri's warning about origins.
- `lib/tokra/webview_manager.rb`, `sig/tokra/webview_manager.rbs`: the
  protocols and the name list.
- `lib/tokra/app.rb`, `sig/tokra/app.rbs`: copy the builder's protocols
  into the manager; route on `event.scheme`; the locality arm.
- `lib/tokra/webview_window_builder.rb`, `lib/tokra/runtime_context.rb`,
  their sigs: hand the list to `open`.
- `test/support/stub_native.rb`: `WebView#open` reads the list.
- CHANGELOG.

## Verification

- Rust: `http_request_event` carries the scheme; the Linux filter keeps
  order and skips what the context has; a NUL scheme is refused.
- Ruby, on a real `App` over `StubNative`: each held scheme reaches its
  handler with the webview's label; the last registration of a scheme
  wins across kinds; a held `ipc` replaces the transport and a held
  `tokra` the Rack app; the webview is opened with the held names, then
  `tokra`, then `ipc`; a page from a held scheme may invoke, and from an
  unheld one may not, on each platform's URL form.
- A real-window fixture, `test/integration/fixtures/uri_schemes`: its
  window loads `second://localhost/` from a synchronous handler, whose
  page fetches from `third`, an asynchronous handler that answers from
  another thread, and invokes a command from that origin.
  `test/integration/uri_schemes_test.rb` checks it. Not run by the
  author (no window may open on the workstation); it runs in the gate.

## Untested without a display

- That wry registers each name and WebKit, WebKitGTK, and WebView2 call
  the closure: the fixture above.
- WebView2's filter for a scheme and its revert: read in wry's source
  only; Windows CI runs the fixture.

## Out of scope

- Serving `frontendDist` or a dev server over `tokra://`.
- Plugin registration of schemes (another agent's plan): it calls
  `WebviewManager#register_uri_scheme_protocol`.
- `asset://` and the isolation pattern's protocol.
