# Plan 056: Real-window tests run in a hidden session

Tokra's real-window tests open tao windows, menus, trays, file panels,
and notifications. On the maintainer's Mac they open them in the
maintainer's own session, and the keyboard tests ask the person to step
away (Plan 046). The maintainer now has a test account, `tokratest`,
logged in out of sight, with its own desktop and its own desktop input
lock, and the scripts in `~/Developer/hidden_session` that hand it jobs
(its `RECIPE.txt`). This plan moves the real-window tests there, so the
gate opens no window in the maintainer's session, ever.

## Which tests open real windows

A test file opens real windows when it is under `test/integration/`
(the `RealApp` fixtures, and `keyboard/`), when it names `RealApp` or
`NativeEventLoop` followed by `.` or `::` (the in-process native tests
in `test/native/`, and each plugin's `test_*_window.rb`), or when it is
one of two plugin tests that open real system UI without either: the
dialog plugin's `test_macos_dialogs.rb` runs real AppKit file panels,
and the notification plugin's `test_macos_notifications.rb` posts real
notifications. `tasks/real_windows.rb` (`RealWindows`) holds that rule,
and its tests check it against the repository's own files.

The clipboard and global-shortcut plugins' other tests touch the
system clipboard and register unusual system hotkeys, but open no
window; they stay where they are.

## Where they run

`RealWindows.where` decides, from the environment:

- `TOKRA_REAL_WINDOWS=local` runs them in this session, as before;
  `TOKRA_REAL_WINDOWS=hidden` runs them in `tokratest`. Any other value
  is refused.
- Unset, they run here on CI and off macOS, and in `tokratest` on a Mac
  outside CI, which is the maintainer's. CI means `CI=true`, exactly as
  GitHub sets it (Linux under Xvfb, macOS, and Windows keep running them
  as today). Any other value of `CI`, empty, `0`, `false`, or `1`, is no
  CI, so a stray variable on the maintainer's Mac cannot open windows.

The split is a split, not a skip: `test:core`, `plugins:test`, and a
plugin's own `rake test` never run a real-window file, and `test:gui`
runs every one, so each runs exactly once wherever it runs. Locally
`test:gui` runs `test:keyboard` first, then `test:real_windows` (the
other core files), then `test:real_windows:plugins` (each plugin's
window files, through its own bundle). Each plugin's Rakefile runs the
files its `TOKRA_TESTS` names, comma-separated, or else every test but
the real-window ones. Rake's own `TEST` would not do: Rake 13.4 splits
it on commas and 13.3, which some plugins lock, does not. The three
local tasks, and `test:replay`, whose recorded orders hold native
window tests, refuse to start when the tests belong in the hidden
session, naming `TOKRA_REAL_WINDOWS=local`. In the hidden session
`test:gui` is `test:hidden`.

## The tripwire

The file rule only routes. A test it misses would still open windows
in whatever run reached it, so whatever opens one checks first:
`RealApp.launch`, `NativeEventLoop.shared`, and the setups of the
dialog and notification plugins' macOS tests call
`RealWindowsRun.require!` (`test/support/real_windows_run.rb`), which
raises unless `TOKRA_REAL_WINDOWS_RUN=1`. Only `test:keyboard`,
`test:real_windows`, `test:real_windows:plugins`, and `test:replay` set
it, and only for their test processes; `test:core` and `plugins:test`
unset it whatever the shell exported. So it holds locally and in the
hidden job alike, where the same tasks run.

## The hidden job

`tasks/hidden_job.rb` (`HiddenJob`) follows the recipe, as rove-2d-09's
cutover of 2026-11-03 gave it. In the maintainer's session it asks
`hidden-run --account tokratest --ping`, then publishes the checkout
with `stage --to ... tokra CHECKOUT`, with four `--allow`s for tracked
files whose names only look like credentials: the Rails example's
`.kamal/secrets` and `credentials.yml.enc`, Tauri's `tokens.rs`, and
its updater test fixtures.

Each checkout gets a copy and a mirror of its own, so the maintainer
can run gates of several checkouts at once, the main one and any
worktrees. `HiddenJob#place`, the one method to change should the
hidden session place them otherwise, keys both by a slug of the
checkout's path (its folder's name and eight hex digits of a digest of
the whole path): `/Users/Shared/hidden-src/tokra-SLUG`, the one place
the test accounts read from, and `/Users/tokratest/tokra-mirror-SLUG`.
rove-2d-09 confirmed `stage --to` for this routine use. Two gates of
the same checkout would still share both, so they take turns on a
`flock` of the checkout's `tmp/hidden-job.lock`, the second saying it
waits.

Every slug shares one gem bundle, `bundle/tokra`, which holds gems by
name and version and git gems by revision, so different checkouts'
lockfiles coexist there; but two installs at once would both write it.
So the job runs `hidden-tools-install --check --staged STAGED tokra`,
and only when that finds something missing installs, holding a `flock`
of a file in the maintainer's own temporary folder across checkouts,
then checks again. An install that fails, or leaves something missing,
fails the job. It then reads `toolchain-env tokra STAGED`.

In `tokratest` it runs the shared `mirror` from the staged copy into
the checkout's mirror, which leaves the copy's `target/` and `tmp/`,
Cargo's builds, to the account. Then it runs `bundle exec rake
test:keyboard test:real_windows test:real_windows:plugins` there, with
`toolchain-env`'s variables, `CARGO_HOME=/Users/tokratest/.cargo`,
`TOKRA_QUIET=1`, `TOKRA_REAL_WINDOWS=local`, `TOKRA_HIDDEN_JOB=1`,
`--min-free-gb 20`, and `--merge`. It never runs `bundle install` at
the root there, which cannot rewrite the shared bundle's binstubs, and
the plugin tasks, seeing `TOKRA_HIDDEN_JOB`, run it only when `bundle
check` fails; elsewhere they install as they always did. It passes on
what each step prints as it comes, not a line at a time, so the tests'
dots show live. It never passes `DESKTOP_INPUT_LOCK`, which
`hidden-run` sets to the account's own lock (one per account, shared by
every Tokra job there), and refuses to hand the account any path under
the maintainer's home. A hidden-session script that is missing fails
the job by name.

A runner that does not answer fails the gate, saying how to run the
tests here instead; nothing falls back to this session. `hidden-run`
exits 69 only when the runner never took the job: a slow heartbeat
mid-job it follows on its own. So 69 at any step is reported as "no test
ran", never as a pass; 70, 75, 124, and 130 get their own messages, and
a step a signal ended names the signal.

`rake test:hidden:prune` keeps the disk in check. It reads each
`tokra-*` copy's `.stage` record, and for each whose checkout is gone
it removes the mirror (`hidden-run --account tokratest -- /bin/rm -rf
/Users/tokratest/tokra-mirror-SLUG`) and then the copy. A copy with no
record is left alone.

## The plugins' real-window tests

These run in `tokratest` with the rest, since `hidden-tools-install`
shares the gems of every plugin's `Gemfile.lock` and the Bundler
version each names (hidden_session `39234ea`). `HiddenJob::PLUGINS`
keeps the switch: false leaves `test:real_windows:plugins` out of the
job, and the job then says, as its last line, that those tests did not
run and how to run them here.

## Tests

`test/tasks/test_real_windows.rb` covers the routing rule (with every
value of `CI` that is not `true`), the file rule against the
repository's own files, and the tripwire, with `RealApp.launch` and
`NativeEventLoop.shared` refusing outside a real-window run. In child
Rakes it checks that each of the four local tasks refuses, that
`test:gui` fails rather than open windows here when the hidden session
cannot run them, and, with every task it might invoke stubbed, which
tasks `test:gui` runs, in order, locally and hidden.
`test/tasks/test_hidden_job.rb` drives `HiddenJob` against fake
`hidden-run`, `stage`, `toolchain-env`, and `hidden-tools-install`
scripts in a temporary folder, which log their arguments: the commands
and their order, each checkout's own place, the check before any
install and the check after it, both locks, output streamed before a
line ends, the plugins switch, the failures (no runner, a missing
script, no `stage:` or `mirror:` line, each exit status, a signal), and
the prune.

## Amendment, 2026-11-03: the console set

Off the console, macOS lowers WebKit's page process to background
priority, and under load the dialog plugin's window test starves past
its bound in `tokratest`. Plan 057 names the few tests that need the
console in `RealWindows::CONSOLE`; the hidden job leaves them out, and
on the maintainer's Mac `test:gui` runs them after `test:hidden`, in
`test:console`, in the maintainer's session. The clipboard plugin's
tests, which write the system clipboard, now count as real-window
tests and run hidden.
