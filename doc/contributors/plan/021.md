# Plan 021: tokra-clipboard on ferro-arboard

ADR 011 §9 moves crate bindings out of Tokra's plugins and into Ferro.
`tokra-clipboard` goes first, now that `ferro-arboard` has a release. The
plugin loses `ext/tokra_clipboard`, its Cargo workspace, and every gate,
CI, and packaging reference to them, and becomes pure Ruby over
`Ferro::Arboard`. Its Tauri behavior, payload validation, and messages stay
as they are. The same session raises the Ruby pin to 4.0.9.

Sources: `tauri-plugin-clipboard-manager` at plugins-workspace `d4613ff0`
(`src/desktop.rs`, `src/error.rs`, `src/lib.rs`, `src/commands.rs`), the
commit plan 016 audited; `ferro-arboard` at tag `ferro-arboard/v0.1.0.pre.2`
(commit `6058508`, arboard 3.7.0), read with `git show` from that tag;
Ferro's plan 001 on its trunk for the caveats found after the tag; Ruby
`v4.0.9`.

## Context

The plugin had two answer keys in one gem. Its Ruby side answered to
Tauri's `clipboard-manager`; its Rust side answered to arboard, and carried
a guard against images arboard 3.6.1 panics on (plan 016, item 6), a
`Mutex<Option<arboard::Clipboard>>` that made it Ractor-shareable (ADR 007),
and a stored construction error. `ferro-arboard` now owns the arboard half:
it mirrors arboard 3.7.0 one to one, raises `Error::ConversionFailure` for
any image with a zero dimension or a byte count other than
`width * height * 4`, turns any arboard panic into `Ferro::Arboard::Error`,
releases the GVL for Linux reads, and marks a frozen `Clipboard` shareable.

What is left for the plugin is what Tauri's plugin does: the managed
`Clipboard` state (`desktop.rs`), the conversion of every arboard error into
`Error::Clipboard(String)` (`error.rs:28-33`), the commands, and the exit
hook (`lib.rs:62-67`).

## Fidelity audit

| Behavior | Tauri | Tokra before | Verdict |
|---|---|---|---|
| Managed state | `Clipboard<R>` holding `Result<Mutex<Option<arboard::Clipboard>>, arboard::Error>` (`desktop.rs:11-28`) | the native `TokraClipboard::Native::Clipboard` | move to a Ruby `Clipboard` class with Tauri's name and methods |
| A failed `arboard::Clipboard::new` | stored; each method returns `Error::Clipboard(e.to_string())` (`desktop.rs:38`) | stored in Rust, raised per call | keep, in Ruby |
| arboard errors | `Error::Clipboard(error.to_string())` (`error.rs:28-33`), serialized as the string (`error.rs:20-26`) | Rust raised `RuntimeError`; the plugin rescued it | rescue `Ferro::Arboard::Error`, whose messages are arboard's `Display` |
| `ClipboardExt#clipboard` | `state::<Clipboard<R>>()` (`lib.rs:32-41`) | returned the native object, which raised `RuntimeError` | returns the Ruby `Clipboard`, which raises `Error::Clipboard` |
| Image arboard cannot draw | passed to arboard, which panics on macOS | guarded in the plugin's Rust | `ferro-arboard` raises `ConversionFailure`; the plugin maps it |
| Exit | `cleanup` takes the arboard clipboard (`desktop.rs:118-122`, `lib.rs:62-67`) | Rust `take()` | Ruby latch; see decision 3 |
| Use after cleanup | panics (`.unwrap()` on `None`) | raised "Clipboard has been cleaned up" | keep Tokra's message |
| Wayland | arboard's `wayland-data-control` feature on (`Cargo.toml:38`) | off | on: `ferro-arboard` builds every feature |

## Decisions

1. **The managed state is `Tokra::Plugins::Clipboard::Clipboard`.** It
   mirrors `desktop.rs`'s `Clipboard`: `write_text`, `write_image`,
   `read_text`, `write_html`, `clear`, `read_image`, and `cleanup`, taking
   and returning Tokra's types (`Tokra::Image`). `ClipboardManagerExt`
   returns it, so `handle.clipboard.read_text` raises `Error::Clipboard`
   with arboard's message, as `app.clipboard().read_text()` returns it in
   Tauri. The `Plugin` methods delegate to it.

2. **Errors map in one place.** Every arboard variant becomes
   `Error::Clipboard` with arboard's text, so one `rescue
   Ferro::Arboard::Error` covers all five subclasses and the base class
   `ferro-arboard` raises for a panic or a variant it does not name yet.

3. **Cleanup is a shareable latch.** Tauri's `Option` exists so its exit
   hook can drop arboard's clipboard, which Rust never drops for managed
   state. The Ruby `Clipboard` is frozen and Ractor-shareable (ADR 007,
   ADR 011 §7), so it cannot drop its reference, and a frozen object cannot
   flip a flag. Ruby has one core object that is shareable and still changes
   state: `Ractor::Port`, whose `close` is one-way and whose `closed?` any
   Ractor may ask. `cleanup` closes the clipboard's port, and every
   operation then raises "Clipboard has been cleaned up". The arboard
   clipboard itself drops when Ruby frees it, at the latest at a normal
   exit, which `ferro-arboard` documents. Rejected: a class-level registry
   (global state, writable only from the main Ractor) and a Ractor that owns
   the clipboard (every call a message, and the Windows barrier bug below).
   This is precedence tier 1: Ruby cannot express a deterministic drop.

4. **No Mutex.** Tauri's `Mutex` turns `&self` into the `&mut` arboard
   wants. `ferro-arboard` takes calls on a frozen clipboard from any thread,
   so the Ruby class holds none.

5. **Validation stays in the plugin, unchanged.** `ferro-arboard`'s own
   `TypeError`s are unreachable from IPC, because the plugin checks every
   argument in Tauri's words first.

6. **The dependency is the release tag.** Tokra's Gemfile and the plugin's
   name `ferro-arboard` as a git source at tag `ferro-arboard/v0.1.0.pre.2`
   with `glob: "gems/*/*.gemspec"`, as Ferro's README shows. The gemspec
   pins `= 0.1.0.pre.2`: prereleases promise no API to each other, and
   RubyGems considers a prerelease only for a requirement that names one.
   RubyGems cannot depend on a git source, so a released `tokra-clipboard`
   waits for `ferro-arboard` on RubyGems.org; until then the gem installs
   only through a Gemfile that names the tag too.

7. **The packaging check learns external dependencies.** Fast mode puts
   each non-Tokra runtime dependency's require paths, from the bundle, on
   the smoke script's load path, and accepts files loaded from Bundler's
   install path. Full mode builds each git-sourced dependency from its
   Bundler checkout and installs it into the empty `GEM_HOME` first, so
   RubyGems compiles `ferro-arboard` from its packaged sources too.

8. **Ruby 4.0.9.** `mise.toml` pins what CI's `4.0` resolves to. Ruby
   4.0.6 added a GVL hint (`thread_pthread.c`, "Use a hint avoid the
   optimistic sched lock drop/reacquire"): a thread back from a short
   blocking region takes the GVL straight back if the thread it woke has
   not run yet. Ferro found a test that failed only on 4.0.9 because of it.
   Tokra's GVL hand-off (ADR 012) calls `Thread.pass` from the loop, not a
   blocking region, and its tests run in the gate below on 4.0.9. Floors in
   the gemspecs stay at 4.0.1, and source citations at `v4.0.1` stay as
   citations of that release.

## Caveats from ferro-arboard

- **X11 handover, 100 ms.** When the last clipboard drops, arboard offers
  its contents to a clipboard manager and waits at most 100 ms
  (`x11.rs:788-801`). Tauri has the same limit. The plugin keeps its
  clipboard for the app's life, so copied text stays while the app runs; at
  exit the handover may lose it. The README says so. CI ran
  `xfce4-clipman` because plan 019 believed tests needed the handover;
  Ferro found the manager refills a cleared clipboard, which would break
  the plugin's clear tests, and no plugin test reads text after its
  clipboard drops. CI drops the manager, as Ferro's does.
- **X11 clear race.** A write right after `clear`, from any clipboard in
  the process, can be dropped by arboard's late `SelectionClear` handling
  (`x11.rs:233-242`, `:835-856`). Tauri shares it. `Clipboard#clear`'s RDoc
  says so. In the suite it can hit a test that writes right after one that
  cleared; Ferro saw a few runs in a hundred. Unverified on Tokra's CI.
- **Windows Ruby 4.0.9 Ractor barrier.** A GC inside a Ractor waits forever
  while the main Ractor has a sleeping thread and waits in `Ractor#value`
  (Ferro plan 001). The plugin starts no Ractor and its tests share none, so
  nothing in Tokra triggers it; an app that hands the shared clipboard to a
  Ractor on Windows meets Ruby's bug, not the plugin's.

## Changes

- `plugins/clipboard`: delete `ext/`, `Cargo.toml`, `Cargo.lock`; the
  gemspec drops `rb_sys`, the extension, and the Cargo files and adds
  `ferro-arboard`; the Gemfile adds the git source and drops `rb_sys` and
  `rake-compiler`; the Rakefile drops its extension task.
- `lib/tokra/plugins/clipboard.rb`: the `Clipboard` class (decisions 1-4).
- `sig/`: the new class; `TokraClipboard::Native` is gone.
- Tooling: `tasks/package.rake` (crate and extension `nil`, a smoke that
  round-trips text), `tasks/package_check.rb` (decision 7),
  `tasks/steep.rake` (no `--native TokraClipboard::Native`; `rbs validate`
  loads `ferro-arboard`'s signatures), `Rakefile` (no plugin compile).
- CI: Windows exports bindgen's settings before `bundle install`, which now
  compiles `ferro-arboard`; Linux installs `libclang-dev` before it too; no
  clipboard manager.
- README, RDoc, CHANGELOG.

## Verification

- Every behavioral test in `test/test_clipboard.rb` runs against the real
  `ferro-arboard`. Tests of the removed native layer now drive the Ruby
  `Clipboard`; the crate-lint and native-`LoadError` tests become a test that
  `ferro-arboard`'s `LoadError` propagates.
- Manual mutation checks, each reverted after. Dropping the
  `Ferro::Arboard::Error` rescue fails 9 tests; dropping the cleaned-up
  check fails 10, as does making `cleanup` a no-op; swapping `read_image`'s
  width and height fails 3. Moving the construction-error check after the
  cleaned-up check fails none: a machine with a clipboard never fails to
  open one, so that order is checked by review against `desktop.rs:33-39`.
  In `PackageCheck`, dropping the bundled require paths or the vendored-path
  exemption each fails its new test.
- `bundle exec rake` from a clean build on Ruby 4.0.9 (macOS): 527 core
  runs (4 skips), 60 clipboard runs, and 83 log runs pass; RuboCop, Steep,
  RBS parity, RDoc, REUSE, Clippy, fmt, and the packaging check pass.
  `rake package:install` builds `ferro-arboard` from its Bundler checkout,
  installs it beside the three gems, and the clipboard smoke round-trips
  text.

## Results

Every change above is done. Unverified until CI runs: the Linux and
Windows jobs (the reordered setup, `ferro-arboard`'s build under bindgen's
Windows settings, and the clipboard tests on Xvfb without a manager).

## Out of scope

- Publishing `ferro-arboard` or `tokra-clipboard` to RubyGems.org.
- arboard options Tauri does not use (Linux selections, history exclusion).
- ADR 007's text, which ADR 011 §7 already amends in effect; a later ADR
  pass can fold them together.

## Risks

- CI on Linux and Windows is unverified until it runs: the bindgen order,
  the clipboard tests without a manager, and the clear race.
- `Ractor::Port` as a latch relies on `close` from its creating Ractor;
  the plugin creates and cleans up on the main Ractor.
