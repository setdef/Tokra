# Plan 030: tokra-notification reads URLs with ferro-url

Tauri's notification plugin reads each attachment's `url` as a
`url::Url`, so a URL the url crate refuses rejects the whole `notify`
with url's words. Plan 024 hand-ported url 2.5.4's error paths and
idna's ASCII deny list into `UrlCheck`, and recorded a deviation for
non-ASCII and `xn--` hosts, which Ruby had no UTS 46 tables to check
(plan 024, decision 6). Ferro now binds url one to one as `ferro-url`,
so this plan replaces the hand port with the crate itself, and moves
tokra-notification to `ferro-notify-rust` 0.1.0.pre.2.

Sources: url 2.5.4, idna 1.0.3, idna_adapter 1.2.0, and ICU4X 1.5 (the
versions plugins-workspace `d4613ff0`'s `Cargo.lock` pins); url 2.5.8,
idna 1.1.0, idna_adapter 1.2.2, and ICU4X 2.4.0 (ferro-url's
`Cargo.lock`), each read from Cargo's registry copy.
`ferro-url` 0.1.0.pre.1 at tag `ferro-url/v0.1.0.pre.1` (its README and
Ferro's plans 005 and 006); `ferro-notify-rust` 0.1.0.pre.2 at tag
`ferro-notify-rust/v0.1.0.pre.2` (its CHANGELOG).

## What changes between the two url releases

Every hunk of url's `src/` from 2.5.4 to 2.5.8 was read. The parser
changes are performance work (string slices in place of characters,
`Cow` hosts, a faster port writer) and Clippy style; no error path
moves, and the serde visitor still writes `format!("{err}: {s:?}")`
(2.5.8 `lib.rs:2936`). idna 1.0.3 to 1.1.0 adds
`domain_to_ascii_from_cow` and changes no logic in `uts46.rs`. What
does change is the Unicode data under idna: Tauri's lock has ICU4X 1.5
(Unicode 15.1), and ferro-url's has ICU4X 2.4.0 (Unicode 18.0).

## Decisions

1. **The argument reader calls `Ferro::Url::Url.parse`.** A string url
   refuses raises a `Ferro::Url::ParseError` with url's message, and the
   reader wraps it as before, with the string in Rust's Debug quoting.
   `UrlCheck` and its signatures are deleted.
2. **An `Attachment` holds a `Ferro::Url::Url`.** Tauri's field is
   `url::Url`, and plan 024 kept the string only because Ruby had no
   such type. The reader stores what url parsed, so
   `HTTP://EXAMPLE.com:80/a/../b` reads back as `http://example.com/b`,
   as in Tauri. Apps that build an `Attachment` themselves pass a parsed
   URL, and `Attachment.new` raises `TypeError` for anything else, as
   Rust's types refuse it.
3. **Only ferro-url is a dependency.** url uses idna internally and
   does not re-export it, and Tauri's attachment needs nothing else, so
   tokra-notification does not depend on ferro-idna.
4. **The UTS 46 deviation closes and a smaller one opens.** Non-ASCII
   and `xn--` hosts now go through idna's full processing. The tables it
   reads are Unicode 18.0's, where Tauri's are Unicode 15.1's. A domain
   with a character Unicode 16.0 or later assigned, or with one of 66
   older code points that UTS 46 16.0 maps, ignores, or allows instead
   of refusing (U+04C0, U+10A0 to U+10C5, U+115F, U+1160, U+17B4,
   U+17B5, U+1806, U+180E, U+2061 to U+2063, U+206A to U+206F, U+2132,
   U+2183, U+3164, U+FFA0, U+1D173 to U+1D17A), can parse in Tokra, or
   fail later with another error such as `invalid IPv4 address`, where
   Tauri answers `invalid international domain name`. Some newly
   assigned characters still fail in both: in the oracle runs, 96
   right-to-left letters that idna's bidi rule refuses beside Latin
   ones. No input in the oracle runs below goes the other way. Ferro
   binds a crate's latest release, as ferro-notify-rust binds
   notify-rust 4.18.2 where Tauri's lock has 4.11.7 (plan 024), and
   Tokra's own extension already links url 2.5.8 and idna 1.1.0 through
   wry. The deviation stands, recorded in the plugin's RDoc and README,
   until Tauri's lock moves to ICU4X 2.
5. **The dependencies are release tags.** Both Gemfiles take
   `ferro-url` from tag `ferro-url/v0.1.0.pre.1` with the glob
   `gems/url/*.gemspec`, and `ferro-notify-rust` from tag
   `ferro-notify-rust/v0.1.0.pre.2`, which fixes a hang reading a
   `Notification` shared between Ractors. The gemspec pins
   `= 0.1.0.pre.1` and `= 0.1.0.pre.2`. Steep's RBS validation reads
   ferro-url's signatures, with the `ipaddr` and `socket` libraries they
   name; the packaging smoke reads an attachment through ferro-url. CI
   needs nothing new: url's Unicode data is compiled in.

## Verification

- The plan 024 oracle, a scratch crate compiling Tauri's `models.rs`
  with the locked serde, serde_json, time, url 2.5.4, idna 1.0.3, and
  idna_adapter 1.2.0, now prints each accepted URL's serialization. A
  twin crate locks url 2.5.8, idna 1.1.0, idna_adapter 1.2.2, and ICU4X
  2.4.0, ferro-url's versions.
- Through the plugin's real argument reader, Tokra matched the 2.5.4
  oracle, message and serialization, on plan 024's 6,057 URLs, and the
  2.5.8 oracle on all of them. On 16,000 new fuzzed URLs aimed at
  international domains (half mutating only the host), Tokra matched the
  2.5.8 oracle on every one and the 2.5.4 oracle on all but 994. On
  `http://a<c>b.com/` for each of the 1,111,936 non-ASCII scalar values,
  Tokra matched the 2.5.8 oracle on every one and the 2.5.4 oracle on
  all but 22,941: 22,875 code points Unicode 16.0 to 18.0 assigned, and
  the 66 of decision 4. Every difference, here and in the fuzz, is a
  2.5.4 IDNA error that 2.5.8 accepts (or, in eight fuzzed URLs, reads
  on to an IPv4 error), and each is a case where the two oracles
  differ.
- `test_each_url_parses_as_url_parses_it` holds 75 of the 2.5.4
  oracle's answers, now with each accepted URL's serialization and 18
  international cases plan 024 could not check;
  `test_a_domain_in_newer_unicode_parses` pins decision 4, and
  `test_an_attachment_refuses_a_url_that_is_not_parsed` decision 2.
- Manual mutation checks, in Results.
- `bundle exec rake` from a clean build.

## Results

Every decision above is done.

- Manual mutation checks, each reverted after: storing the string in
  place of the parsed URL fails `test_each_url_parses_as_url_parses_it`
  and `test_every_field_reaches_notification_data`; dropping the quoted
  string from the message fails `test_each_url_parses_as_url_parses_it`;
  skipping idna's refusal for a non-ASCII or `xn--` host, as `UrlCheck`
  did, fails it too; dropping `Attachment`'s type check fails
  `test_an_attachment_refuses_a_url_that_is_not_parsed`.

## Out of scope

- The ISO 8601 port (`iso8601.rb`), which a ferro-time binding will
  replace separately.
- ferro-idna: nothing Tauri's notification plugin does calls idna
  directly.
