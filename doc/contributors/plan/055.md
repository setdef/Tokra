# Plan 055: Every URL Tauri types as `url::Url` is a `Ferro::Url::Url`

Tauri hands a URL across its API as the url crate's `Url`, which parses
by the WHATWG URL Standard. Tokra reached the same spots at different
times and answered them differently. Plan 052 (decision b2, e1-4, e2-2)
chose Ruby's `URI`, which follows RFC 3986, for `WebviewUrl`,
`proxy_url`, `Webview#url`, `#navigate`, and `#cookies_for_url`. Plan
030 gave the notification plugin's attachments a `Ferro::Url::Url`.
Plan 054 (decision 25) found that the two parsers disagree widely
(`http://a:99999`, `http:/localhost`, IDN hosts, `%zz`, `C:\dist`, dot
segments, IPv4 shorthand), made the config's URLs ferro-url's, and left
`WebviewUrl::External` and `CustomProtocol` taking either type. That
mix means a URL reads one way from the config and another from code,
and every `URI` site carries a documented deviation from the url crate.

ferro-url binds url 2.5.8 one to one (ADR 011), and the core gem
already depends on it. This plan makes every URL Tauri types as
`url::Url` a `Ferro::Url::Url` in Tokra, and stops taking or answering
Ruby's `URI` there.

## Decisions

1. **A URL argument is a `Ferro::Url::Url`, and anything else raises
   `TypeError`, a `URI` included.** Tauri takes `Url`, and a Rust caller
   parses first (`"https://tauri.app".parse().unwrap()`), so a Ruby
   caller parses first too: `Ferro::Url::Url.parse("https://tauri.app")`.
   Converting a `URI` would invent a second, Ruby-shaped door into the
   API, which AGENTS.md's precedence 2 rules out, and it would hide
   exactly the disagreement plan 054 found: the `URI` a caller built is
   not the URL Tauri would have parsed from the same text (`URI` keeps
   `http://a/b/../c`, the url crate reads `http://a/c`; `URI` takes
   `http://a:99999`, the url crate refuses it). ADR 001 puts the logic in
   Ruby, so Ruby parses, and it parses with the url crate as Tauri does;
   ADR 011 sends that crate binding to Ferro, and plan 054 (decision 25)
   reads the config's URLs into `Ferro::Url::Url`, so a URL written in
   code and one read from `tokra.conf.json` are now one type with one
   parser. The message is Ruby's, as the notification plugin's
   `Attachment` words it: "wrong argument type URI::HTTPS (expected
   Ferro::Url::Url)".
2. **The relative-URL refusals keep the url crate's words.** A
   `Ferro::Url::Url` is always absolute, so `navigate` and
   `cookies_for_url` no longer check: the refusal moved to where Tauri
   has it, `Url.parse`, which raises
   `Ferro::Url::ParseError::RelativeUrlWithoutBase`, "relative URL
   without a base". A relative `URI` is refused by its type, before any
   check could see it. `Webview#url` parses wry's String with
   `Ferro::Url::Url.parse` and raises `Error::InvalidUrl` with the
   crate's message for any refusal, "invalid url: relative URL without a
   base" for WebKitGTK's `""`, as `Error::InvalidUrl(url::ParseError)`
   prints it. This closes 052e-2's deviation, where a URL Ruby's `URI`
   refused raised with `URI`'s message.
3. **A `WebviewUrl` holds a frozen URL.** A `Ferro::Url::Url` is mutable
   (`set_path`, `set_host`), and a `Data` value should not change under
   its holder. Rust moves the `Url` into the enum, so no one else can
   change it; Ruby gets the same by freezing: a frozen URL is kept, any
   other is copied and the copy frozen. The page-load payload's URL,
   which Tokra parses itself, is frozen too, and so is the notification
   plugin's `Attachment#url`, which keeps or copies as `WebviewUrl` does.
4. **A page load reaches its hooks with a `Ferro::Url::Url`, or not at
   all.** tauri-runtime-wry parses wry's String and drops the load when
   the url crate refuses it (`lib.rs:4843-4855`), so `dispatch_page_load`
   does the same, before it looks up the webview.
5. **`proxy_endpoint` reads the URL as `parse_proxy_url` does.** The host
   is `url.host` printed (an IPv6 host keeps its brackets), the port
   `url.port`, which the url crate already answers as `nil` for the
   scheme's default. The lowercasing Tokra did for `http`, and the
   IPv4 and IDNA deviations the RDoc named, go: the url crate does that
   as it parses.
6. **Nothing in Rust changes.** wry takes `&str` for `load_url` and
   `cookies_for_url` and answers `String` for `url`; Tauri's runtime
   hands it `url.as_str()`. Ruby sends `Ferro::Url::Url#as_str`, the same
   serialization, and the native signatures stay Strings.
7. **Tokra's own URLs are the url crate's too.** Tauri builds the app's
   URL with `Url::parse` and joins an `App` path with `Url::join`, and it
   reads an IPC origin with `Url::parse`. With ferro-url Tokra does the
   same and drops `encode_relative`, which imitated the crate's join by
   hand, with the four deviations its RDoc named (`|`, `^`, `\` off
   Windows, a second `#`, a stray `%`). Tokra's app URL still keeps its path's slash
   (`tokra://localhost/`, plan 052, decision b2), now as
   `tokra_protocol_url.join("/")`. Tauri maps a failed join to
   `Error::InvalidUrl` and then unwraps it, saying it "will never fail"
   (`manager/webview.rs:423-427`); it can, for a path naming another host
   such as `//exa mple`. Tokra raises that `Error::InvalidUrl`, with the
   crate's reason, from `WebviewWindowBuilder#build` before anything is
   built (*deviation*, tier 1: a panic ends Ruby's VM), and says so in the
   RDoc of `#build` and `WebviewUrl::App`. `local_url?` reads the origin
   with the url crate and compares the scheme and `domain` exactly, as
   `is_local_url`'s first arm does: the crate lowercases the scheme and an
   http host as it parses, but keeps a `tokra://` host's case, so
   `tokra://LOCALHOST` is not the app's. Tokra used to fold that case.
   Tauri's third arm covers only schemes the app registers itself, so for
   a Rack-served app the fold was looser than Tauri, the wrong direction
   for a check that guards IPC.

## Breaking changes, and the CHANGELOG

Everything here is unreleased: `v0.0.1.pre.2` shipped only `Native` and
`Rack::Handler::Tokra` (`git ls-tree v0.0.1.pre.2 lib/`), so per
AGENTS.md the Unreleased "Added" entries are amended in place and no
"Changed" line is added:

- `#proxy_url` (in the webview rows entry) takes a `Ferro::Url::Url`.
- `Webview#url`, `#navigate`, `#cookies_for_url`: answer and take a
  `Ferro::Url::Url`.
- `Tokra::WebviewUrl::External` and `CustomProtocol` hold a
  `Ferro::Url::Url`; the separate "also take a `Ferro::Url::Url`" line
  goes.
- `Builder#on_page_load`: the payload's `url` is a `Ferro::Url::Url`, and
  a load whose URL the url crate refuses is not reported.
- The ferro-url dependency line names every URL, not only the config's.

`Rack::Handler::Tokra` is the one released API that parses a URL, and it
keeps `URI`.

## Tests

Each changed signature gets a test that fails against the old code:

- `WebviewUrl::External` and `CustomProtocol` refuse a `URI` with the
  new message, and hold a frozen copy of an unfrozen URL;
  `webview_url` joins `|`, `^`, `\`, a second `#`, and `%zz` as the url
  crate does where it raised before.
- `proxy_url` refuses a `URI`; the endpoint table reads Ferro URLs, with
  a non-default IPv4 form as the url crate normalizes it.
- `Webview#url` answers a `Ferro::Url::Url`; a URL the url crate refuses
  raises `Error::InvalidUrl` with the crate's message; `navigate` and
  `cookies_for_url` refuse a `URI` and send `as_str`.
- The page-load payload's URL is a frozen `Ferro::Url::Url`, and a load
  with an unparseable URL reaches no hook.
- The origin check: an origin `URI` takes and the url crate refuses
  (`tokra://localhost:99999`) is malformed.
- `webview_url` and `#build` raise `Error::InvalidUrl` for a path the
  join refuses, and `#build` builds nothing.
- The origin check: a host in another case is the app's only where the
  url crate lowercases it (http), and the app's domain under another
  scheme is foreign.
- The notification plugin's `Attachment` holds a frozen copy of its URL.

The real-window fixtures (`webview_page`, `webview_rows`, `exit_paths`)
build their URLs with ferro-url.
