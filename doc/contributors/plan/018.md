# Plan 018: Real-Window Integration Tests

[ADR 003](../adr/003.md) set a bar every feature has to clear and called it
the "Ping Pong Test": a full round trip through a real window, a real
webview, and the IPC layer. The test it named was never written. Every test
since has driven `App` through `StubNative`, which stands in for tao and wry,
so nothing has shown that the page a user sees can call Ruby, get an answer,
and exit cleanly. Plan 016 closed with a list of native paths "untested
without a display" and the manual run that would confirm each.

ADR 003's code sample predates the current design: it builds `Native`
objects by hand, posts a raw `"PING"` through `window.ipc.postMessage`, and
wakes the loop from a Worker Ractor. Today `App` owns the loop (ADR 009), the
real `@tauri-apps/api` client rides `ipc://` (ADR 010), and the Worker Ractor
is still deferred. This plan meets the bar against today's design, as a small
test infrastructure rather than one test.

Sources: `vendor/tauri` at `9f0306fb`; tao 0.34.5 and wry 0.54.1 as locked
in `Cargo.lock`.

## Decisions

1. **Tests and fixtures, not an example.** `examples/` is documentation for
   app developers, so the tests own their apps. `test/integration/support/`
   holds two halves of one contract. `real_app.rb` (`RealApp`) launches a
   fixture, captures it, and holds the skip rules. `fixture_app.rb`
   (`FixtureApp`) is what a fixture builds on: a Rack site serving its
   `index.html`, the shared `harness.js`, its options, and a report endpoint,
   plus a `fixture` plugin that prints the run events it hears and serves
   `plugin:fixture|exit`. Each concern gets one fixture directory under
   `test/integration/fixtures/` with an `app.rb` and a minimal page, and one
   test file named for what it verifies:

   | Test | Fixture | Verifies |
   |---|---|---|
   | `ipc_transport_test.rb` | `ipc_transport` | invoke resolves and rejects over `ipc://`, no fallback |
   | `image_plugin_test.rb` | `image_plugin` | `plugin:image` through the real `Image` class |
   | `rack_assets_test.rb` | `rack_assets` | byte-exact PNG and render size, array and file bodies |
   | `origin_acl_test.rb` | `origin_acl` | foreign frame rejected on both transports |
   | `exit_paths_test.rb` | `exit_paths` | exit status, Ctrl-C, `RunEvent::Exit`, Ruby's exit, a raising hook |

   The fixtures share only the harness and site; each page holds its own
   checks. The test glob becomes `test/**/test_*.rb` and
   `test/**/*_test.rb`, so the rake task never loads a fixture app (which
   would open a window in the test process).

2. **The page reports over Rack, not IPC.** If IPC were broken, a report sent
   over IPC would never arrive. `harness.js` `POST`s the results to
   `tokra://localhost/report`, and the site prints one `REPORT` JSON line.
   Only then does the page ask Ruby to exit through `plugin:fixture|exit`,
   which calls `AppHandle#exit`. The tests assert in Ruby on each check's
   details, not only on the page's verdict, and compare the PNG against
   `File.binread` and `Tokra::Image.from_path`.

3. **A foreign origin without the network.** Tauri's threat is a page from
   another origin that holds the invoke key: wry injects it into every
   top-level document. The `origin_acl` page embeds an iframe from
   `tokra://foreign.test`, which the same Rack app serves offline, and only
   for that host. The same scheme with another host is not local under
   `is_local_url`, which compares scheme and host. wry injects initialization
   scripts into the main frame only (`lib.rs:966-968`), so the frame cannot
   use `@tauri-apps/api`; the fixture writes the real key into it, labeled as
   a test fixture that no app may copy, and the frame sends both transports
   by hand. Over `ipc://` it reads the HTTP reply itself. Over `postMessage`,
   wry reports the frame's own URL (`wry_web_view_delegate.rs:50-61`), and
   Tokra answers with `runCallback` in the main frame, so the main page
   registers the callbacks (`transformCallback`) and passes their ids to the
   frame. A `data:` or `about:blank` frame would not test the ACL check: its
   origin is the opaque `null`, which `ipc://` rejects earlier as `Origin
   header is not a valid URL`. A `srcdoc` frame inherits the app's own
   origin.

4. **Ruby ends the process, not `process::exit`.** The first real run showed
   that everything the app wrote to a piped `$stdout` vanished, and `at_exit`
   hooks never ran. tao's `run` is `process::exit(run_return(handler))` on
   every desktop backend, and `process::exit` from inside Ruby skips Ruby's
   exit: no `at_exit`, no `ensure`, no flush of buffered IO.
   `Native::EventLoop#run` now calls `run_return` and raises `SystemExit` with
   the returned code. The process still ends with the code tao would have
   used, but the Ruby way. This is a tier-1 translation (Ruby the language):
   Tauri's `App::run` never returns and Rust has no exit hooks to skip; in
   Ruby, ending the process means unwinding to the top with `SystemExit`.
   `App#run` still never returns. Flushing `$stdout` and `$stderr` from Rust
   before tao exits would keep losing `at_exit` hooks and `ensure` clauses.

5. **Child processes, each under a timeout.** tao's loop needs the main
   thread and ends the process, so each fixture runs as a child in its own
   process group, once per test class however many tests read the result. A
   hung app has its group killed after 60 seconds and fails with its captured
   output; the reader threads get a bounded wait, an `ensure` kills the child
   if the launcher itself raises, and signals ignore a process that already
   ended. `exit_paths` runs twice: once exiting through `AppHandle#exit`, once
   with `--wait` (no exit of its own) and Ctrl-C (`SIGINT`) sent after the
   report. The Ctrl-C test requires the app to end within 15 seconds of the
   signal and refutes `Interrupt` on stderr, the trace of Ruby's own SIGINT
   handler, which would only raise inside the next callback.

6. **In the default gate when a window can open.** The tests run under
   `bundle exec rake` and skip, with the reason, when there is no display: on
   macOS when `launchctl managername` is not `Aqua`, on Linux when `DISPLAY`
   and `WAYLAND_DISPLAY` are both unset or empty. They also skip on Windows,
   where the fixture pages' hand-built URLs are wrong (Out of scope).

7. **The loop-survives check uses page-load start.** With
   `--raise-on-page-load`, the `exit_paths` page-load hook raises on `started`
   for `tokra://localhost/`. wry fires `started` when the navigation commits,
   before the page's script sends anything, so the invoke after it ran on a
   loop that survived the exception. The test asserts the full message and
   backtrace on stderr and the invoke's answer.

8. **The example stays the maintainer's.** `examples/verify_ping_pong` is
   back to its last hand-reviewed version (7885f70) with the changes
   today's API requires. The `invoke_handler` is a `Ractor.shareable_proc`
   that reads `Invoke#payload` (Builder rejects a plain proc, and handlers
   receive an `Ipc::Invoke`). The app turns on `with_global_tauri`, and the
   IPC button and the availability badge use `window.__TAURI__.core.invoke`,
   the documented call every Tauri example makes, instead of a raw
   `window.ipc.postMessage(value)` (App drops a message without the invoke
   key, which a page cannot read). The log line after `run` is gone, since
   `run` never returns. Its empty `README.md` is removed.

## Changes

- `ext/tokra/src/event_loop.rs`: `run` uses `run_return`, then raises
  `SystemExit` with the exit code (decision 4). `sig/tokra/native.rbs`
  declares it `-> bot`. `App#run`, `Builder#run`, and
  `Rack::Handler::Tokra.run` stay `-> void`: they also run against
  `StubNative`, whose loop returns, and a `bot` declaration there would claim
  more than the stub delivers. The RDoc of `App#run`, `Native`,
  `Native::LoopDestroyedEvent`, and the loop's own comments say what now
  happens at exit. `clippy_exceptions.rb` follows an approved `#[allow]` that
  moved two lines.
- `test/integration/support/real_app.rb`, `support/fixture_app.rb`,
  `fixtures/harness.js`, five fixtures, and five test files (decision 1).
- `tasks/test.rake`: the narrower test glob.
- `examples/verify_ping_pong`: decision 8.
- `plugins/log`: the README and `Log::Plugin` RDoc showed a `Builder#plugin`
  method Tokra lacks and a constructor the plugin does not take. Both now show
  the real path, `Log::Builder` registered from the setup hook, and
  `test/test_registration.rb` runs that example on a real `App`.
- ADR 003: its status note names the tests that meet its bar.
- CHANGELOG: the exit fix.
- `.agents/skills/port-tauri-feature/references/lessons.md`: the
  `process::exit` lesson and where real-window checks go.

## Verification

Each test is a real assertion against a real window, and each covered line
fails a test when reverted:

| Mutation | Fails |
|---|---|
| Disable the `ctrlc` handler | `exit_paths`: Ctrl-C run hangs and is killed |
| Revert `run_return` + `SystemExit` to tao's `run` | `exit_paths`: stdout loses `EVENT exit` and `AT_EXIT` in both runs |
| Remove the ACL line in `App#route_invoke` | `origin_acl`: both foreign-origin tests |

### Plan 016's "untested without a display" list

- `deliver` and `report_callback_error`: verified (`exit_paths`).
- `SystemExit` to `ControlFlow::ExitWithCode`: verified (status 7).
- `LoopDestroyed` to `RunEvent::Exit` on Ctrl-C: verified.
- `LoopDestroyed` to `RunEvent::Exit` on window close: manual. AppleScript
  could not reach the window from this session (System Events found no
  window for the process), the page cannot close it (wry's UI delegate
  implements no `webViewDidClose:`, so `window.close()` has no handler), and
  Tokra has no native close request. The manual check runs
  `bundle exec ruby test/integration/fixtures/exit_paths/app.rb --wait`,
  closes the window with its close button, and reads `EVENT ready`, the
  `REPORT` line, `EVENT window Tokra::WindowEvent::CloseRequested`,
  `EVENT exit`, and `AT_EXIT`, with status 0.

## Out of scope

- Linux and Windows. The tests are written to run on Linux with a display,
  but only macOS was run. On Windows the pages' hand-built `ipc://localhost`
  and `tokra://foreign.test` URLs need WebView2's `http://<scheme>.<host>`
  forms, and wry adds initialization scripts to subframes there
  (`lib.rs:984`). UNVERIFIED.
- `ExitRequested` and preventing exit. Tauri routes `AppHandle::exit` and the
  last window closing through `RunEvent::ExitRequested`; Tokra raises
  `SystemExit` directly. Unchanged here.
- The Worker Ractor round trip ADR 003 describes (deferred by ADR 009 §4).
- A screenshot in the tests. `screencapture` needs Screen Recording access
  the tests cannot assume, and wry exposes no snapshot API on macOS.

## Risks

- **App Nap.** macOS slows timers in an app whose window is hidden behind
  others. The fixture pages use no timers on their success path, but a
  loaded machine stretched one launch to 20 seconds; the 60-second timeout
  leaves room.
- **Raising `SystemExit` from the native loop** means a caller that rescues
  `Exception` around `App#run` swallows the exit. That is ordinary Ruby
  behavior for `Kernel#exit`, and RDoc says so.
- **Teardown after `run_return`.** Ruby now finalizes the native window and
  webview during its exit instead of the OS reclaiming them mid-loop. No crash
  showed on macOS across repeated runs; Linux and Windows are UNVERIFIED.
- **Exit can now wait on other threads.** `process::exit` ended the process
  at once. Ruby's exit runs `at_exit` hooks and finalizers first, so a hook,
  or a thread it waits on, stuck in a blocking native call could keep the
  process alive after the window closes. UNVERIFIED; no such case was seen.
