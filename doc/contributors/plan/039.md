# Plan 039: Restarting the app

Plan 038 ported `RESTART_EXIT_CODE` and its `prevent_exit` rule, and
deferred `AppHandle::restart` and `AppHandle::request_restart` because
they rest on Tauri's `process` module and its `Env`, and because "the
current binary and its arguments" needs a meaning for a Ruby script. This
plan gives it one and ports both methods.

Sources: Tauri core at `vendor/tauri` (`9f0306fbc`):
`crates/tauri/src/app.rs:540-582` (`restart`, `request_restart`),
`:1304-1311` (the run callback's `Exit` arm restarts once the run event
is out), `:2248-2249` (`Env::default()`, managed at build),
`crates/tauri/src/lib.rs:760-763` (`Manager::env`),
`crates/tauri/src/process.rs:11-133` (`current_binary`, `restart`,
`restart_macos_app`), `crates/tauri/src/manager/mod.rs:218, 320`
(`restart_on_exit`), `crates/tauri-utils/src/lib.rs:262-316` (`Env`),
`crates/tauri-utils/src/platform.rs:172-174` and
`platform/starting_binary.rs:11-80` (the starting binary, cached before
`main`, canonicalized, and refused on macOS when a symlink leads to it).

## How Tauri restarts

`request_restart` sets the manager's `restart_on_exit` flag and asks the
loop to exit with `RESTART_EXIT_CODE`. Handlers hear
`RunEvent::ExitRequested { code: Some(RESTART_EXIT_CODE) }`, and
`prevent_exit` does nothing for that code, so the loop ends. Its `Exit`
arm emits `RunEvent::Exit`, cleans up, and, with the flag set, calls
`process::restart(&env)`. If the request cannot reach the loop, it cleans
up and restarts at once.

`restart` never returns. On the main thread it cleans up and restarts at
once: no `ExitRequested`, no `Exit`. On any other thread it does what
`request_restart` does and then sleeps forever, so the thread never runs
code after the call; the loop ends the process.

`process::restart` takes `current_binary(env)`, spawns it with the
process's arguments after the first (`args_os.skip(1)`), and calls
`exit(0)`. A failed spawn is logged ("failed to restart app: {e}"); a
`current_binary` error skips the spawn silently. Either way the process
ends with 0. The child inherits the parent's working directory, its
environment, and its standard streams, as `Command` does by default.

`current_binary` is the binary the process started from, cached before
`main` and canonicalized; on macOS it is an error if any ancestor of
that path is a symlink. On Linux an `APPIMAGE` path wins. On macOS, a
binary inside `Contents/MacOS` of a bundle is replaced by the bundle's
`CFBundleExecutable`, so an update that renamed the binary still
restarts. `Env::default()` reads `std::env::args_os()` once, at build.

`exit(RESTART_EXIT_CODE)` does not restart: only `restart` and
`request_restart` set the flag.

## Decisions

1. **The current binary is the Ruby interpreter; the script is the first
   argument.** A Ruby app's process is `ruby app.rb args...`: its
   `current_exe` is the interpreter, `RbConfig.ruby`, and its arguments
   after the first are the script and the app's own. `Env#args_os` is that
   command line as Ruby knows it: `[RbConfig.ruby, script, *ARGV]`.
   `Process.restart` runs `current_binary` with `args_os.drop(1)`, as
   Tauri does, so it reruns the same script with the same arguments under
   the same interpreter. The script is expanded to an absolute path, since
   for a Ruby app it is the program, and Tauri's program path is absolute;
   the app's own arguments stay as given, relative paths and all, as
   Tauri's do. Interpreter options such as `-Ilib` are not in the list:
   Ruby keeps no portable record of them (precedence tier 1). Options in
   `RUBYOPT` survive, because the child inherits the environment.

   `RbConfig.ruby` is the interpreter this Ruby was built as, not
   necessarily the executable running now: an app started with
   `rubyw.exe` on Windows restarts under `ruby.exe`, which opens a console
   window, where Tauri's `current_exe` would rerun the same executable.
   Tokra keeps `RbConfig.ruby` for now. The running executable's path
   often passes through a symlink on macOS (Homebrew's `opt/ruby`), which
   decision 6's refusal would reject, so switching trades a Windows
   console for macOS restarts that silently do nothing. The RDoc of
   `Process.current_binary` says so.

   Follow-up: Rust's `std::env::args_os()`, read from the extension, may
   recover the interpreter's own options and its real `argv[0]`.
   UNVERIFIED: whether Ruby's `$0=` overwrites the `argv` memory that
   `args_os` reads on each platform, which would make it no more reliable
   than the Ruby snapshot.

2. **The arguments are captured when Tokra loads.** Tauri's `args_os`
   comes from the operating system and nothing can change it. Ruby's
   `ARGV` and `$PROGRAM_NAME` are mutable, and an app often parses `ARGV`
   with `OptionParser#parse!` before it builds. Tokra snapshots `$0` and
   `ARGV` when `tokra/env.rb` loads, the counterpart of the starting
   binary cached before `main`, and `Env.default` reads the snapshot. An
   app that requires Tokra after it changed `ARGV` restarts with what it
   left.

3. **Spawn, then exit 0, as Tauri does.** `Process.restart` calls
   `::Process.spawn(binary, *args)` and `Kernel.exit(0)`. The child
   inherits the working directory at restart time, the environment
   (Bundler's `BUNDLE_GEMFILE` and `RUBYOPT=-rbundler/setup` among it, so
   it loads the same gems), and the standard streams. `Kernel.exec` would
   keep the pid, but it replaces the process without running `at_exit`
   or `ensure`, and on Windows Ruby's `exec` spawns a child and exits
   anyway. `Kernel.exit` instead of `exit!` keeps Plan 018's rule that
   the process ends the Ruby way, flushing its output.

4. **The restart follows `RunEvent::Exit`, and its exit counts.** Tokra's
   `LoopDestroyedEvent` branch emits `RunEvent::Exit` and then restarts
   when the flag is set, as Tauri's `Exit` arm does. The restart raises
   `SystemExit` from that last callback. The native loop used to report a
   `SystemExit` there by setting a control flow nobody read again, so the
   process ended with the loop's code, 255 for a restart. Now a
   `SystemExit` raised while delivering `LoopDestroyedEvent` replaces the
   status `EventLoop#run` raises, as an `exit` in an `ensure` clause
   replaces the exception in flight. This also fixes an app's own
   `Kernel#exit` in a `RunEvent::Exit` handler.

5. **`restart` on the main thread raises `SystemExit` like any exit.**
   Tauri's `process::exit` ends the process inside the callback. Tokra's
   `Kernel.exit(0)` unwinds instead (Plan 018), so inside the loop it ends
   the loop and `RunEvent::Exit` still arrives, as for any `Kernel#exit`
   in a handler; before the loop, it propagates from `App#run`. No
   `ExitRequested` fires on either path, as in Tauri. The flag is not
   set, so the loop's end does not restart a second time.

6. **macOS refuses an interpreter reached through a symlink.** Tauri's
   default is the safe one, and its
   `process-relaunch-dangerous-allow-symlink-macos` feature exists to
   weaken it. Tokra ports the default: on macOS, `current_binary` raises
   `Error::Io` with Tauri's message when an ancestor of `RbConfig.ruby` is
   a symlink, and `restart` then exits 0 without spawning, as Tauri does.
   Reading AGENTS.md's "a feature Tauri gates behind a Cargo feature is
   simply supported" as "always on" would turn a dangerous opt-out on for
   everyone. The maintainer decided (2026-10-28) to keep the safe default
   and not expose the opt-out, and recorded the rule as an amendment to
   ADR 011's Cargo-feature row and in AGENTS.md: an additive feature is
   built in; one that relaxes a safety default stays off, and if ever
   exposed becomes a code-level opt-in named after the feature, off by
   default, never an environment variable. mise records
   the real install path in `RbConfig.ruby`, so the refusal does not trip
   on this machine; other installers are UNVERIFIED.

7. **`exit(RESTART_EXIT_CODE)` still just exits.** Tauri restarts only
   when `restart` or `request_restart` set the flag, so an exit with that
   code ends the app. Tokra keeps Plan 038's status, 255, the low byte of
   `i32::MAX` (Plan 038, decision 5). Plan 038's note that restart would
   change this read more into Tauri than the source holds.

8. **`Tokra::Process` mirrors `tauri::process`.** Inside `module Tokra`,
   a bare `Process` now names Tokra's module, so Tokra's own code writes
   `::Process` for Ruby's and `Tokra::Process` for its own. Decided
   2026-10-28, after Ferro's guardrail for `Ferro::Time`: RuboCop's
   `Lint/ConstantResolution` with `Only: [Process]` refuses a bare
   `Process` in `lib/` and every plugin's `lib/`, and
   `test/tasks/test_top_level_constants.rb` refuses one in the signatures,
   which RuboCop does not read. AGENTS.md's Ruby section records the rule.

9. **Only a restart that ends the loop restarts after it.** Tauri's `Exit`
   arm restarts when `restart_on_exit` is set, but a handler that calls
   `restart` on the main thread, or `process::exit`, ends the process
   before the arm runs (`process.rs:84`). Tokra's exits unwind, so the
   loop still ends and `RunEvent::Exit` still arrives; restarting there on
   the flag alone started two processes. `App` notes a pending restart
   only when the handlers of `ExitRequested(RESTART_EXIT_CODE)` returned
   with the flag set, so the loop ended for the restart; an exit raised
   inside them skips it. `AppHandle#restart` on the main thread also
   clears the flag before it restarts. The flag stays on `AppHandle`, not
   on `AppManager` as Tauri's does (`manager/mod.rs:218`): `AppManager` is
   a `Data` value and cannot hold a flag that changes.

10. **A restart refuses an app with no script file.** Run with `ruby -e`
    or from standard input, `$0` is `-e` or `-`, and rerunning
    `args_os.drop(1)` would run an argument as code or wait on standard
    input. `Process.restart` raises `Error::Io` ("the app's script is not
    a file: ...") inside its spawn rescue, so it is reported to
    `$stderr` as "failed to restart app: ...", as a failed spawn is, and
    the process still exits 0. Tauri has no such case: its binary is the
    program.

## Verification

- Stub-native tests (`test/builder/test_restart.rb`) with
  `::Process.spawn` stubbed: `request_restart` emits
  `ExitRequested(RESTART_EXIT_CODE)`, ignores `prevent_exit`, emits
  `Exit`, then spawns `[ruby, script, *args]` and exits 0; `restart` on
  the main thread spawns with no `ExitRequested` and no `Exit`;
  `restart` from a thread asks to exit and the loop's end restarts;
  `request_restart` before `run` waits for the loop; after the loop it
  restarts at once; a failed spawn is reported and still exits 0; a plain
  `exit(RESTART_EXIT_CODE)` spawns nothing.
- Unit tests for `Env` (the snapshot survives `ARGV.replace`) and
  `Process.current_binary` (canonical interpreter; the macOS symlink
  refusal; a script that is not a file).
- A real process (`test/integration/restart_test.rb`, no page, so it runs
  on Windows too): the fixture restarts through `request_restart`, then
  `restart` from a thread, then `restart` on the main thread, then
  exits. Each run logs its arguments, `ARGV` after `OptionParser#parse!`,
  its working directory, and Bundler's presence; the test checks four
  runs with the same of each, the first process ending with 0, and the
  events each run heard, with one logged spawn per restart. Two more
  cases: `restart` inside the handler of the exit request that
  `request_restart` caused starts one process, not two, and `exit(3)`
  there ends the app with 3 and no restart.
- Mutation checks by hand, recorded under Results.

## Out of scope

- Packaged apps. `restart_macos_app` replaces a binary inside a bundle's
  `Contents/MacOS` with the bundle's `CFBundleExecutable`, and on Linux
  an `APPIMAGE` path replaces the binary. A Tokra app is a Ruby script
  until a packager (Fledge, or another) decides how a bundle launches
  Ruby, and that launcher decides what restarting it means: spawning the
  bundle's executable with the script as an argument would be wrong.
  `Env` has no `appimage` or `appdir` until then.
- `cleanup_before_exit`, as in Plan 038.

## Risks

- A spawned child shares the parent's process group and terminal, as
  Tauri's does: a Ctrl-C meant for the old process reaches the new one if
  it arrives late.
