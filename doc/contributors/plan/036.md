# Plan 036: Error::Io speaks std::io::Error

Plan 027 made `Tokra::Error::Io` Tauri's `Error::Io`, displayed as
`#[error("{0}")]`, but left its text Ruby's (its Follow-ups): a missing
file read as <tt>No such file or directory @ rb_sysopen - PATH</tt>, where
Tauri sends <tt>No such file or directory (os error 2)</tt>. That message
reaches the frontend through the image plugin's `from_path` and through
`JsImage#into_img`, which clipboard's `write_image` calls.

Sources: Tauri core at `vendor/tauri` (`9f0306fbc`):
`crates/tauri/src/image/mod.rs:91-97` (`from_path` calls
`std::fs::read(path)?`), `error.rs:53-54` (`Io(#[from] std::io::Error)`).
Rust at `d8ef4f3fe` (`/Users/kerrick/Developer/rust`):
`library/core/src/io/error.rs:520-531` (Display: an OS error is
`{detail} (os error {code})`, a simple message is the message itself),
`library/std/src/sys/io/error/unix.rs:196-229` (`strerror_r`),
`library/std/src/sys/io/error/windows.rs:98-143` (`FormatMessageW` with
`FORMAT_MESSAGE_FROM_SYSTEM | FORMAT_MESSAGE_IGNORE_INSERTS`, trailing
whitespace trimmed), `library/std/src/fs.rs:353-362` (`fs::read`),
`library/std/src/sys/fs/windows.rs:314` (no `FILE_FLAG_BACKUP_SEMANTICS`
by default). magnus `2370a35`: `src/try_convert.rs:335-355` (`PathBuf`
goes through `rb_get_path`).

## Where Tokra surfaces an io::Error

Tauri's core builds `Error::Io` from `std::fs::read` in
`Image::from_path`, and `?` reaches it from `scope/fs.rs` and
`path/plugin.rs` (`CurrentDir`), neither of which Tokra ports.
`protocol/asset.rs` maps the io::Error to a status code and sends no
text. In Tokra, `Image.from_path` is the only place that turns an OS
error into a message: the image plugin, `JsImage#into_img`, and clipboard
all reach the OS through it. The log plugin's `FileUtils.mkdir_p` raises
Ruby's `SystemCallError` during setup, where plugin-log's `create_dir_all`
would fail setup with its own `Error::Io`; that is the log plugin's error
type, not core's, and stays out of scope.

## Fidelity audit

Measured on macOS with rustc 1.99.1 against `std::fs::read`:

| Case | Rust (Unix) | Rust (Windows) | Ruby before |
|---|---|---|---|
| Missing file | No such file or directory (os error 2) | The system cannot find the file specified. (os error 2) | No such file or directory @ rb_sysopen - PATH |
| Directory | Is a directory (os error 21) | Access is denied. (os error 5) | Is a directory @ io_fread - PATH (Windows: Permission denied @ rb_sysopen - PATH) |
| No read permission | Permission denied (os error 13) | n/a | Permission denied @ rb_sysopen - PATH |
| NUL byte | file name contained an unexpected NUL byte | strings passed to WinAPI cannot contain NULs | Rust's text, by a Ruby check (plan 027) |

## Decisions

1. **std reads the file when Ruby cannot.** On Unix the text is only formatting: Ruby's
   `SystemCallError` message starts with `strerror(errno)`, the same text
   std's `strerror_r` gives, and `errno` is the code. On Windows it is not:
   Ruby maps the Win32 error to a POSIX errno (`rb_w32_map_errno`) before
   it raises, and keeps no copy of the original. `GetLastError` after the
   fact is not sound, since Ruby makes other system calls while it raises.
   So the code Rust formats is gone by the time Ruby can see it. Tauri
   calls `std::fs::read`, so `Tokra::Native.fs_read` calls it too and
   raises `RuntimeError` with the io::Error's Display, as
   `image_from_bytes` raises with the image error's. That is a thin
   binding under ADR 005: one std call, no logic, and every case above,
   NUL bytes included, gets std's own text on every OS. Ruby rescues it
   into `Error::Io`. Ruby still reads first (decision 3); std reads only
   after Ruby's read fails.

2. **The path keeps its bytes.** magnus's `PathBuf` conversion calls
   `rb_get_path`, which raises `ArgumentError` for a NUL byte before std
   sees the path. `fs_read` takes the string instead: its bytes as an
   `OsString` on Unix, UTF-8 on Windows, where std encodes paths as
   UTF-16. So plan 027's `NUL_IN_PATH` check goes, and std reports NUL
   bytes itself.

3. **Ruby reads; std retries a failure.** Tauri's synchronous command
   blocks only its own thread. In Tokra the main thread runs the event
   loop and takes the GVL at every hand-off, so a read holding it would
   freeze every window while it lasts (a FIFO, `/dev/stdin`, a slow
   network file system), against ADR 001 and ADR 012. A read without the
   GVL in Rust would fix that, but std retries a call the OS interrupts
   (`cvt_r` in `File::open`, `Interrupted` in `default_read_to_end`), so
   no unblocking function could end it, and `Thread#raise`, Ctrl-C, and
   `Timeout` would wait for it, where they end a blocked `File.binread`
   (measured on this Mac, in both `open` and `read`).

   So `Image.read` reads with `File.binread` as before: Ruby's IO
   releases the GVL and stays interruptible. Only when it fails
   (`SystemCallError`, or `ArgumentError` for a NUL byte) does
   `Native.fs_read` read again, to obtain std's text. If std's read
   succeeds, because the file appeared between the two, its bytes are the
   result, as Tauri's single read would have read them. So the error path
   opens the file twice where Tauri opens it once, a benign
   time-of-check difference: each answer is one a single read could have
   given.

   `fs_read` still releases the GVL, since a failing open on a slow
   network file system can block too. It builds the `PathBuf` with the
   GVL held, runs only `std::fs::read` in an `extern "C"` function under
   `catch_unwind`, and builds the Ruby string or raises after the GVL is
   back. It uses `rb_thread_call_without_gvl2`, not
   `rb_thread_call_without_gvl`, which checks interrupts on return and
   could `longjmp` across the Rust frame (`thread.c:1636-1638` at Ruby
   v4.0.1), with ferro-rfd's retry loop: a try Ruby skips for a pending
   interrupt runs that interrupt through magnus's protected
   `thread_check_ints`, and after three skips the read runs with the GVL
   held. It has no unblocking function, so that retry alone is
   uninterruptible (`thread.c:1677-1679`); it runs only after a failure.

4. **Any `to_path`.** Tauri's `from_path` takes `impl AsRef<Path>`, so
   `Image.from_path` takes a String or anything with `to_path`, such as a
   Pathname, and hands its path to `fs_read`.

5. **`RuntimeError` stays the native signal.** `fs_read` raises
   `RuntimeError` only for std's error, as `image_from_bytes` does for
   its own: a panic resumes into magnus, which raises it as a `fatal`
   error, and a bad Windows encoding raises `EncodingError`. A dedicated
   native class would need its own definition and RBS for one rescue.

## Steps

1. Tests first: `test/test_image.rb` asserts Rust's exact text for a
   missing file, a directory, and (Unix, non-root) an unreadable file;
   the image plugin and clipboard assert it for a missing file. Windows
   expectations are the `FormatMessageW` text, checked by CI.
2. `ext/tokra/src/fs.rs`: `Native.fs_read`, reading with the GVL
   released, with Rust tests of its retry loop. `Image.read` reads with
   `File.binread` and, when that fails, with `fs_read`, rescuing its
   `RuntimeError` into `Error::Io`; `NUL_IN_PATH` goes.
3. FIFO tests, in a child Ruby so a deadlock or a hang is a failure, not
   a stuck suite, and skipped on Windows, which has no FIFOs: a reader
   thread opens a FIFO that only the main thread writes, through
   `from_path` and through `Native.fs_read`, so the write happening at
   all proves the GVL was released; and `Thread#raise` ends a `from_path`
   blocked on a FIFO nothing writes.
4. RBS, RDoc on `Image.from_path` and `Error::Io`, CHANGELOG, and plan
   027's Follow-ups.

## Results

Every step is done. The message assertions failed against `File.binread`
alone. Mutations, each restored: removing the std retry brought Ruby's
messages back (<tt>No such file or directory @ rb_sysopen - PATH</tt>);
reading the success path with `fs_read` made the `Thread#raise` child
never finish; running `fs_read`'s read with the GVL held (`Read::run` in
place of `release_and_run`) deadlocked its FIFO child; removing
`std_read`'s rescue failed seven tests with `RuntimeError`; sending
`e.kind()` in place of the Display failed six; converting the path with
magnus's `PathBuf` failed the NUL-byte tests with `ArgumentError`;
dropping `to_path` failed the Pathname test with `TypeError`. The Windows
strings are checked by CI only.

The clean gate passed: Rust 43 tests, core 672 runs and 2080 assertions
with 0 failures and 5 skips, every plugin suite green, and no RuboCop,
Steep, or Clippy finding.
