# Plan 041: The window items plan 040 deferred

Plan 040 ported every window getter and setter that is a thin call into
tao and deferred the rest, each with a reason. This plan takes up the
deferred rows whose reason was "Tauri code of its own" or "needs a type
Tokra lacks": `is_enabled` and `set_enabled`, `cursor_position` and the
`AppHandle` monitor getters, `set_size_constraints`, `set_icon`,
`set_background_color`, `set_shadow`, and the Windows undecorated
resizing that plan 040's decision 8 left out of `set_resizable` and
`set_decorations`. Menus, tray icons, effects, child webviews, and the
other "out of scope" rows stay where plan 040 put them.

## Decisions

1. **The event loop's window target answers on the main thread.** Tauri
   reads `primary_monitor`, `monitor_from_point`, and
   `available_monitors` from the runtime context's window target on the
   calling thread, and sends `cursor_position` to the loop as a message.
   Tokra's native objects answer only the main thread (ADR 012), so all
   four go through `RuntimeContext#getter`, as `AppHandle#display_handle`
   does. tao lends its window target only to the run callback, so
   `Native::EventLoop` answers from the target it holds before it runs
   and, while it runs, from the one tao passed the callback, which the
   loop lends for exactly that call; once the loop has ended it answers
   `nil`, and the getter raises "failed to receive message from webview".
   To make the target exist when the setup hook runs, as Tauri's runtime
   does, `App#run` builds the event loop before calling the hook. Before
   `App#run` no event loop exists, so these raise the same error
   (Tauri's never fail; tier 1, ADR 012). `RuntimeContext` holds the
   target, as Tauri's `Context` holds `main_thread.window_target`.
   `Window#cursor_position` asks its app handle, as Tauri's does. A tao
   error raises `Error::Runtime` "failed to get cursor position".

2. **`Color` is a `Data` of four bytes.** Tauri's `Color(u8, u8, u8, u8)`
   is a tuple struct; Ruby's `Data` needs names, so Tokra's members are
   `red`, `green`, `blue`, and `alpha`, the names Tauri's own object form
   deserializes (tier 1). A member that is not an Integer from 0 to 255
   raises `RangeError` or `TypeError`, where Rust would not compile.
   `Color.from_str` is Tauri's `FromStr`, with its error texts. Tauri's
   `Window::set_background_color` colors only the window; its
   `WebviewWindow` colors the window and then the webview. Tokra has no
   `WebviewWindow`, so it ports `Webview#set_background_color` as well,
   and an app that wants Tauri's `WebviewWindow` behavior calls both.
   wry does not implement it on macOS, so there it does nothing.

3. **Pixel units are `Data` like the other dpi values.** dpi's
   `LogicalUnit(f64)` and `PhysicalUnit(i32)` are tuple structs; Tokra's
   hold their number as `value` and convert as dpi does. `PixelUnit` is
   translated the way plan 040 translated `Size`: a constraint takes a
   `LogicalUnit` or a `PhysicalUnit` (tier 1), and anything else raises
   `TypeError` on the caller's thread. `WindowSizeConstraints` has
   Tauri's four fields, each `nil` by default as Tauri's `Default`.
   dpi's `MAX`, `MIN`, and `ZERO` constants come along as dpi defines
   them, which includes `PhysicalUnit::MAX` being a `LogicalUnit`.

4. **An icon is built on the caller's thread.** Tauri converts the
   `Image` before it sends the message, so a bad image fails the call.
   `Native::Icon.from_rgba` builds tao's `Icon` on any thread (tao's
   `Icon` is `Send` on every platform); `Window#set_icon` raises
   `Error::Runtime` "invalid icon: …" with tao's `BadIcon` text, then
   sends the icon. On Linux tao checks nothing and GTK's
   `Pixbuf::from_mut_slice` panics on the main thread for a buffer
   shorter than the image, which would end Ruby's VM; Tokra checks the
   buffer there with tao's own `RgbaIcon` rules, so Linux raises what
   macOS and Windows raise. tao ignores icons on macOS.

5. **Undecorated resizing is Tauri's module, ported whole.** On Windows
   Tauri covers an undecorated resizable window with a child window
   whose region is only the frame, answers its hit tests as resize
   borders, and attaches or detaches it as `set_resizable`,
   `set_decorations`, and `set_shadow` change, and when the window
   content's webview is created; on Linux it connects button and touch
   handlers to that webview, which begin a resize drag at an undecorated
   window's edges. Tokra ports both halves, with `hit_test` shared and
   unit-tested in Rust. `once_cell::Lazy` becomes `std::sync::LazyLock`
   (tier 1); the Linux handler's `downcast().unwrap()` becomes an
   `if let`, since a panic in a GTK callback would end the VM. Two of
   Tauri's quirks are kept as they are, each with a comment: the drag
   window posts the address of a `POINTS` as `WM_NCLBUTTONDOWN`'s
   `lparam`, and `update_drag_hwnd_rgn_for_undecorated` sends the shadow
   flag in `lparam` while both procedures read it from `wparam`
   (`undecorated_resizing.rs:222-225`, `385-388`, `458-472`), so they
   always store `false`; the region it sets first does follow the flag.

6. **`set_enabled` follows Tauri's three platforms.** On macOS it builds
   the sheet with `objc2-app-kit`'s `NSWindow`, which needs that crate's
   `NSGraphics`, `NSApplication`, `objc2-core-foundation`, and `block2`
   features, as tauri-runtime-wry enables them; `block2` joins
   `objc2-app-kit`'s locked dependencies. Tauri panics if it is not on
   the main thread; Tokra's native window already refuses other threads
   with `ThreadError`, so the main-thread marker always exists there.
   One deviation: objc2-app-kit requires a window made outside a window
   controller not to release itself when closed (objc2-app-kit 0.3.2
   `src/lib.rs:15-20`), or AppKit's release on close and the
   `Retained`'s own would release the sheet twice. Tauri omits it
   (`window/macos.rs:17-27`); Tokra calls `setReleasedWhenClosed(false)`
   before attaching the sheet, which no caller can observe except as a
   crash that cannot happen.

## Verification

- Stub-native unit tests: each new getter's value, each setter's
  arguments as the native window receives them, closed windows, the
  argument errors, the icon's failure path, the event loop's answers
  before, during, and after the run, and the value types' conversions.
- Real-extension tests (`test/native/`): a closed window ignores the new
  setters and answers `nil`; an open one answers `is_enabled`; the event
  loop answers its monitors and cursor before it runs; `Native::Icon`
  raises tao's texts; a bad color component or constraint raises.
- Real window (`window_state` fixture, Prohibited policy, no focus):
  `set_enabled` read back through `is_enabled`; size constraints read
  back through AppKit's content limits on macOS, and through tao's
  inner size after a smaller resize: held to the minimum on Linux, as
  asked elsewhere; `set_shadow` read back through AppKit's
  `hasShadow`; the app handle's monitors equal the window's;
  `cursor_position` answers a position; `set_icon`,
  `set_background_color` and `Webview#set_background_color` run without
  error.
- Rust unit tests: `hit_test`, the Linux icon guard.
- Mutation checks by hand, recorded under Results.

Untested without a person at the screen: the Windows and Linux resize
drags themselves (they need a pressed mouse button over the window's
edge), how a disabled window refuses input, and the icon and background
color as a person sees them.

## Out of scope

Plan 040's "out of scope" rows; `WebviewWindow`; Tauri's creation-time
window background drawing with softbuffer on Windows (`draw_surface`),
which follows the window builder's color and not `set_background_color`.

## Risks

- `beginSheet:` on a window of a Prohibited app must not bring it to the
  front; the frontmost guard checks it.
- The Windows code cannot be built here: it is checked with Clippy for
  `x86_64-pc-windows-gnu` in a scratch crate, as plan 040's was. The
  Linux code is built, Clippied, and run under Xvfb in a Debian
  container with CI's packages.

## Results

Every item above is done; nothing in scope was deferred. The clean-build
gate passed on macOS with zero errors and zero warnings (core suite 859
runs, 2961 assertions, 0 failures, 0 errors, 6 skips), and
`package:install` built every gem from its package.

Two translations the gate forced: `Color` and `WindowSizeConstraints`
validate in `initialize`, which Steep checks against `Data#initialize`
and rejects, so each carries `# steep:ignore MethodParameterMismatch`
while its signature declares `self.new`, as AGENTS.md asks; and RDoc
needs `##` before the first constant in `Color`'s body.

Linux: in a `ruby:4.0.9` Debian container with CI's packages the
extension built and passed Clippy with `-D warnings` (after removing two
unused GDK imports the first run found), its Rust tests passed, and under
Xvfb the new stub, native, and real-window tests passed: `set_enabled`
reads back through GTK's sensitivity, a minimum width holds a smaller
size, and the app handle's monitors equal the window's, from another
thread and from the main one. Windows: the `WindowExt` functions, the
resize hooks, and the whole `undecorated_resizing` module passed Clippy
for `x86_64-pc-windows-gnu` with the crate's lints in a scratch crate
with the same tao, wry, and `windows` versions and features; nothing of
it has run on Windows.

CI then failed the minimum-width check on macOS and Windows, which a
race had hidden here: at this Mac's scale factor of 2 the window was
narrower than the new minimum, so tao grew it at once
(`platform_impl/macos/window.rs:1752-1763`), and the fixture read that
before the later resize landed. Only GTK holds a resize Tokra asks for to
the minimum, through geometry hints (`platform_impl/linux/util.rs:40`). On
macOS tao resizes with `setContentSize` (`macos/util/async.rs:87-92`),
which AppKit's minimum does not limit, and on Windows tao answers
`WM_WINDOWPOSCHANGING` itself (`windows/event_loop.rs:1151-1236`), so
the minimum `WM_GETMINMAXINFO` gives (`:1861-1889`) bounds only a
person's drag. Tauri adds nothing (`lib.rs:3404-3411`). The fixture now
waits for each platform's own answer: the minimum on Linux, the size
asked for elsewhere.

Mutations checked by hand, each failing the named test and then
restored: in Ruby, the cursor's failure raise removed
(`test_a_cursor_the_platform_cannot_read_raises_failed_to_get_cursor_position`),
a unit's kind swapped (`test_size_constraints_reach_tao_limit_by_limit`),
`App#run` not handing over the window target
(`test_the_setup_hook_and_the_run_callback_can_ask`), the "invalid icon: "
prefix dropped
(`test_an_image_that_does_not_fill_its_size_raises_invalid_icon_and_sends_nothing`),
the webview's failure no longer logged
(`test_a_webview_background_color_wry_refuses_is_logged`), and
`Color.from_str` trimming text without a `#`
(`test_from_str_trims_only_around_a_hash`); in Rust, against the real
window, macOS `is_enabled` asking for a sheet instead of none
(`test_set_enabled_reads_back_through_is_enabled`), the loop not lending
its target (every `window_state_test` check: the fixture's first app
handle getter raised), `pixel_unit` swapping logical and physical
(`test_size_constraints_reach_appkit`; the minimum-width check that
also failed then did so only through the race described above), and
`set_has_shadow` inverted (`test_set_shadow_reaches_appkit`).
