# Plan 040: Window getters and setters

Plans 018, 020, and 022 deferred the Tauri getters and setters Tokra had
not ported: Plan 020 ported `Window#title` and the getter machinery
(`RuntimeContext#getter`) and said each other getter "lands through
`RuntimeContext` when it does"; Plan 022 listed them again as a follow-up
none of its work took up. This plan takes the inventory first, then ports
every window getter and setter that is a thin call into tao, with the dpi
value types they speak in, and defers the rest with a reason for each.

### Webview

Tokra's `Webview` has `label`, `window`, `eval`, and `run_on_main_thread`,
and Tokra has no `WebviewWindow`: each window holds one webview that fills
it. Tauri's `Webview` getters and setters (`url`, `navigate`, `reload`,
`position`, `size`, `bounds`, `set_size`, `set_position`, `set_bounds`,
`set_focus`, `show`, `hide`, `reparent`, `set_auto_resize`, `set_zoom`,
`set_background_color`, `print`, `open_devtools`, `close_devtools`,
`is_devtools_open`, `clear_all_browsing_data`, `cookies`,
`cookies_for_url`, `set_cookie`, `delete_cookie`, `with_webview`) are all
missing and all deferred: they are wry calls, not tao calls, and several
(`position`, `bounds`, `reparent`, `set_auto_resize`) mean something only
for child webviews, which Tokra lacks. `WebviewWindow`'s methods delegate
to the window and the webview, so the window half arrives with this plan.

## Decisions

1. **dpi values are `Data` with Tauri's names.** `LogicalPosition` and
   `PhysicalPosition` have `x` and `y`; `LogicalSize` and `PhysicalSize`
   have `width` and `height`; `PhysicalRect` has `position` and `size`.
   Each converts the way the dpi crate does: `to_physical(scale_factor)`
   multiplies, `to_logical(scale_factor)` divides, and `from_logical` and
   `from_physical` build from the other kind. Ruby has no type parameter
   to pick the pixel type, so a conversion keeps the Float it computed,
   which is dpi's answer for `f64`; a caller that wants dpi's `u32` or
   `i32` rounds it (precedence tier 1). A scale factor dpi rejects
   (`validate_scale_factor`: not positive, or not normal) panics there
   with `assertion failed: validate_scale_factor(scale_factor)`; here it
   raises `ArgumentError` with the same text.

2. **A setter takes either kind of position or size.** Rust's
   `Into<Size>` and `Into<Position>` let a caller pass a logical or a
   physical value; Ruby has no conversion traits, so `set_size`,
   `set_min_size`, `set_max_size`, `set_position`, and
   `set_cursor_position` take a `LogicalSize` or `PhysicalSize`
   (`LogicalPosition` or `PhysicalPosition`), and anything else raises
   `TypeError` on the caller's thread, where Rust would not compile
   (tier 1). `set_min_size` and `set_max_size` take `nil` too, for
   Tauri's `None`. This replaces `Window#set_size(width, height)`, which
   only took logical pixels; `Tokra::Window` has not been released, so
   no released API breaks. `Native::Window#set_size(width, height)`,
   which `App` and the examples call, is unchanged.

3. **Getters go through `RuntimeContext#getter`, setters through
   `run_on_main_thread`.** Each getter is a `window_getter!` in Tauri, a
   message the loop answers on the main thread; each setter is a message
   sent without waiting. Tokra's existing `title` and `set_title` are the
   pattern, and every new method follows it. A closed window answers a
   getter with nothing, as Plan 038 decided for `title`, and the getter
   raises `Error::Runtime` "failed to receive message from webview", the
   channel Tauri's runtime drops unanswered (`lib.rs:3244-3250`). A
   closed window ignores setters. `inner_position` and `outer_position`
   map tao's `NotSupportedError` to "failed to send message to the
   webview", as Tauri's handler does (`lib.rs:3261-3276`).

4. **`Monitor` is a `Data` of what the runtime copies.** Tauri's
   `Monitor` holds `name`, `size`, `position`, `work_area`, and
   `scale_factor`, copied from tao's `MonitorHandle` at the moment of
   asking; Tokra's holds the same five, read on the main thread. The
   native window answers each monitor as a plain Array, and Ruby builds
   the values. tao has no work area, so Tauri reads it itself
   (`tauri-runtime-wry/src/monitor/`): `-[NSScreen visibleFrame]` on
   macOS (moving the position right by the frame's left inset and leaving
   its top alone, as Tauri does), the GDK monitor's work area on Linux,
   and `GetMonitorInfoW`'s `rcWork` on Windows. Tokra ports each, which
   makes `objc2`, `gtk`, and `windows` direct dependencies at the versions
   and features tao already locks. One deviation: tao hands out the
   `NSScreen` with a retain the caller owns (`Retained::into_raw`), which
   Tauri's reference never releases; Tokra takes it back with
   `Retained::from_raw` so it is released, which no caller can observe
   except as memory that is no longer leaked.

5. **Closed enums are `Data` constants, as `ActivationPolicy` is.**
   `Theme` (`Light`, `Dark`), `CursorIcon` (Tauri's 35 names),
   `UserAttentionType` (`Critical`, `Informational`), and
   `ResizeDirection` (eight) each have a `name` and private `new`. The
   native layer takes and gives the name and matches it to tao's
   variant; a tao theme Tauri does not know reads as `Light`, as
   `map_theme` does. `set_theme(nil)` follows the system, as Tauri's
   `None` does.

6. **`inner_size` on macOS reads the webview.** wry makes its own view
   the window's content view (`wkwebview/mod.rs:616-636`), so the view
   tao measures stops following the window; Tauri reads the first
   webview's frame instead, when the window has no child webviews
   (`lib.rs:5195-5212`). Tokra's windows never have children, so on
   macOS `Window#inner_size` hands the native window its webview, and the
   native window reads that webview's frame and scales it as Tauri does.
   Elsewhere, or once the webview is closed, it asks tao.

7. **Results the runtime drops stay dropped.** tao's `set_cursor_grab`,
   `set_cursor_position`, `drag_window`, `drag_resize_window`,
   `set_skip_taskbar`, and macOS's `set_simple_fullscreen` return a
   result Tauri's handler discards (`lib.rs:3438-3478`), so these setters
   return `nil` and raise nothing for it.

8. **No Windows undecorated-resizing.** On Windows Tauri's
   `SetResizable` and `SetDecorations` handlers also attach or detach its
   own hit-test for undecorated windows (`undecorated_resizing`), which is
   Tauri code over Win32, not tao. Tokra calls tao alone, so an
   undecorated resizable window on Windows cannot be resized by its edges
   until that module is ported. Recorded here and in the RDoc of both.

9. **`center` comes with the work area; the rest of `WindowExt` and the
   event-loop target wait.** `center`, `set_enabled`, and `is_enabled`
   have no tao call: Tauri's `WindowExt` implements them with AppKit, GTK,
   and Win32 code of its own (`window/macos.rs`, `linux.rs`,
   `windows.rs`). `center` needs only the work area of decision 4 and one
   more call per platform (`-[NSWindow center]`, tao's
   `set_outer_position`, and `DwmGetWindowAttribute` for a decorated
   window's height on Windows), so it is ported. `set_enabled` on macOS
   builds and attaches a sheet window, and on Linux needs GTK's
   sensitivity, a separate small port with its own tests of what a
   disabled window refuses. `cursor_position` is an `AppHandle` getter
   answered by the event-loop target, with its own error
   (`FailedToGetCursorPosition`); it belongs with `AppHandle`'s
   `primary_monitor`, `available_monitors`, and `monitor_from_point`,
   which Tokra does not have either.

## Verification

- Unit tests through the stub native (`test/test_window_state.rb`,
  `test/test_dpi.rb`): each getter's value and type, each setter's
  arguments as the native window receives them, closed windows, getters
  and setters from another thread inside a running app, the webview
  `inner_size` hands the native window, argument errors, and the dpi
  conversions and enums.
- The real extension in process (`test/native/test_closed_window.rb`):
  a closed native window ignores every new setter and answers `nil` to
  every new getter; an open one answers each getter in the shape Ruby
  reads; a name an enum lacks raises `ArgumentError`; another thread gets
  `ThreadError`.
- A real window (`test/integration/window_state_test.rb`, fixture
  `window_state`, Prohibited policy, no page, so it runs on Windows too):
  the fixture sets each state through `Tokra::Window`, from the main
  thread and from another, and reads back what tao reports: size and
  position in both kinds, min and max sizes, resizable, maximizable,
  minimizable, closable, decorations, always on top, visibility, the
  theme it set, `center` against the work area, the monitors, and the
  scale factor's agreement with the monitor's; on macOS also AppKit's
  content minimum and maximum, and on Windows maximizing. It never calls
  `set_focus`; the frontmost guard checks the app never comes to the
  front.
- Mutation checks by hand, recorded under Results.

Untested without a person at the screen: the cursor setters (grab,
visibility, icon, position), `start_dragging` and
`start_resize_dragging` (they need a pressed mouse button),
`request_user_attention`, `set_content_protected`, and
`set_visible_on_all_workspaces`; each is a single tao call checked in
the stub tests for its arguments and in the native tests for a closed
window. `set_fullscreen`, `set_simple_fullscreen`, `minimize`, and
`set_focus` are not run against a real window anywhere: on macOS they
move the window to another Space, animate it into the Dock, or would
bring the app to the front, and on Linux CI has no window manager to
grant them. `maximize` runs against a real window on Windows only, for
the same reasons.

## Risks

- tao applies many macOS setters asynchronously (`util/async.rs`), so a
  getter right after a setter can read the old state, in Tauri as here.
  The real-window fixture reads until the state settles or two seconds
  pass.
- Window managers on Linux may refuse or delay some requests (always on
  top, decorations, position); the real-window test checks what tao
  reports, and skips a check the platform documents as unsupported. CI
  runs Xvfb with no window manager, so the fixture does not maximize
  there.
- The Linux and Windows halves of the work area and `center` cannot be
  built on the macOS machine this plan was written on. The Windows code
  passed Clippy for `x86_64-pc-windows-gnu` in a scratch crate with the
  same tao and `windows` versions. The extension was built and Clippied
  for Linux in a Debian container with CI's packages, and the new unit,
  native, and real-window tests passed there under Xvfb. That run showed
  two things tao cannot report there: tao 0.34.5 has no maximize or
  minimize button setting on Linux and always answers `true`
  (`platform_impl/linux/window.rs:614-616`, `663-669`), and it learns
  always-on-top only from a window manager's `window-state-event`
  (`:368-378`), which Xvfb alone never sends. The real-window test
  expects the first and skips the second on Linux.

## Results

Every item above is done or deferred with its reason in the inventory.
The clean-build gate passed on macOS with zero errors and zero warnings
(core suite 807 runs, 2785 assertions, 0 failures, 0 errors, 6 skips),
after `Window#monitor_from_point` was changed to fail on the channel once
the loop has ended, as Tauri's dispatcher does (`lib.rs:1954-1967`), and
after the review fixes below.

A review then found a Linux build break: `RbWebView::open_webview`, used
only on macOS, failed `-D warnings` elsewhere; it is now macOS-only.
The macOS work area is now also checked against AppKit's own
`visibleFrame`, so measuring the whole screen fails the real-window test.

Mutations checked by hand, each failing the named test and then
restored: the getter's `nil?` check made falsy
(`test_flags_are_the_native_answers`, `test_flag_setters_...`); the
unsupported-position raise removed
(`test_an_unsupported_position_raises_failed_to_send_message`); `nil`
passed for the webview (`test_inner_size_hands_the_native_window_its_webview`);
a `LogicalSize` sent as physical (`test_sizes_and_positions_reach_tao_as_their_kind`);
`unmaximize` asking to maximize (`test_actions_ask_tao_for_the_state_tauri_names`);
`monitor_from_point`'s mapping removed
(`test_after_the_loop_has_ended_monitor_from_point_fails_to_receive`); in
Rust, `inner_size` measuring tao's view instead of the webview on macOS
(`window_state_test`'s logical and physical size checks: tao's view stops
following the window, which confirms decision 6), `Dark` mapped to
`Light` (`test_a_theme_set_is_the_theme_read`), and `size` swapping
logical and physical (the size and AppKit-limit checks), and the macOS
work area using the screen's full frame
(`test_the_work_area_is_appkits_visible_frame`).
